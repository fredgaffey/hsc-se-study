  Content

Lists

A List is a linear data structure that can store data belonging to multiple data types.

    Lists are essentially the same as Arrays except multiple data types can be stored. The syntax between the data structures are the same in Python.

An Index is the location of an item in the List, with the first Index being 0.

Elements are the items stored in the List.

 

Stacks

A Stack is a linear data structure that behaves in a certain way when adding and removing items, using a 'Last-in, first-out' structure (LIFO). This can be implemented by either an array or list but a Stack will always be limited in the number of items it can store.

This means that the item that was last added to the Stack will be the next item to be removed. In other words, the way you retrieve items will be in the reverse order that you added them into the Stack.

  • Push: The process of pushing is adding an item to the top of the Stack.
  • Pop: The process of popping is removing an item from the top of the Stack.

   Think of a stack like a pile of plates. You would want to only add and removed plates from the top of the pile. Removing plates from the bottom would cause the pile to fall over!

Hash Tables

Hashing is the process of converting a given key into a code (a hash). In the case of implementing a Hash Table, the resulting hash is used to indicate the index in which data is being inserted.

Depending on the complexity of the hash function, it is possible for the resulting code to be the same for multiple keys (e.g. the keys "cat", "act" and "tac" could all generate the same hash).

 

Positional Indexing (Ordered Containers)

(i.e. Lists, arrays, trees) have a sense of order between elements. Typically you can assign a meaningful index to each element that denotes an order or sequence.

Associative Indexing (Associative Containers)

(i.e. Hash Tables) use unique "keys" to map their values. Items in associative containers have no sense of order. Keys are typically strings (but for now, we will use integers as keys). 

Hash Table

A Hash Table implements Associative Indexing through the use of a Hashing Function.

The Hashing Function is given a unique key (i.e. "HISTORY"), which then converts the key into an integer (i.e. 2) between 0 and the length of the array - 1.

   Note: As stated above, the Hashing Function may allow multiple keys to generate the same integer code. This is called a collision and there are advanced ways to handle this (see advanced section below).

This integer represents the index in which data (i.e. data about the "HISTORY" subject) will be inserted.

The Hashing Function for the purposes of this course can be very simple, but when it comes to the 'real-world' these functions can be very complex.

Hash Tables - Collision Handling

Separate Chaining is an advanced collision handling strategy that allows multiple items to be stored in a single index. In this example, the Hash Table is an array made up of lists in each index.

Whenever a key produces a hash, the item is appended to the end of the list which is contained inside the index (as defined by the hash value).
