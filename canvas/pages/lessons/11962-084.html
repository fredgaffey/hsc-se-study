How to Answer "Fill in the Blank" Questions

Procedure:

  1. Read the question carefully.
  2. Analyse any provided stimulus.
  3. Fill in each blank using the most logical answer.
  4. Re-read the question and make sure your answer is correct.

Question Walkthrough & Tips and Tricks

Question: Add appropriate fields into each of the tables to show a correctly normalised schema. Use (P) to indicate primary key and (F) to indicate foreign key. Person_ID, the primary key for the People table and Type, a field in the table has been included for you. (4 marks)

Step 1. Read the question carefully

It's important to dissect the question so you can identify exactly what it requires you to do. The two most important things to identify are:

  • What is the topic area? This question is on 2.18 Web-Based Databases schemas, with a focus on the normalisation of data. Although normalisation is not explicitly in your syllabus or course specs, your syllabus does involve reading entity relationship diagrams and using SQL so this skill is good to have up sleeve in case it help with your understanding of future questions. You need to be ready to recall content and apply skills from this topic.
  • What do we actually need to fill in? In this question, we need to add appropriate fields to ensure the schema is normalised.

Stimulus:

A database is being designed to track students’ classes. Students and teachers can be assigned to classes and classes need to take place in a specific room/location. A student can be enrolled in many classes and a class can have many students.

person_ID is the numerical unique identifier for teachers and students and type is the field which stores weather the person is a teacher or student.

Four tables, People, Classes, Class_Attendees, and Locations have been identified for the database.

Step 2. Analyse the provided stimulus

This question has a very detailed stimulus, so it's essential to use the highlighting tool in the online exam software.

  • The yellow highlight "track students' classes" gives us context as to what the database is for.
  • The green highlight "classes need to take place in a specific room/location" tells us we need a one to many relationship between the Locations and Classes table since many classes (plural) can take place in a (single) classroom.
  • The blue highlight "a student can be enrolled in many classes and a class can have many students" tells us we need a many to many relationship between Classes and People to ensure proper data normalisation. Recalling our knowledge of data normalisation, a many to many relationship requires a third intermediary table, since without it, we would need to duplicate students in the People table if we want to add them to many classes which violates data normalisation which focuses on reducing data redundancy and duplication.
  • The red highlight confirms our assumptions so far by revealing there is in-deed an intermediary table between People and Classes called Class_Attendees.

Looking at the provided schema outline on the right, we don't actually have to label the relationships with one/many and the tables have already been laid out, so our job is relatively easy. However, understanding how to draw this schema without it being provided is an important skill since you could get a question that focuses on picking tables or labelling relationships.

Step 3. Fill in each blank using the most logical answer.

Since our only job it to add appropriate fields into each gap to create a correctly normalised schema, we need to focus on creating appropriate primary keys, reasonable data fields and place them all in the right place based on the links between the tables. Below are the marking guidelines for this question which will give you insight into what should go into each gap.

Step 4. Quickly reread question and ensure you answer is correct.

Before we move to the next question, we want to make sure we are correct since it's often easy to forget one small fact from the question. Something some people may forget is this part of the question: "Use (P) to indicate primary key and (F) to indicate foreign key." Since it's in the marking criteria, you need to include the (P) or (F) to get full marks. Ensure you don't miss small details like this whilst focussing your mental power to coming up with correct appropriate fields.

 Marking Criteria (through the eyes of a marker)

How do I get full marks?

  • To get full marks, you would need to fill out every field correctly. This includes all the primary and foreign keys and extra attributes for each table. 
  • You need to have a good understanding of relational databases. If you're not sure how to answer this question or want to enhance your understanding further, you should revise 1.26 Relational Database and 1.26a Relational Database Tutorial Series.

I'm completely stuck. How do I maximise my marks?

  • Don't leave the question blank. If you're totally stuck, there are always some basic things you can do to guarantee at least one or two marks. After this, flag the question so you can come back to it after you finish the rest of the exam, hopefully with fresh ideas to claim a few more marks.
  • You can get 1 mark even for providing "some relevant fields". This means that providing two fields that are related to a table or putting the primary keys into each table will get you one mark. This is better than 0 for very little work. If you are able to add a foreign key into a table, you would be in the two mark range. If you can add a foreign key, a primary key, and other relevant fields in each table you could even get a three. So don't give up if the question looks too tricky. Just reread it a couple times and with a decent attempt, you could get most of the marks.
