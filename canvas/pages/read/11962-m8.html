2.4 Collaborative Code Development

Syllabus
Outline the features of OOP that support collaborative code development including:
- consistency
- code commenting
- version control
- feedback

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand and explain how Object-Oriented Programming (OOP) features support collaborative code development, focusing on consistency, code commenting, version control, and feedback mechanisms.

Success Criteria - Students can:

  • Explain how OOP features like modularity, naming conventions, design patterns, and comments contribute to consistency and readability in collaborative development.
  • Describe the role of version control systems in managing code changes and the importance of code reviews, automated testing, and CI/CD pipelines in maintaining high code quality.

  Content

Collaborative code development is a practice where multiple developers work together on a shared codebase to build, maintain, and enhance software projects. 

 

Consistency

  1. Modularity and Encapsulation: OOP encourages the use of classes and objects to represent real-world entities, promoting a consistent and organised structure within the codebase. By defining clear interfaces and encapsulating data and behaviour within classes, developers can maintain a standardised approach across different modules and components of the software. Review this content here: 2.2.1 OOP Features: Objects, Classes & Encapsulation

  2. Standard Naming Conventions: OOP encourages the use of consistent naming conventions for classes, methods, and variables. This practice ensures that the code is readable and understandable by all team members, reducing confusion and enhancing collaboration.

  3. Design Patterns: Using established design patterns (e.g., Facade) ensures a uniform approach to solving common problems, making the codebase predictable and easier to understand and maintain. Review the content for the Facade pattern here: 2.5 Code Design

  4. Reusable Components: Classes and objects can be reused across different parts of the codebase. This reuse promotes consistency in code behaviour and reduces duplication of code.

 

Code Commenting

  1. Documentation Comments: Comments written within the code itself allows developers to document the overall purpose, functionality, and usage of classes and their methods. Properly commented code enhances readability and understanding, facilitating collaboration among team members who may be working on different parts of the project.

  2. Inline Comments: These comments are placed within the code to explain complex logic, decisions, or unusual implementations. They help other developers understand the rationale behind specific code sections, facilitating easier maintenance and updates.

  3. TODO Comments: These comments highlight areas of the code that need further development, testing, or refactoring. They help keep track of pending tasks and ensure that important updates are not overlooked.

  4. Consistent Commenting Style: Adopting a consistent commenting style across the project ensures that all team members can easily read and interpret comments, enhancing overall code comprehension and reducing miscommunication.

Version Control

  1. Branching and Merging: Version Control Systems (VCS) allows developers to work on separate branches for different features or bug fixes. This isolation ensures that changes do not interfere with the main codebase until they are ready to be safely integrated. Merging branches enables the combination of these changes into the main codebase, facilitating collaborative development. Branches with modified code need to be tested for errors first before being merged into the main codebase. This is so that the main codebase always remains as stable as possible.

  2. Commit History: Every change made to the code is recorded with a commit, which includes a message describing the change. The commit messages form a history that provides a detailed record of what was changed, who made the change, and why it was made, making it easier to track progress and understand the evolution of the codebase.

  3. Conflict Resolution: When multiple developers work on the same code, conflicts can arise. VCS tools provide mechanisms to detect, highlight, and resolve these conflicts, ensuring that the final code is coherent and integrates contributions from all team members.

  4. Collaboration Platforms: Platforms like GitHub, GitLab, and Bitbucket offer additional collaborative features such as pull requests, code reviews, and issue tracking, which streamline the development process and enhance team coordination.

Feedback

  1. Code Reviews: Programmers are generally biased towards their own code, thinking that they are correct despite being potentially flawed. A code review handles this bias by having someone other than the original programmer check the correctness the code. Peer reviews of code changes help identify potential issues, enforce coding standards, and share knowledge among team members. This collaborative practice improves code quality and fosters a culture of continuous improvement.

  2. Automated Testing: Unit tests, integration tests, and automated testing frameworks ensure that code changes do not introduce new bugs or regressions. Automated test results provide immediate feedback on the impact of changes, enabling developers to address issues promptly. Review this content here: 1.18 Test and evaluate.

  3. Continuous Integration/Continuous Deployment (CI/CD): CI/CD pipelines automate the process of building, testing, and deploying code. They provide immediate feedback on the status of the codebase, ensuring that it remains in a deployable state and that issues are caught early in the development cycle.

Initial Clone of a Repository

  1. Use git clone <url> to clone the repository. Remember to replace the <url> with the link that is found under: Code (green button) > HTTPS (see screenshot below).

    Reason: We must be editing our code locally on Visual Studio Code, not using the online editor on GitHub.




 

 

 Using a Branch to Add Features

  1. Change the Visual Studio Code workspace to the folder that was created from cloning the repository. Use the command git pull origin main to update the local repository with any changes that may be on the GitHub repository.

    Reason: Ensures your local repository is synchronized with the remote repository to avoid conflicts.



  2. Then, create a new branch for your feature using this command git checkout -b <new-feature-branch>. Remember to replace <new-feature-branch> with the name of the feature that you are implementing (you come up with this name).

    Reason: Creating a new branch allows you to work on the new feature without affecting the main branch. 



  3. Now, implement the code for your new feature in your local environment, i.e., Visual Studio Code.



  4. After this, you may stage all the changes you've made to the code by running the command git add .

    Reason: Staging the changes prepares them to be committed. You can also add specific files instead of all changes.



  5. Commit the changes with a message through the command, git commit -m "Add feature X". Make sure you include an appropriate message with your commit that details the changes you made.

    Reason: Commit messages should be descriptive to provide context about the changes.



  6. Push the changes to the remote repository by using git push.

    At this stage you will likely be asked to login to GitHub if you have not already. For the first push we do to a new branch, there is be no corresponding branch on the GitHub repository so the push command will fail (see screenshot). So, just copy the command in the error, git push --set-upstream origin <branch-name>,  to push it for the first time, you only need to run this command once for a new branch.

    Reason: Pushing the changes uploads your branch to the remote repository, making it available for review and merging.



  7. Create a Pull Request and Merge on GitHub
        •    Copy the link that you received when running the git push command from the previous step. Paste it into your browser; it should be in the form https://github.com/<username>/<repository>/pull/new/<branch>
        •    Fill in a meaningful title and description for your pull request, then press the "Create pull request" button
        •    Review the changes, address any comments or feedback.
        •    Once approved, merge the pull request into the main branch.

    Reason: Merging via a pull request allows for code review and ensures that the main branch is always stable.




  8. Return to Visual Studio Code and checkout the main branch which you have just merged your changes to by using git checkout main

    Reason: Switches your working directory back to the main branch to incorporate the latest changes.



  9. Pull the latest changes from the main branch with the command git pull origin main

    Reason: Ensures your local main branch is up to date with the remote main branch, including the new feature you just merged.



  10. Repeat from Step 1 whenever you want to add a new feature into your program.

    Reason: To add a new feature into the codebase.

 

 

 

 

 

2.5 Code Design

Syllabus
Describe the process of design used to develop code in an OOP language including:
- task definition
- top-down and bottom-up
- facade pattern
- agility

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Students will understand the process of designing code in an OOP language, including task definition, top-down and bottom-up approaches, the facade pattern, and agility in development.

Success Criteria - Students can:

  • Students can define coding tasks, apply design approaches, implement the facade pattern, and adapt their code to changing requirements efficiently.

  Content

The process of designing software in an object-oriented programming (OOP) language is essential for creating systems that are clear, scalable, and easy to maintain. Effective design ensures that code meets user requirements while adhering to best practices. This process involves defining tasks, choosing appropriate design approaches such as top-down or bottom-up, implementing design patterns like the facade pattern, and adopting agile principles to accommodate change.

 

Code Design

The main advantage of object-oriented programming over imperative programming is its unique ability to create elegant and beautiful software through a design that is centred around the use of objects; rather than functions used in procedural programming.

Throughout the remainder of this unit, the aim is to emphasise good design practices of object-oriented code as we apply the principles you have learned to effectively create modular systems that are flexible, maintainable and reusable.

When it comes to code design, there is no clear right or wrong answer. There are many shades of grey, where design decisions aren't clear cut. Good programming skill doesn't matter if you don't have good design. Designing elegant OOP software is an art.

Task Definition

A task definition (or problem statement) is a concise and clear description of a specific issue or challenge. It acts as a foundational element in the problem-solving process by clearly articulating what needs to be addressed. A well-crafted task definition should be focused, precise, and actionable, enabling individuals or teams to remain aligned on the objective and work collaboratively toward a solution.

Key Characteristics of a Good Task Definition

  1. Clarity: The problem should be easy to understand and free from jargon.
  2. Focus: It should highlight the core issue without unnecessary details.
  3. Importance: The statement should explain why solving the problem matters, emphasizing its significance.
  4. Impact: Identifies who or what is affected by the issue.
  5. Stimulates Creativity: Inspires innovative and critical thinking to develop effective solutions.

Top-Down and Bottom-Up

The Top-Down and Bottom-Up design methodologies represent two different approaches to system development.

  • Top-Down Design is an approach where the system is broken down into smaller components starting from the highest level.
    • In OOP, we would start by creating high-level generalised classes before creating lower-level child classes that have more specific responsibilities.
    • e.g. In a game, we may start by creating a generalised Character class before creating more specific child classes such as Knight and Witch.
  • Bottom-Up Design is an approach where the system is built starting from the lowest level components.
    • In OOP, we would start by creating low-level classes with specific responsibilities before generalising into higher-level parent classes.
    • e.g. In a game, we may start by creating the Knight and Witch classes before creating more a generalised Character class.

Façade Pattern

In software design, there are many established design approaches that are used as a template for handling common design problems. One such problem is having to deal with complexity of our object-oriented code. The solution is to create a simplified interface (facade) to hide the complexity of underlying classes in a way that allows people who are unfamiliar with the code (e.g. the client) to use the software.

The Facade Pattern is a design approach that provides a simplified interface to a complex subsystem. It is particularly useful when you have a program with multiple interdependent classes, and you want to make it easier to use by providing a single interface to interact with that system.

Imagine your computer as one of these complex systems. The facade in this scenario is your keyboard, mouse and screen which offer you a method to control and use your computer whilst hiding the complexity and millions of operations going on behind the screen to provide you with a user friendly method to interact with the systems.

Example:

Consider a home entertainment system with:

  • A DVD Player
  • A Projector
  • Lights
  • A Sound System

To use the Facade Pattern in the design of this system, we can provide a simple interface class called RemoteControlFacade to interact with the components of the home theatre without knowing how to use each of those individual components.

The attributes of the RemoteControlFacade class contains the objects that make up the home theatre.

The methods of the RemoteControlFacade class then call the methods of those objects (dim(), on(), set_input(), set_volume(), etc).

We can then use the interface methods in the RemoteControlFacade to start and end a movie without needing to know how to use the DVDPlayer, Projector, Lights or SoundSystem classes. The client only needs to know how to use the facade interface.

Output:

Get ready to watch a movie...
Lights dimmed to 10%.
Projector is on.
Projector input set to DVD.
Sound system is on.
Sound system volume set to 5.
DVD Player is on.
Playing movie 'Imitation Game'.
Shutting movie theater down...
DVD Player is off.
Sound system is off.
Projector is off.
Lights dimmed to 100%.

 

Agility

When designing object-oriented code, it is important to structure classes in a way that allows for easy and efficient modification.

The agility of a program is described as its ability to adapt to unspecified or changing needs of the client.

This adaptability is crucial in modern software development, where requirements can evolve rapidly.

If adding a feature requires a large number of classes to be modified, then:

  • the update will take a long amount of time
  • the large number of modifications will likely cause existing features to fail

This is a sign of poorly designed OOP code.

However, if the same feature can be added by modifying a small number of classes, then:

  • the update will take a short amount of time
  • the small number of modifications will not largely affect existing features

This is a sign of effectively designed OOP code.

Ideally, when we need to add new features into our object-oriented code, these changes should only be made in as few places as possible. If you need to make changes in many other places too, then program development will become much more complicated and expensive as a result because of poor agile design.

Example:

Consider a video game that has to be frequently updated to receive new characters. If we have a generalised character class that contains the common attributes and behaviours across all characters in the game (e.g. moving, attacking, defending), then any modifications that add any new characters into the game will mainly require the addition of a single new child class and its specialised behaviours. The more changes that are required outside of the new child class, the less agile the object-oriented code becomes.

2.6 Message passing

Syllabus
Investigate how OOP languages handle message-passing between objects

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand how object-oriented programming (OOP) languages handle message passing between objects to facilitate communication and interaction in software systems.

Success Criteria - Students can:

  • Explain the concept of message passing in OOP and its role in enabling object interactions within software systems.
  • Demonstrate how to implement message passing between objects in an OOP language, using methods and parameters to simulate real-world interactions.

  Content

In Object-Oriented Programming (OOP), objects are the fundamental building blocks of a program. These objects communicate with each other to perform tasks, much like how individuals exchange information in real-life interactions. This communication is achieved through message-passing, where one object sends a request to another, prompting it to perform an action or share information.

Message-passing is more than just a way for objects to interact—it underpins core OOP principles like encapsulation, polymorphism, and abstraction, enabling flexible and modular software design. In this lesson, we will explore how different programming languages handle message-passing, the mechanics behind it, and its importance in creating scalable and maintainable systems.

 

Message Passing

Message passing in object-oriented programming (OOP) refers to the process by which objects can interact with each other. Objects interact with each other by sending a message that requests to run a method from a different object.

In other words, objects interact with each other by calling the methods of another object. For example, when Object A runs a method in Object B, then Object A is sending a message to Object B.

The process of message passing between objects works as follows:

  1. The sender object constructs a message that specifies: the name of the method and the required parameters to use that method.
  2. The message is sent to the receiving object to be processed.
  3. The receiving object then interprets the message. If the specified method exists and the message contains the all of the required parameters, then that method is run using those parameters.
  4. If the method returns a value, then it is sent back to the sender object.

Message passing allows different objects (the components of a program) to talk to each other without needing to know all the details about how the other works. This makes it easier for them to work together and simplifies the overall design. This approach promotes abstraction and encapsulation, where objects interact only through the well-defined interfaces of their methods, ensuring modularity and flexibility in software design.

 

Example of Message Passing

In Python, the concept of message passing involves any method that calls a method from another object.

Consider the Car class below which has a simple behavioural method called start() that starts the car's engine (represented using a print() statement for simplicity).

Now consider the Driver class. It has a behavioural method called drive(car) that takes in a car object as a parameter and runs that car object's start() method.

It is important to note that the drive(car) method does not need to know exactly how a car starts (i.e. putting the fuel in the engine, igniting the fuel, etc). The inner workings of the car are only being handled in the Car class itself, hidden away by its method interface. All the drive(car) method needs to know is that we can start a car object just by using its start() method.

The use of the drive(car) method through message passing is demonstrated in the mainline below. The car and driver objects are created before interacting with each other when the drive(car) method is called.

From the output, we can see that by calling the drive(car) method in the driver object, we also call the start() method in the given car object.

 

Note on Code Design

By using message passing, the drive(car) method is inherently designed to always require a car object (which makes sense because a driver needs a car in order to drive). If a driver is not given a car, then they cannot drive.

2.7 Code Effectiveness & Optimisation

Syllabus
Assess the effectiveness of programming code developed to implement an algorithm
Explain code optimisation in software engineering

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Students will be able to evaluate the effectiveness of programming code that implements a given algorithm, focusing on aspects such as correctness, efficiency, and readability

Success Criteria - Students can:

  • Describe what the algorithm is designed to achieve and outline the key functions of the code
  • Verify that the code correctly implements the algorithm by checking if it produces expected outputs for a variety of test inputs
  • Assess the efficiency of the code by examining time complexity and space complexity.
  • Suggest specific changes or optimizations that could enhance the code’s effectiveness, citing reasons for each recommendation.

  Content

In software development, the implementation of an algorithm through programming code is not just about ensuring it works correctly but also about how effectively it performs under various conditions. An effective implementation balances correctness, efficiency, and maintainability while meeting the requirements of the task.

Equally important in this process is code optimisation, which enhances the performance of the program by refining its structure and execution. Through thoughtful optimisation, developers can create software that is faster, more resource-efficient, and scalable, all while maintaining clarity and reliability.

 

Code Effectiveness

When assessing the effective of programming code developed to implement an algorithm there are a few key points to keep in mind:

  1. Correctness: Ensure the code produces the correct output for all possible inputs. Test it with various input values, including edge cases and boundary conditions.
  2. Efficiency: Make sure the code takes the shortest possible route to solve the solution whilst not wasting resources on unnecessary or unneeded objects such as empty variables or repeated sections of code. 
  3. Readability: Assess how easily the code can be understood by other developers. Clear, well-organised code with meaningful variable names, comments, and logical structure is crucial for maintainability and collaboration.
  4. Modularity: Check if the code is broken down into modular components, each responsible for a specific task. Modular code is easier to understand, debug, and maintain.
  5. Error Handling: Evaluate how the code handles unexpected situations, such as invalid input or runtime errors. Robust error handling can prevent unexpected crashes and improve the reliability of the code.

Optimisation

Code optimisation in software engineering is the process of refining code to make it run faster, use fewer resources, and be easier to understand and maintain. This can involve things such as choosing more efficient algorithms, avoiding unnecessary calculations and organising code in a clear and logical way.

General methods of optimising code:

  • Reducing the amount of loops used within an algorithm
    • Loops are often necessary but can be costly in terms of performance, especially when they are nested or repeated unnecessarily.
    • If multiple loops iterate over the same data set, combine them into a single loop to reduce overhead.
  • Avoid unnecessary calculations
    • Perform calculations only when necessary to save processing time.
    • Calculations that do not depend on the loop index should be moved outside the loop.
    • Store results of expensive operations if they need to be used multiple times.
  • Use efficient data structures
    • Selecting the right data structure can significantly affect the performance of your code. 
    • Use sets instead of lists for checking if an item exists in a collection of items.
    • Use dictionaries for key-value pairs and fast lookups.
  • Break early from loops
    • Exiting a loop as soon as possible can save significant processing time.
    • Use conditions to break out of loops early.
  • Utilise built-in functions
    • Built-in functions are often optimised and written in lower-level languages, making them faster.
    • String Concatenation: Use ''.join() instead of + in loops.
    • Use map and filter for applying functions to collections of items.
  • Avoid deep nesting of code
    • Deeply nested code can be difficult to read, maintain, and optimise.
    • Use early returns to reduce the depth of nesting.
    • Break down deeply nested logic into separate functions.
