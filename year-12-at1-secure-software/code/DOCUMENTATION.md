# Backend Project Documentation

This document outlines the structure and purpose of each major component in the `backend/` directory.

---

## Directory Structure

```
backend/
├── app.py
├── clear.sh
├── requirements.txt
├── swagger.py
├── database/
├── classes/
├── core/
├── services/
├── utils/
├── decorators/
├── tests/
└── venv/
```

---

## Overview of Key Files & Folders

### `app.py`
- **Main entry point** of the Flask application.
- Responsible for initializing the server and registering blueprints and middleware.

### `requirements.txt`
- Python dependency list used by `pip3 install -r requirements.txt`.

---

## `database/`

Contains JSON-based storage and a helper module for read/write operations.

```
database/
├── __init__.py
├── data.py
├── users.database.json
├── games.database.json
└── sessions.database.json
```

- `data.py`: Contains helper functions to load/save data from the above JSON files.
- `*.json`: Used as the **persistent flat file storage** for users, games, and sessions.

---

## `core/`

Contains core logic grouped by feature. These are the **raw logic handlers**, separate from routing.

```
core/
├── auth_core.py
├── game_core.py
├── game_helpers.py
└── player_core.py
```

### Files:
- `auth_core.py`: Auth logic (register, login, logout, token/CSRF management).
- `game_core.py`: Game lifecycle logic (create, update, start, end).
- `game_helpers.py`: Utility helpers shared across game modules.
- `player_core.py`: Handles logic related to player interaction (joining, answering, score tracking).

---

## `services/`

Flask **route handlers (controllers)** that act as the API interface.

```
services/
├── auth.py
├── game.py
└── player.py
```

### Files:
- `auth.py`: Defines `/auth/...` endpoints, uses `auth_core.py`.
- `game.py`: Defines `/game/...` endpoints, calls into `game_core.py`.
- `player.py`: Defines `/player/...` endpoints, uses `player_core.py`.

---

## `classes/`
Contains **data structures or helper classes** used throughout the backend logic.

- `User.py`:  
  Defines the `User` class that handles most authentication-related logic and session data.

- `Error.py`:  
  Defines the custom exception types used in route handling:
  - `InputError`: Raised for invalid inputs or bad requests (maps to HTTP 404).
  - `AccessError`: Raised when a user is not authorised to access a resource (maps to HTTP 402).

---

## `utils/`

General-purpose helpers used across modules.
- Examples: token generation, hashing, timestamp utils, etc.

---

## `tests/`

Contains automated **unit/integration tests** for the backend.

- Run tests with:
```bash
pytest
```
> [!WARNING]  
> Ensure you run `pytest` from the **root directory**.  
> Otherwise, PyTest won’t recognise your imports and dependencies correctly.

---

## Virtual Environment (`venv/`)

- Python virtual environment for dependency isolation.
- Can be regenerated using:
```bash
python3 -m venv venv
source venv/bin/activate
pip3 install -r requirements.txt
```

> ⚠️ Do **not** commit `venv/` to GitHub. It should be in `.gitignore`.

---

## Summary

| Component     | Responsibility                      |
|---------------|--------------------------------------|
| `core/`       | Core app hame logic                  |
| `services/`   | API endpoint definitions (routes)    |
| `database/`   | JSON file storage + access helpers   |
| `tests/`      | Backend test suite                   |
| `utils/`      | Generic utility functions            |
| `decorators/` | Custom Python decorators for Flask   |
| `classes/`    | Custom data classes / structures     |

---

# Frontend Project Documentation

This document outlines the structure and purpose of each component in the `frontend/` directory of the SmallBrain project.

## Directory Structure

```
frontend/
├── backend.config.json
├── cypress/
├── cypress.config.js
├── dist/
├── eslint.config.js
├── index.html
├── jsconfig.json
├── node_modules/
├── package.json
├── package-lock.json
├── public/
├── src/
├── upload/
└── vite.config.js
```

## File Overview

### `backend.config.json`
Stores configuration for connecting to the backend API (e.g. base URL, endpoints).

### `cypress/` & `cypress.config.js`
Contains **end-to-end (E2E)** tests using Cypress, and its configuration file.

### `dist/`
Build output generated by Vite.  
> ⚠️ This folder is auto-generated and should **not** be committed to Git.

### `eslint.config.js`
Configuration for ESLint, enforcing code style and linting rules.

### `index.html`
The entry HTML file for the app. Vite injects scripts here when serving/building.

### `jsconfig.json`
Configures module resolution for VS Code, enabling absolute imports from `src/`.

### `node_modules/`
All installed dependencies from `npm install`.  
> ⚠️ Do not commit this folder to Git — it’s in `.gitignore`.

### `package.json` / `package-lock.json`
Dependency list, scripts, and metadata for the frontend project.

### `public/`
Static assets that will be copied to the root of the build output without processing.

### `upload/`
Folder for handling uploaded media/assets in the frontend.

### `vite.config.js`
Configuration for the Vite bundler, including plugins and server settings.

---

## 📁 `src/`

Main source code for the React + Vite app.

```
src/
├── App.jsx
├── __test__/
├── assets/
├── components/
├── contexts/
├── hooks/
├── main.jsx
├── routes/
├── services/
├── setup.js
└── utils/
```

---

### `App.jsx`
The root React component containing global layout and route definitions.

### `main.jsx`
Entry point for rendering the React app into the DOM.

### `setup.js`
Setup file for configuring the testing environment (e.g. Vitest/JSDOM).

---

## `__test__/`
Contains a few **unit tests** for frontend components and logic.

---

## `assets/`
Holds images, icons, and static files imported directly in the app.

---

## `components/`
All reusable UI elements and composite components.

Examples:
- `AlertBox.jsx`, `Spinner.jsx` — general UI widgets
- `NavBar.jsx`, `BreadCrumb.jsx` — navigation elements
- `buttons/`, `inputs/`, `modals/`, `media/` — grouped component categories

---

## `contexts/`
React Context providers for managing **global state** (e.g. authentication).

---

## `hooks/`
Custom React hooks for encapsulating reusable logic (e.g. form handling, API calls, auth checks).

---

## `routes/`
React Router route components/pages for different app screens.

---

## `services/`
Contains **API interaction logic** for communicating with the backend.

```
services/
├── api.js       # Base API configuration (fetch setup)
├── auth.js      # Auth-related API calls (login, register, logout)
├── game.js      # Game creation, management, and control API calls
├── play.js      # Player-specific gameplay API calls
└── session.js   # Session handling API calls
```

---

## `utils/`
General utility functions used across components and services (e.g. formatting, validation).

---

## Testing

- **Unit Tests**: Located in `__test__/`, run with:
```bash
npm run test
```

---
