Secure Software Architecture

This cycle delves deeper into the technical implementation of secure software systems. Moving beyond the foundational concepts, we explore how to proactively build security and privacy directly into software architecture from the ground up.

Throughout this cycle, we will cover the following key areas:

  • The 'Security by Design' approach, focusing on the technical pillars of cryptography and sandboxing.
  • Implementing the 'Privacy by Design' framework to ensure user data is proactively protected and respected.
  • Testing software resilience, determining vulnerabilities, handling breaches, and planning for business continuity and disaster recovery.
  • Utilising vital developer strategies and tools, including SAST, DAST, code reviews, and penetration testing.
  • Designing defensive code with robust data input handling, validation, and sanitisation to prevent malicious exploits like SQL injection.

Lessons

Title Syllabus Page Focus
1.6 Security by Design

Use and explain the contribution of cryptography and sandboxing to the 'security by design' approach in the development of software solutions.

 Building security into software from the ground up is more effective than adding it later. This page explores two key technical pillars of 'Security by Design': Cryptography for data protection and Sandboxing for safe execution.
1.7 Privacy by Design

Use and explain the 'privacy by design' approach in the development of software solutions, including:

  • proactive not reactive approach
  • embed privacy into design
  • respect for user privacy
 Privacy isn't an afterthought; it's a core component of modern software architecture. This page explores the 'Privacy by Design' framework, ensuring user data is protected proactively, embedded deeply, and respected throughout the software lifecycle.
1.8 Test Security & Resilience

Test and evaluate the security and resilience of software by determining vulnerabilities, hardening systems, handling breaches, maintaining business continuity and conducting disaster recovery.

 Building software is only half the battle; keeping it safe is the other. This page explores how we test software for vulnerabilities, harden it against attacks, handle breaches when they happen, and ensure the business keeps running even when disaster strikes.
1.9 Security Strategies & Tools

Apply and evaluate strategies used by software developers to manage the security of programming code:

  • code review
  • static application security testing (SAST)
  • dynamic application security testing (DAST)
  • vulnerability assessment
  • penetration testing

Writing code is only half the battle; ensuring it is secure is equally important. This page explores the tools and strategies developers use to find and fix vulnerabilities, including code reviews, automated testing (SAST/DAST), and penetration testing.
1.10 Defensive Data

Design, develop and implement code using defensive data input handling practices, including input validation, sanitisation and error handling.

Input based vulnerabilities are a major security risk for software. This page covers how to design and implement defensive data handling, including validation, sanitisation, and error handling, to protect systems from malicious attacks like SQL injection.
