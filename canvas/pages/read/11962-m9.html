2.8 Design and Implement OOP

Syllabus
Design and implement computer programs involving branching, iteration and functions in an OOP language for an identified need or opportunity

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Design and implement software solutions using branching, iteration, and functions within an OOP framework to address specific needs or opportunities.

Success Criteria - Students can:

  • Demonstrate the use of branching (if-else, switch-case statements), iteration (loops like for, while), and functions in creating software.
  • Develop a small project or a component of a larger project that utilizes OOP concepts to solve a real-world problem, documenting the process and the code effectively.

  Content

Together, branching, iteration, and functions (methods) enable developers to create more modular, reusable, and maintainable code in object-oriented systems. They help manage complexity by dividing tasks into smaller, manageable parts and defining clear interfaces for objects.

 

These are all concepts that you have learnt already, to summarise:

  • Branching involves making decisions within the program. It uses conditions to determine which blocks of code to execute. For example, if, else, and elif statements allow the program to execute different code based on different inputs or states. In OOP, branching can be used within methods to determine how an object should behave under different conditions. Refer to 1.5 Structured algorithms for more information.
  • Iteration refers to looping through data structures or repeating some action until a condition changes. Common iterators include for loops and while loops. In OOP, iteration might be used to perform actions on each item in a collection of objects, such as invoking a method on every object in a list. Refer to 1.5 Structured algorithms for more information.
  • Functions are blocks of code that perform specific tasks and can be called as needed. In OOP, these are often implemented as methods, which are functions that are associated with a specific class. Methods define behaviours for class instances and can access and modify the state of these instances. Refer to 1.8 Procedures and functions for more information.

2.9 Implement and Modify OOP

Syllabus
Implement and modify OOP programming code including:
- clear and uncluttered mainline
- one logical task per subroutine
- use of stubs
- use of control structures and data structures
- ease of maintenance
- version control
- regular backup

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand best practices in code structure, including maintaining a clear mainline, task-specific subroutines, and utilizing control and data structures effectively.

Success Criteria - Students can:

  • Develop a clear, uncluttered mainline and modular subroutines, each performing a single logical task, enhanced by the use of stubs for independent testing.
  • Utilise control and data structures effectively for optimal data management and decision-making.
  • Apply maintenance principles, version control, and regular backups to ensure the code is robust, easily updatable, and secure against data loss.

  Content

When writing any program we aim to create robust, maintainable and scalable software, facilitating both initial development and any future modifications. This includes:

  1. Clear and Uncluttered Mainline: The mainline logic of the program should be straightforward and free from clutter, serving as a clear entry and exit point of the application.

  2. One Logical Task per Subroutine: Each subroutine or method should handle a single logical task, enhancing readability and reusability.

  3. Use of Stubs: Stubs are temporary, simplistic implementations of methods used during the early stages of development to help test sections of the code independently by simulating the behavior of complete methods.

  4. Use of Control Structures and Data Structures: Effective use of control structures (like loops and conditionals) and data structures (like arrays, lists, and dictionaries) is crucial for managing data flow and organization within the program. 1.5 Structured algorithms

  5. Ease of Maintenance: The code should be written in a way that makes it easy to update and modify, with a clear structure and well-documented sections to assist future developers or for future reference.

  6. Version Control: Utilizing version control systems (such as Git) is essential for managing changes to the codebase, allowing multiple versions and collaborative work. 1.2 Online collaboration tools

  7. Regular Backup: Regularly backing up the code ensures safety against data loss and provides a means to revert to previous versions if necessary.

2.10 Test and Evaluate

Syllabus
Apply methodologies to test and evaluate code including:
- unit, subsystem and system testing
- black, white and grey box testing
- quality assurance

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand and apply various testing methodologies, including unit, subsystem, and system testing, along with black, white, and grey box testing, to ensure software quality and reliability.

Success Criteria - Students can:

  • Use OOP principles to build, document, and debug a software project that addresses a real-world problem.
  • Execute comprehensive testing strategies across different stages of the software development process and apply quality assurance practices to meet software standards.

  Content

To test and evaluate code effectively, we can apply the following methodologies:

  1. Unit, Subsystem, and System Testing:

    • Unit Testing: Tests individual components or functions of a software for correctness.
    • Subsystem Testing: Tests a complete module or subsystem for errors, typically involving multiple units.
    • System Testing: Evaluates the complete system's compliance with specified requirements.

  2. Black, White, and Grey Box Testing:

    • Black Box Testing: Testing without knowledge of the internal workings of the application, focusing on outputs in response to certain inputs and execution conditions.
    • White Box Testing: Involves testing internal structures or workings of an application, as opposed to its functionality (i.e., testing internal code logic).
    • Grey Box Testing: A combination of both black and white box testing methods where some knowledge of the internal structure is used to design test cases.

  3. Quality Assurance: Ensures that the software meets quality standards and satisfies the requirements through various practices and processes throughout the development lifecycle.

For more detailed information refer to: 1.18 Test and evaluate
