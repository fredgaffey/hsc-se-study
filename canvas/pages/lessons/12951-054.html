2.13 Managing Load Times

Syllabus
Investigate methods to support and manage the load times of web pages/applications

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Investigate strategies to improve and manage web page/application load times.

Success Criteria - Students can:

  • Identify common factors that impact load times.
  • Explain methods to optimise load performance.
  • Apply tools to monitor and reduce load times effectively.

  Content

Web page and application load times are crucial for user experience and SEO. Faster load times enhance user engagement, decrease bounce rates, and improve overall satisfaction. This guide explores various techniques to optimise load times, including front-end and back-end strategies.

 

Understanding the Impact of Load Times

Load times are more than just numbers; they directly influence user behaviour. Slow loading can lead to higher bounce rates and decreased user satisfaction. For e-commerce, a delay of just one second can result in a significant drop in conversions. Therefore, optimising load times is crucial for both user retention and business success.

 

Front-End Optimisation

Front-end optimisation focuses on everything that happens in the browser. This involves managing the way assets like HTML, CSS, JavaScript, and images are loaded and rendered.

 

Minification and Compression

Minification:

  • What It Is: Minification involves stripping out unnecessary characters such as spaces, comments, and line breaks from CSS, JavaScript, and HTML files.
  • Why It Matters: These characters, while useful for development, are not needed for the browser to execute the code. Removing them reduces file sizes significantly, which in turn decreases download times.
  • How to Implement: Use tools like UglifyJS for JavaScript, CSSNano for CSS, and HTMLMinifier for HTML. Most build tools and task runners like Webpack, Gulp, and Grunt can automate this process.

Compression:

  • What It Is: Compression algorithms like Gzip and Brotli compress files into a smaller size before they are sent from the server to the browser.
  • Why It Matters: Compressed files reduce the amount of data that needs to be transferred, speeding up load times, especially on slower networks.
  • How to Implement: Enable Gzip or Brotli compression on your server. Most web servers like Apache, Nginx, and IIS support these natively.

Image Optimisation

Choosing the Right Format:

  • Modern Formats: Use modern formats like WebP or AVIF, which offer better compression than traditional formats like JPEG and PNG without compromising quality.
  • Use Cases: WebP works well for a wide range of image types, while AVIF provides superior compression but may not be supported on all browsers yet. Use a fallback strategy with multiple formats.

Responsive Images:

  • What It Is: Using the srcset attribute in the <img> tag allows you to specify different images for different screen sizes and resolutions.
  • Why It Matters: This ensures that the browser only downloads the most appropriate image size, reducing unnecessary data transfer for smaller screens.
  • How to Implement: Define a set of image sizes and use srcset and sizes attributes to provide various options to the browser.

Lazy Loading:

  • What It Is: Lazy loading defers the loading of non-critical images (images below the fold) until they are about to enter the viewport.
  • Why It Matters: This technique reduces initial load time and saves bandwidth, especially for users who do not scroll down.
  • How to Implement: Use the loading="lazy" attribute in image tags or implement a JavaScript-based solution for finer control.

JavaScript and CSS Optimisation

Defer and Async Loading of JavaScript:

  • What It Is: Scripts can be loaded in different ways. defer ensures scripts are executed in order but only after the HTML is fully parsed. async allows scripts to load independently, potentially in any order.
  • Why It Matters: Blocking scripts delay page rendering. By using defer or async, scripts do not block the page, reducing perceived load times.
  • How to Implement: Add defer or async attributes to your <script> tags. Prioritise critical scripts by including them in the head with defer and move non-critical scripts to the end of the body with async.

Critical CSS:

  • What It Is: Critical CSS refers to the minimum CSS required to render the visible part of the page. Inlining this CSS in the <head> can speed up the initial paint.
  • Why It Matters: By reducing the number of CSS files the browser has to download before rendering, you improve the time to first paint and reduce perceived load time.
  • How to Implement: Tools like Critical and Penthouse can extract critical CSS. Integrate this step into your build process to automatically inline the necessary styles.

Reducing CSS and JavaScript File Sizes:

  • Modular CSS and JavaScript: Avoid loading entire libraries or stylesheets if only a small part is needed. Use tree-shaking for JavaScript and modular CSS approaches (e.g., CSS modules or utility-first frameworks like TailwindCSS).
  • Remove Unused Code: Tools like PurifyCSS and UnCSS can analyze your HTML and remove unused CSS. For JavaScript, Webpack’s tree-shaking feature removes unused exports, reducing the bundle size.

Reducing HTTP Requests

Combining Files:

  • What It Is: Instead of loading multiple CSS or JavaScript files, combine them into a single file to reduce the number of HTTP requests.
  • Why It Matters: Each request introduces latency. Fewer requests mean less overhead and faster load times.
  • How to Implement: Use build tools like Webpack to bundle assets together. Be cautious of creating bundles that are too large, which can have the opposite effect.

Using HTTP/2:

  • What It Is: HTTP/2 allows multiple resources to be sent over a single connection. This can reduce the need for concatenation of files, as requests are multiplexed.
  • Why It Matters: HTTP/2 minimises the need for workarounds like file concatenation and makes it easier to manage asset loading.
  • How to Implement: Ensure your server supports HTTP/2. Most modern browsers support it, and it’s enabled by default on many hosting providers.

Caching Strategies

Browser Caching:

  • What It Is: Browser caching stores copies of resources locally in the user’s browser. On subsequent visits, the browser can use these cached files instead of requesting them again from the server.
  • Why It Matters: Reducing the need for repeated downloads speeds up page loads for returning visitors.
  • How to Implement: Set caching headers like Cache-Control and Expires for static resources. Consider using unique file names (cache-busting) when resources change, to ensure users always get the latest versions.

Service Workers:

  • What It Is: Service workers are scripts that run in the background and can intercept network requests, caching resources and providing offline functionality.
  • Why It Matters: They offer advanced caching strategies that go beyond what browser caching can achieve, improving load times for both initial and repeat visits.
  • How to Implement: Register a service worker with a caching strategy such as Cache-First or Network-First, depending on the resource type and usage patterns.

 

Back-End Optimisation

Back-end optimisation is fundamental to ensuring that web pages and applications load quickly and efficiently. It focuses on server-side strategies to reduce processing time, manage data effectively, and optimise resource delivery. This section explores the various methods and technologies used to enhance back-end performance, enabling a smoother and faster user experience.

 

Database Optimisation

Databases are often the backbone of web applications, handling everything from user information to content delivery. Inefficient database queries or poorly designed schemas can significantly slow down response times. 

Query Optimisation:

  • Indexing: Create indexes on frequently queried columns to speed up data retrieval. While primary keys and unique constraints are indexed by default, adding additional indexes on foreign keys or commonly filtered columns can reduce query execution time.
  • Avoid SELECT : Specify only the required columns instead of using SELECT * to reduce the amount of data retrieved and processed.
  • Batch Queries: Instead of making multiple single-row queries, use batch queries to fetch or update multiple rows at once. This reduces the overhead of multiple database connections.

Caching Strategies

  • Query Caching: Store the results of frequent, expensive queries in a cache, such as Memcached or Redis, to quickly serve the results without re-executing the query.
  • Object Caching: Cache entire objects or data structures in memory to avoid repeated database queries. This is particularly useful for static or semi-static content like navigation menus or user profiles.
  • Fragment Caching: Cache specific parts of a database-driven page (e.g., a news feed or a user’s dashboard) while allowing other dynamic elements to be updated in real-time.

Server-Side Caching

Server-side caching reduces the time required to generate and deliver content to the user. By storing pre-computed or pre-rendered content, servers can handle more traffic with less strain.

Page Caching

  • Static Page Caching: Store the fully rendered HTML of a page. When a user requests this page, the server can serve the cached HTML instead of generating it from scratch. This is effective for pages that change infrequently, such as blog posts.
  • Fragment Caching: Cache specific parts of a page, such as a sidebar or header, and dynamically generate the remaining parts. This reduces load without sacrificing real-time updates.

Load Balancing

Load balancing ensures that traffic is evenly distributed across multiple servers, preventing any single server from becoming a bottleneck.

Types of Load Balancing

  • Round Robin: Requests are distributed sequentially across a pool of servers. Simple and effective for uniform resource loads.
  • Least Connections: Directs new requests to the server with the fewest active connections, ideal for handling varying loads.
  • IP Hash: Routes requests based on the client’s IP address, ensuring consistent routing for each client. Useful for stateful applications.

API Optimisation

APIs are the communication channels between the client and the server. Optimising API performance can drastically reduce server load and improve response times.

Reducing Payload Size

  • Use Compression: Compress API responses using Gzip or Brotli to reduce payload size.
  • Minimise Data: Send only necessary fields in the response. For example, instead of sending a full user profile, provide only the fields required by the client.
  • Use Efficient Formats: JSON is widely used but can be verbose. Consider using more compact formats like Protocol Buffers (protobuf) or MessagePack for performance-critical applications.

Pagination and Lazy Loading

  • What It Is: Instead of sending large datasets in a single response, split data into pages or load it incrementally as needed.
  • Implementation: Use parameters like limit and offset in API requests to control the amount of data returned, or implement cursor-based pagination for more efficient data retrieval.
