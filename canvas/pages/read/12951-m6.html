Programming for the Web

This cycle dives into the core technologies, protocols, and architectural concepts that power modern web applications. From understanding the underlying transmission of data to exploring the standards that govern the web, we will build a comprehensive understanding of how the internet functions and how to build applications for it.

E-commerce

E-commerce websites enable the buying and selling of goods or services online. These websites require secure handling of user information, real-time inventory management, and seamless payment processing.

Core Features of E-commerce Websites:

  • Product Listings: Display products, descriptions, and prices.
  • Shopping Cart: Allows users to add and manage items before checkout.
  • Secure Payment Processing: Handles transactions safely with encryption and security protocols.
  • User Accounts: Enables login and order tracking for personalised experiences.

Python in E-commerce:

Python's powerful frameworks, like Django and Flask, are commonly used in e-commerce to handle server-side functionality. For example, Django’s built-in admin panel makes managing products and orders easier, while Python libraries can integrate payment gateways like PayPal or Stripe.

E-commerce Example: In a Python-based e-commerce app, users can browse products, add them to a shopping cart, and securely pay for them. Python helps manage the entire process, from inventory updates to secure payment processing.

Progressive web apps (PWAs)

Progressive Web Apps (PWAs) are web applications that combine the best features of web and mobile apps. They are designed to work offline, load quickly, and offer an app-like experience in the browser, often without needing installation from an app store.

Benefits of PWAs:

  • Offline Access: Thanks to cached resources, PWAs can function even without an internet connection.
  • Push Notifications: Users can receive updates even when not actively using the app.
  • Performance: PWAs are optimised for fast load times, enhancing the user experience.
  • Installable: Users can add PWAs to their home screens, providing the same functionality as native apps without requiring app store downloads.

PWAs in Python:

Although PWAs are largely built using web technologies like JavaScript and service workers, Python can be the back-end to manage data and process user requests. Using Python’s Flask or Django frameworks, you can build APIs that provide the data needed by the front end to display content even offline.

PWA Example: A progressive web app could be a news site that loads quickly, sends notifications for breaking news, and caches articles for offline reading. The back-end, powered by Python, handles the fetching of new data, while the front-end PWA provides a seamless, app-like experience.

 

Recognising a PWA

Installation prompt

If you visit a website that is a PWA, some browsers, especially on mobile devices, may prompt you to install the app to your home screen. This typically happens if you visit the site frequently.

Home screen icon after installation

If the PWA is added to your home screen, it will have an icon just like any other app. If you see an app icon for a website you frequently visit, it's likely a PWA.

Full-screen mode

PWAs often offer a full-screen mode, which hides the browser's URL bar and navigation controls, giving you an experience similar to an app.

Offline functionality

If you notice that the app still works even when you're offline or have a spotty internet connection, it's likely a PWA. PWAs use service workers to cache content and provide offline functionality.

Push notifications

PWAs can send push notifications, similar to native mobile apps. If you receive push notifications from a website, it might be a PWA.

Responsive design

PWAs are built to be responsive, meaning they adapt to various screen sizes and devices. If the app adjusts well to different screen sizes, it could be a PWA.

Check browser settings

Some browsers have specific settings or developer tools that allow you to see if a website is a PWA. For example, in Google Chrome, you can go to Settings > Site Settings > Installed Apps to see a list of installed PWAs.

Not all websites have PWAs

This means, if none of the above indicators are evident it is unlikely to be a PWA.

2.2 Data Transfer

Syllabus

Investigate and practise how data is transferred on the internet, including:

  • data packets
  • internet protocol (IP) addresses, including IPv4
  • domain name systems (DNS)

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Investigate how data is transferred over the internet using data packets, IP addresses, and the Domain Name System (DNS).

Success Criteria - Students can:

  • Describe data packets and their role in internet data transfer.
  • Explain the function of IPv4 addresses in identifying devices.
  • Understand how DNS translates domain names into IP addresses.

  Content

The internet enables billions of devices to communicate by breaking data into smaller, manageable packets, assigning unique IP addresses to every device, and using DNS to map human-readable domain names to machine-readable IP addresses. Understanding how these elements work together will provide you with a deeper insight into the foundations of modern networking and internet functionality.

 

Data Packet

 

What is a packet?

Imagine sending a long letter through a mail system that only allows small envelopes. Instead of trying to fit the entire letter into one envelope, you would break it into smaller parts, put each part into its envelope, and send them individually. When the recipient receives all the envelopes, they put the parts back together to read the full letter.

This is similar to how packets work in networking. When data, such as a file or image, is sent over the internet, it is broken down into smaller segments called packets. Each packet is transmitted independently and can take different routes to reach the destination. Once all packets arrive, the receiving device reassembles them to recreate the original data.

 

The Importance of Packets

Theoretically, large chunks of data could be sent in one continuous stream; however, this method would be inefficient, especially on shared networks. Imagine trying to communicate with someone using a single long phone call that prevents others from using the network.

Instead, packets allow multiple devices to use the same network resources simultaneously, as packets can be switched and routed through different paths independently.

 

Components of a Packet

Header

The header contains crucial information required for data transmission:

  • Sender's IP Address: Identifies the source of the packet.
  • Receiver's IP Address: Specifies the intended recipient.
  • Protocol: Defines the communication rules (e.g., TCP, UDP).
  • Packet Number: Indicates the sequence order for reassembly.

Payload

The payload is the actual data being transmitted. It could be part of a file, an email message, or any other information that needs to be sent.

Trailer

The trailer marks the end of the packet and includes:

  • Error Detection Data: Helps verify data integrity (e.g., checksum).
  • End of Packet Signal: Indicates that the packet transmission is complete.

 

Packet Switching and Routing

In a packet-switching network, each packet can travel a different route to its destination. This flexibility allows multiple devices to send data over the same network simultaneously. Once all packets arrive at the destination, protocols like TCP (Transmission Control Protocol) reassemble them into the correct order.

This method makes the internet robust, as packets can be rerouted if a path is busy or unavailable, ensuring that billions of devices can communicate concurrently.

Packet Security and Malicious Traffic

While packets enable seamless communication, they are also susceptible to manipulation for malicious purposes. Hackers may generate packets designed to overwhelm networks (e.g., in Distributed Denial of Service (DDoS) attacks). Advanced cybersecurity measures, such as packet inspection and filtering, help safeguard networks from these attacks.

 

Internet Protocol (IP)

 

Internet Protocol (IP) is a fundamental system that allows data to travel between devices over the internet. Every device connected to the internet is assigned a unique IP address, similar to a mailing address, that identifies it from other devices. This allows data to be sent and received across networks in a highly organised way.

When a message or file is sent over the internet, it is assigned a source and destination IP address.  After the packets arrive at the destination IP address, another protocol, like Transmission Control Protocol (TCP), reassembles them into the original message.

 

What is IPv4?

Internet Protocol Version 4 (IPv4) is the most widely used IP version and has been the backbone of Internet communication for decades. IPv4 uses a 32-bit address system, meaning it can support around 4.3 billion unique IP addresses. This format typically represents four numbers separated by periods (e.g., 192.168.1.1).

IPv4 has been instrumental in enabling global communication, but its main limitation is the finite number of available addresses. As the internet expanded, the demand for IP addresses increased, leading to the problem of IPv4 address exhaustion.

Key Features of IPv4

  • Address Format:

    • An IPv4 address consists of four octets (8-bit segments), separated by periods, each ranging from 0 to 255 (e.g., 172.16.254.1).

  • Routing:

    • IPv4 supports dynamic routing, allowing packets to travel through different paths and networks to reach their destination.

  • Subnetting:

    • IPv4 allows the division of large networks into smaller sub-networks, optimises traffic, and enhances security within large-scale organisations.

  • Address Exhaustion:

    • Despite its success, IPv4's limited address pool became a concern as internet usage grew exponentially, necessitating the development of a successor, IPv6.

 

IPv6

The introduction of Internet Protocol Version 6 (IPv6) was a response to the limitations of IPv4, particularly the exhaustion of available addresses. IPv6 provides a much larger address space, using 128-bit addresses, allowing for trillions of unique IP addresses. While IPv4 is still widely used, the adoption of IPv6 continues to grow to accommodate the increasing number of devices connected to the internet.

 

 

Domain Name System

The Domain Name System (DNS) is a crucial technology that translates human-readable domain names (like www.example.com) into IP addresses (like 192.0.2.1), which computers use to identify and communicate with each other over the internet. DNS acts as the internet's "phonebook," allowing users to access websites without remembering complex numerical IP addresses.

 

What is DNS?

Imagine trying to call someone, but instead of dialling their phone number, you say their name, and your phone automatically finds their number and places the call. DNS works similarly for the internet. When you type a website address into your browser, DNS translates the domain name into the correct IP address, allowing your computer to find and connect to the desired website.

Without DNS, you would have to memorise the numerical IP addresses of every website you wanted to visit, making navigating the internet extremely cumbersome.

How does DNS work?

When a user enters a URL, such as www.kings.edu.au, the browser initiates a DNS query to retrieve the IP address associated with that domain. This process involves multiple DNS servers, each performing a specific role:

  1. User input: a user enters a domain name (like ‘example.com’) into their web browser.
  2. DNS lookup: the browser sends a DNS query to a DNS resolver, typically provided by the user's internet service provider (ISP) or configured in their network settings
  3. DNS resolver: the DNS resolver receives the query and checks its cache to see if it already has the IP address for the requested domain. If the address is found in the cache and is still valid (has not expired), the resolver returns it immediately to the browser. If not, it proceeds to step 4.
  4. Recursive query: if the resolver doesn't have the IP address in its cache, it becomes responsible for finding it. It starts by querying the root DNS servers, which hold information about the top-level domains (like ‘.com’, ‘.org’, ‘.net’ and so on).
  5. Top-level domain (TLD) server: the root server directs the resolver to the appropriate TLD server based on the domain extension (for example, ‘.com’). The TLD server holds information about the authoritative name servers responsible for the next level of the domain hierarchy.
  6. Authoritative name server: the resolver contacts the authoritative name server for the specific domain (for example, ‘example.com’). This server holds the most up-to-date information about the domain, including its IP address.
  7. Response: the authoritative name server responds to the resolver with the requested IP address.
  8. Cache update: the resolver caches the IP address for future use, reducing the need for repeated lookups.
  9. Browser request: armed with the IP address obtained from DNS, the browser can now send a request to the appropriate server hosting the website.
  10. Website access: the server responds to the browser's request and the website is displayed to the user.

Types of DNS Servers

  • Recursive DNS Server: The first point of contact for the user’s DNS query. It resolves the request by communicating with other DNS servers.
  • Authoritative DNS Server: This server contains the actual DNS records (IP addresses) for domains and provides the definitive answer to a query.
  • Root Nameserver: Directs queries to the appropriate TLD nameserver.
  • TLD Nameserver: Responsible for resolving queries for specific top-level domains (like .com, .org).

Types of DNS Queries

  • Recursive Query: The client expects the DNS server to return the correct IP address or an error message if the domain is not found.

  • Iterative Query: The DNS server provides the best answer, typically directing the query to another DNS server with the required information.

  • Non-Recursive Query: The DNS server returns a cached result, offering a faster response without contacting other servers.

Why is DNS Important?

DNS ensures that users can access websites using easy-to-remember domain names instead of complex IP addresses. It also optimises performance by caching results, reducing the time required for repeated lookups. Without DNS, navigating the internet would be both tedious and impractical.

DNS Caching

Caching plays a critical role in DNS efficiency. When a DNS query is resolved, the result is stored temporarily (cached) by the resolver. The next time the same query is made, the DNS resolver can return the cached IP address without repeating the entire lookup process. This reduces latency and network traffic, allowing websites to load more quickly.

Security Considerations: DNS Cache Poisoning

DNS is not without vulnerabilities. One of the most common security issues is DNS cache poisoning (also known as DNS spoofing). In this attack, malicious actors inject false DNS records into the resolver’s cache, causing users to be redirected to harmful websites. This can lead to phishing, malware infections, and other security breaches.

  • Explain the purpose and function of each protocol.

  Content

Web protocols are rules and conventions that allow computers and other devices to communicate with each other across the internet. These protocols enable everything from browsing the web to sending and receiving emails securely. Each protocol operates over a specific port, which is a virtual point through which network connections are made. Understanding these protocols and their associated ports is essential for efficient and secure network communication.

 

HTTP/HTTPS

HTTP

  • Port: 80

  • Function: HTTP is the protocol responsible for transmitting web pages and other resources across the web. It facilitates communication between a client (usually a web browser) and a server. Each request sent by the client is independent and stateless Stateless: A system where each request is handled independently, without retaining any information from previous requests. Each interaction must provide all necessary details., meaning the server does not retain information about previous requests. This simplicity makes HTTP fast but not secure, as data is transmitted in plain text, leaving it vulnerable to interception.

  • Use Cases:

    • Loading web pages
    • Submitting forms on websites
    • Retrieving static and dynamic content like images, videos, and text

  • Key Features:

    • Stateless, meaning each request is treated independently.
    • Flexible, as it can transport various types of media (text, images, video, etc.).
    • Widely used for non-sensitive data transfers.

HTTPS

  • Port: 443

  • Function: HTTPS is the secure version of HTTP. It uses encryption methods such as SSL (Secure Sockets Layer) or TLS (Transport Layer Security) to provide confidentiality, integrity, and authentication between the client and server. With HTTPS, all data transmitted between the client and server is encrypted, which helps prevent man-in-the-middle attacks and eavesdropping. HTTPS is now a standard for securing websites, especially those dealing with sensitive data like login credentials, personal information, and payment details.

  • Use Cases:

    • Secure web browsing
    • Online banking and e-commerce
    • Securing login forms and payment portals

  • Key Features:

    • Encrypted communication ensures that sensitive data is protected.
    • Provides authentication via SSL/TLS certificates A digital document used to verify the identity of a website or server. It ensures secure communication by encrypting data and is issued by trusted authorities (CA)., ensuring the legitimacy of the website.
    • Protects data integrity, ensuring it is not tampered with during transmission.

TCP/IP

  • Ports: TCP commonly uses ports in the range of 0–65535, depending on the application. IP is protocol-based, not port-based.
  • Function: TCP/IP is the foundational protocol suite for all internet communications. TCP ensures reliable and ordered data delivery between applications, while IP handles addressing and routing packets to their correct destination.

TCP (Transmission Control Protocol) is a connection-oriented protocol that establishes a connection between the client and the server before data is transferred. It breaks data into packets, ensures all packets are received, and reassembles them in the correct order. TCP also handles error-checking and retransmission of lost packets.

IP (Internet Protocol) is responsible for addressing packets and routing them across different networks. Each packet includes a source and destination IP address, which enables routers to forward them correctly.

  • Use Cases:

    • Web browsing
    • File transfers (via FTP)
    • Sending and receiving emails (SMTP)
    • Streaming services (video/audio)

  • Key Features:

    • Reliable, ensuring data is delivered correctly and in order.
    • Connection-oriented, meaning a session is established before transmission begins.
    • Supports flow control and error correction.

DNS

  • Port: 53
  • Function: DNS translates domain names (e.g., www.example.com) into IP addresses (e.g., 192.168.1.1) that computers use to identify each other on a network. It functions like a phonebook for the internet. Without DNS, users would have to memorise numerical IP addresses to visit websites.

The DNS system works by querying several servers in a hierarchy to resolve the domain name. The query starts at the DNS resolver, which then contacts the root server, the Top-Level Domain (TLD) server, and finally, the authoritative server to retrieve the IP address.

  • Use Cases:

    • Browsing the web
    • Accessing services by domain names
    • Email routing

  • Key Features:

    • Hierarchical structure for resolving queries.
    • Caching improves efficiency and reduces lookup times.
    • Essential for linking human-readable names to machine-readable IP addresses.

 

Find out more about how DNS is used for data transfer here: 2.2 Data Transfer

FTP & SFTP

FTP (File Transfer Protocol)

  • Port: 21

  • Function: FTP is a protocol used to transfer files between computers over a network. It operates in two modes: active and passive. FTP is not secure, as data, including credentials, is transferred in plain text. However, it's efficient for moving large files or directories between systems, especially when security is not a primary concern.

  • Use Cases:

    • Uploading files to a website
    • Downloading large datasets
    • Managing files on a remote server

  • Key Features:

    • Simple to use for transferring files.
    • Lacks encryption, meaning it’s vulnerable to eavesdropping.

SFTP (Secure File Transfer Protocol)

  • Port: 22

  • Function: SFTP is an extension of SSH (Secure Shell) and provides secure file transfer by encrypting both the commands and the data. This makes it a preferred choice for transferring sensitive information over an unsecured network. Unlike FTP, which requires multiple ports, SFTP operates over a single port (port 22), simplifying firewall configurations.

  • Use Cases:

    • Securely transferring confidential files (e.g., financial records).
    • Synchronising files between local and remote systems.
    • Backup and storage of sensitive data.

  • Key Features:

    • Encrypted data transfer via SSH.
    • Supports file manipulation commands (e.g., renaming, deleting).
    • Operates over a single, secure port.

SSL & TLS

SSL (Secure Sockets Layer)

  • Port: Primarily used on port 443 (HTTPS).

  • Function: SSL is a cryptographic protocol designed to secure communications between a web server and a client. It encrypts the data transmitted, protecting it from unauthorised access or tampering. While SSL is largely deprecated in favour of TLS, it still serves as a foundational protocol for many secure communications.

  • Use Cases:

    • Secure websites (e.g., HTTPS)
    • Protecting data in transit for online transactions

  • Key Features:

    • Provides data encryption and authentication.
    • Uses certificates to verify server identity.

TLS (Transport Layer Security)

  • Port: Primarily used on port 443 (HTTPS).

  • Function: TLS is the successor to SSL and provides improved encryption, security, and performance. TLS ensures that data transmitted between a web browser and a web server remains private and unaltered. It uses cryptographic algorithms to secure the communication channel.

  • Use Cases:

    • Secure web browsing (HTTPS)
    • Secure email (with SMTP, IMAP, POP3)
    • Securing VoIP (Voice over IP) communication

  • Key Features:

    • Enhanced security over SSL.
    • Utilises stronger encryption algorithms.
    • Provides forward secrecy, preventing past communications from being decrypted if the private key is compromised.

SMTP, POP3, IMAP

SMTP (Simple Mail Transfer Protocol)

  • Ports: 25 (unencrypted), 465/587 (with SSL/TLS)

  • Function: SMTP is the protocol used to send emails between servers or from a client to a server. SMTP pushes messages from the sender’s mail server to the recipient's mail server and works in conjunction with email retrieval protocols like POP3 or IMAP.

  • Use Cases:

    • Sending email from client to server.
    • Transmitting email between mail servers.

  • Key Features:

    • Pushes outgoing emails to the server.
    • Requires email retrieval protocols (e.g., IMAP/POP3) for receiving emails.

POP3 (Post Office Protocol v3)

  • Ports: 110 (unencrypted), 995 (with SSL/TLS)

  • Function: POP3 is used to retrieve emails from a mail server to a local device. Once emails are downloaded, they are often deleted from the server, making this protocol suitable for users who access their email from a single device.

  • Use Cases:

    • Accessing email offline.
    • Downloading emails to a single device.

  • Key Features:

    • Simple, one-way communication (download only).
    • Emails are typically deleted from the server after download.

IMAP (Internet Message Access Protocol)

  • Ports: 143 (unencrypted), 993 (with SSL/TLS)

  • Function: IMAP allows users to access their email from multiple devices, as messages are stored on the server until explicitly deleted. It synchronizes email across devices, enabling users to read, organise, and delete emails from any device.

  • Use Cases:

    • Accessing email from multiple devices.
    • Synchronising email across devices.

  • Key Features:

    • Two-way communication (synchronisation).
    • Emails remain on the server unless deleted.

  Content

 

SSL Certificates

 

Definition

SSL certificates are digital certificates used to establish a secure, encrypted connection between a web server and a client (typically a web browser). They are part of the broader category of Transport Layer Security (TLS) certificates.

 

Components:

  • Certificate Authority (CA): A trusted organisation that issues SSL certificates after verifying the identity of the entity requesting the certificate.
  • Public and Private Keys: The certificate includes a public key, which is paired with a private key held by the server. These keys are used to encrypt and decrypt data.
  • Digital Certificate: This file contains the public key and information about the server and the CA.

Process:

  1. Handshake: When a browser connects to a server, the server sends its SSL certificate.
  2. Certificate Verification: The browser verifies the certificate’s authenticity by checking it against a list of trusted CAs.
  3. Session Key Generation: If the certificate is trusted, the browser generates a session key and encrypts it using the server’s public key.
  4. Secure Communication: The server decrypts the session key with its private key, establishing an encrypted communication channel using the session key.

Encryption Algorithms

Symmetric Encryption:

  • AES (Advanced Encryption Standard): A widely used symmetric encryption algorithm known for its speed and security. It uses keys of 128, 192, or 256 bits.
  • DES (Data Encryption Standard) & 3DES: Older symmetric algorithms. DES uses a 56-bit key and is considered insecure today, while 3DES applies DES three times for improved security.
  • How It Works: A single key is used to both encrypt and decrypt the data. Both parties must securely share and keep this key confidential.

Asymmetric Encryption:

  • RSA (Rivest-Shamir-Adleman): A common asymmetric encryption method used for secure data transmission. It relies on the difficulty of factoring large numbers.
  • ECC (Elliptic Curve Cryptography): Provides similar security to RSA but with smaller keys, making it faster and more efficient.
  • How It Works: Two keys are used—one public and one private. Data encrypted with the public key can only be decrypted by the corresponding private key and vice versa.

 

Encryption Keys

Key Generation: Keys are generated using mathematical algorithms. For symmetric encryption, a random number generator is often used. For asymmetric encryption, key pairs are generated mathematically.

Key Management: Secure storage and exchange of keys are critical. Methods like Public Key Infrastructure (PKI) are used to manage keys in a structured manner.

Key Length: The security of an encryption key is determined by its length (measured in bits). Longer keys are harder to break. For example, a 2048-bit RSA key is more secure than a 1024-bit key.

 

Plain Text and Cipher Text

Plain Text:

  • Refers to readable data before encryption. Examples include emails, passwords, and financial information.

Cipher Text:

  • This is the scrambled, unreadable version of plain text after encryption. It appears as a random string of characters and can only be converted back to plain text with the appropriate key.

Authentication and Authorisation

Authentication:

  • Process: Confirms the identity of a user or system. Common methods include:
    • Passwords/PINs: A secret known to the user.
    • Biometrics: Fingerprints, facial recognition, or retinal scans.
    • Tokens: One-time passwords (OTP) or security tokens.
    • Multi-Factor Authentication (MFA): Combines multiple methods, such as a password and a biometric scan, to enhance security.

Authorisation:

  • Process: Determines what resources or actions an authenticated user is allowed to access. Often implemented using Role-Based Access Control (RBAC) or Attribute-Based Access Control (ABAC).
  • Example: An authenticated user may have access to view documents but not to modify or delete them.

 

 

Hash Values

Hash Functions:

  • Purpose: Convert input data of any size into a fixed-size string. Common algorithms include SHA-256 and MD5.
  • Properties:
    • Deterministic: The same input will always produce the same hash.
    • Collision-Resistant: It’s computationally infeasible to find two different inputs that produce the same hash.
    • Non-Reversible: It’s practically impossible to reverse the hash to obtain the original input.

Use Cases:

  • Password Hashing: Instead of storing passwords, systems store hashed versions. During login, the user’s input is hashed and compared to the stored hash.
  • Data Integrity: Verifies that files or messages have not been altered. For example, software downloads often provide a hash value for the user to verify against the downloaded file.

 

Digital Signatures

Components:

  • Hashing: The document or message is first hashed.
  • Signing: The hash is then encrypted with the sender’s private key, creating the digital signature.

Process:

  1. The sender creates a hash of the message.
  2. The hash is encrypted with the sender’s private key, forming the digital signature.
  3. The signature is sent along with the original message.
  4. The recipient decrypts the signature using the sender’s public key to obtain the hash.
  5. The recipient generates a hash of the received message and compares it to the decrypted hash.
  6. If the hashes match, it confirms that the message is authentic and unaltered.

Applications:

  • Email Security: Confirms the sender’s identity and the integrity of the email content.
  • Software Distribution: Verifies that software has not been tampered with since it was signed by the developer.

2.5 Big Data

Syllabus

Investigate the effect of big data on web architecture, including:

  • data mining
  • metadata
  • streaming service management

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Investigate and analyse the impact of big data on web architecture, focusing on data mining, metadata, and streaming service management.

Success Criteria - Students can:

  • Define data mining, metadata, and streaming service management in the context of big data.
  • Explain how big data technologies influence web architecture, particularly in processing and storing large datasets.
  • Describe the role of data mining in extracting useful information from large datasets and how it affects decision-making in web services.
  • Identify how metadata is used to organise, manage, and retrieve data effectively in web systems.
  • Discuss the architecture and technology requirements for managing streaming services, including real-time data processing and content delivery.
  • Analyse real-world examples of how big data impacts companies like Netflix, particularly in content recommendations and user experience optimization.

  Content

Big Data is transforming the architecture of the web in profound ways, driving new structures and technologies to handle the vast influx of data. By examining data mining, metadata, and streaming service management, we can understand how modern web systems evolve to meet the demands of an increasingly data-driven world.

 

What is Big Data?

Big Data refers to extremely large and complex datasets that cannot be managed or processed using traditional data processing tools.

The concept of Big Data has evolved over time, leading to various definitions, but the most widely accepted characterisation is based on the "V's" framework, which outlines the key attributes of Big Data. Originally, Big Data was defined by three Vs—Volume, Velocity, and Variety—but over time, other V's have been added to describe its growing complexity and importance.

 

Data Mining

Data mining refers to the process of discovering patterns, correlations, and insights from large datasets. By analysing massive amounts of data, organisations can extract valuable information that can be used to make informed decisions, optimise processes, and predict future trends. Data mining is essential in industries such as e-commerce, healthcare, finance, and marketing.

 

How it works?

  • Data is collected from various sources (such as social media, IoT devices, and transaction records).
  • Advanced algorithms analyse the data to uncover hidden patterns and relationships.
  • These insights are used to guide decision-making, enhance user experiences, and improve business operations.

Common Data Mining Techniques

  • Classification: Assigning data into predefined categories (e.g., classifying customers based on purchase behaviours).
  • Clustering: Grouping similar data points together (e.g., segmenting users based on browsing patterns).
  • Association: Discovering relationships between variables (e.g., identifying which products are frequently bought together).
  • Regression: Predicting a continuous value based on other variables (e.g., forecasting sales based on past trends).

Examples

  • Retail and E-commerce: Amazon uses data mining to recommend products based on user history.
  • Healthcare: Hospitals analyse patient data to predict the likelihood of diseases and personalise treatments.

 

The rise of Big Data has significantly impacted web architecture, leading to the development of new technologies and approaches to manage, store, and process enormous volumes of data. Traditional data processing methods are insufficient, and modern web architecture has adapted to meet the challenges posed by Big Data.

Scalability and Distributed Systems

  • Challenge: Big Data systems must handle vast volumes of data that are continuously generated from various sources. Centralised systems cannot manage this level of data efficiently.
  • Solution: Modern web architecture incorporates distributed systems, where data is processed and stored across multiple servers. Technologies such as Hadoop and Apache Spark enable parallel data processing, allowing systems to scale horizontally by adding more servers as data volume grows.

Example: Companies like Google and Facebook use distributed systems to manage data generated by billions of users in real-time.

Real-Time Data Processing

  • Challenge: The speed (velocity) at which data is generated, especially from IoT devices and social media, requires web systems that can process and respond to data instantly.
  • Solution: Web architectures now integrate real-time data processing frameworks such as Apache Kafka and Apache Flink, which handle streaming data. These systems allow businesses to analyse data as it arrives, enabling real-time decision-making.

Example: Streaming platforms like Twitch and Netflix analyse user data in real-time to optimise streaming quality and recommend content.

Data Storage and Management

  • Challenge: The volume and variety of Big Data demand storage solutions that can handle structured, unstructured, and semi-structured data.
  • Solution: Web architectures have shifted towards cloud-based storage solutions like Amazon S3 and Google Cloud Storage, which offer flexibility, scalability, and cost-effectiveness. These solutions allow organisations to store data in its raw form and process it as needed, reducing the need for pre-defined schemas.

Example: E-commerce platforms store massive amounts of customer interaction data in cloud databases, which are analysed for marketing, inventory management, and customer service.

 

Metadata

Metadata is a set of data that describes and gives information about other data. Think of it as a label or tag that provides details about a file or piece of information. For example, when you take a photo with your phone, metadata can include the date and time the photo was taken, the location, the camera settings, and more. This extra information helps organise, categorise, and make sense of data.

 

In the world of Big Data, metadata is like a roadmap or a guide that helps us navigate through the massive and complex landscape of information. Imagine trying to find a specific book in a gigantic library without a catalogue or labels on the shelves. It would be nearly impossible! Metadata serves as that catalogue, providing essential details about the data so that we can understand, find, and use it effectively.

Data Organisation

  • Categorising Data: Metadata helps categorise data by providing information about its content. For example, in a huge collection of social media posts, metadata can include tags like the type of content (text, image, video), the topic discussed, the language used, and even user demographics. This makes it easier to group similar data together.
  • Data Models and Schemas: Metadata defines the structure of data in databases, such as tables, columns, and relationships. This structure is essential for storing and retrieving information efficiently, especially when dealing with large datasets.

Data Discovery

  • Enhanced Search Capabilities: When we search for something on the internet or in a database, metadata helps narrow down the results. For example, if you’re looking for movies from the 1990s on a streaming service, metadata tags like the release year, genre, and director make this search possible and efficient.
  • Facilitating Advanced Queries: In complex datasets, metadata enables advanced search queries. For example, a company might use metadata to filter customer data based on purchase history, geographic location, or engagement with marketing campaigns.

Improving Search and Analysis

  • Connecting Different Data Sources: In Big Data, information often comes from various sources, like social media, e-commerce, and sensor data. Metadata standardises these diverse sources by providing common reference points, such as time stamps or geographic coordinates, making it easier to combine and compare them.
  • APIs and Data Sharing: Metadata facilitates data sharing between systems and applications through APIs (Application Programming Interfaces). It provides the necessary details, such as data format and access protocols, to ensure that different systems can communicate and share data effectively.

Data Quality and Accuracy

  • Ensuring Data Accuracy: Metadata includes information about data provenance, or the origin of the data, which helps verify its accuracy and reliability. For example, knowing who created the data and when it was last updated can be crucial for research and decision-making.
  • Data Lifespan and Usage Policies: Metadata can include rules about how long data should be stored (data retention policies) and who is allowed to access or modify it. This is especially important in sectors like healthcare or finance, where data privacy and security are critical.

 

Streaming Service Management

Streaming service management involves organising, storing, and delivering digital content like movies, music, and videos over the internet. Companies like Netflix, Spotify, and YouTube are examples of streaming services that manage vast libraries of content and deliver it to users on demand.

 

Managing a streaming service involves several key tasks:

  1. Content Storage: Storing massive amounts of data, including videos, audio files, and metadata.
  2. Content Delivery: Making sure content is delivered quickly and efficiently to users around the world. This often uses Content Delivery Networks (CDNs) that cache content close to users.
  3. User Experience: Providing features like content recommendations, fast loading times, and high-quality streaming without buffering.
  4. Analytics and Personalisation: Analysing user behaviour to recommend new content based on their preferences.

 

Content Recommendations

Big Data’s Role:

  • Streaming platforms like Netflix and Spotify gather data on what content users interact with, including what they watch or listen to, the time spent on each piece of content, and their browsing habits.
  • This data is used to create personalised recommendations, improving user engagement and satisfaction. For instance, Netflix’s recommendation engine suggests movies and shows based on viewing history, ratings, and even how long a user watched a particular type of content.

Effect on Architecture:

  • To process and analyse this enormous amount of data, streaming services use big data technologies like Hadoop, which stores and processes large datasets, and Apache Spark, which performs real-time data processing.
  • The backend infrastructure is designed to be scalable and capable of handling real-time analytics. This often involves using distributed databases such as Cassandra or MongoDB, which can efficiently manage and query large datasets across multiple servers.

Real-Time Streaming and Adaptive Bitrate

Big Data’s Role:

  • Streaming services monitor the quality of the user’s internet connection and the specifications of their device (like screen resolution) to dynamically adjust the quality of the video or audio being streamed. This is called adaptive bitrate streaming.
  • By analysing network conditions in real-time, services can switch between different quality streams to prevent buffering, thus ensuring a smooth viewing experience.

Effect on Architecture:

  • The architecture for real-time streaming involves microservices that handle different tasks like encoding, caching, and distribution of content. These microservices work together to adjust the stream quality based on real-time data.
  • Tools like Kafka or RabbitMQ are used for real-time data streaming and processing. These tools help in the continuous monitoring of network conditions and user interactions, ensuring the stream quality is adjusted on the fly.

Predictive Maintenance

Big Data’s Role:

  • Predictive maintenance involves using big data analytics to foresee and prevent potential technical issues that could disrupt the service. For example, by analysing server logs, network traffic, and user error reports, streaming platforms can identify patterns that may indicate an impending system failure.
  • This helps in proactive troubleshooting, reducing downtime, and maintaining a seamless user experience.

Effect on Architecture:

  • The architecture must support the ingestion and analysis of large volumes of real-time data. Technologies like Apache Kafka or Amazon Kinesis are often used for data streaming, while machine learning models are deployed to detect anomalies in the data.
  • The system also needs to be highly available and fault-tolerant, as it is crucial to react quickly to potential issues. This often involves using cloud-based solutions that provide auto-scaling and automated recovery features.

Scalability and Flexibility

Big Data’s Role:

  • As the number of users and the amount of content grow, streaming services need to scale their infrastructure to handle increased traffic and data loads. Big data analytics helps predict when these spikes will occur, such as during the release of a popular show or live event.
  • By analysing historical data, services can allocate resources dynamically to meet demand, ensuring that users experience no delays or interruptions.

Effect on Architecture:

  • The architecture is typically cloud-based, utilising platforms like AWS, Google Cloud, or Microsoft Azure. These platforms offer scalable storage and computing resources that can be adjusted based on demand.
  • Containerisation tools like Docker and orchestration platforms like Kubernetes are often used to deploy and manage applications in a scalable and flexible manner. This allows streaming services to add or remove resources easily, maintaining performance during peak times.

Enhanced Security and Fraud Detection

Big Data’s Role:

  • Streaming platforms collect data to monitor for unusual activity, such as multiple logins from different locations, which could indicate account sharing or hacking attempts. Analysing this data helps in detecting and preventing fraud and security breaches.
  • For example, services like Netflix use machine learning models trained on user behaviour data to identify suspicious activity patterns.

Effect on Architecture:

  • The architecture for security and fraud detection needs to support real-time data analysis and rapid response. Tools like Elasticsearch are used to search and analyse security logs, while machine learning models deployed in the cloud can process large volumes of data and detect anomalies.
  • Data security measures, including encryption and secure APIs, are integrated into the architecture to protect user data and ensure compliance with regulations like GDPR.

2.6 World Wide Web Consortium

Syllabus

Investigate and explain the role of the World Wide Web Consortium (W3C) in the development of applications for the web, including:

  • Web Accessibility Initiative (WAI)
  • internationalisation
  • web security
  • privacy
  • machine-readable data

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Investigate and explain the role of the World Wide Web Consortium (W3C) in setting standards for web development, including initiatives related to web accessibility, internationalisation, web security, privacy, and machine-readable data.

Success Criteria - Students can:

  • Describe the purpose and impact of the Web Accessibility Initiative (WAI) in making web content accessible to people with disabilities.
  • Explain how W3C standards support internationalisation, allowing web applications to be used by a global audience in multiple languages and cultures.
  • Identify W3C guidelines that enhance web security and protect user privacy in web applications.
  • Understand the importance of W3C standards for machine-readable data, such as RDF and Linked Data, in enabling the semantic web and data interoperability.

  Content

The World Wide Web Consortium (W3C) is the main international standards organisation for the web, founded by Tim Berners-Lee in 1994. It develops open standards to ensure the long-term growth of the Web. Below are key initiatives and areas where the W3C has a significant impact on web development.

 

Web Accessibility Initiative (WAI)

The Web Accessibility Initiative (WAI) is a core program of the W3C that develops strategies, guidelines, and resources to make the web accessible to people with disabilities.

  • Accessible Rich Internet Applications (WAI-ARIA): WAI-ARIA is a set of specifications that provide ways to make web applications accessible, especially dynamic content and advanced user interface controls.
  • Authoring Tool Accessibility Guidelines (ATAG) and User Agent Accessibility Guidelines (UAAG): These guidelines focus on ensuring that tools used to create and consume web content are accessible. ATAG addresses accessibility in content creation tools, while UAAG focuses on browsers and media players.
  • Web Content Accessibility Guidelines (WCAG): WCAG provides a framework for making web content more accessible. It is structured around four principles: Perceivable, Operable, Understandable, and Robust (POUR). The guidelines are divided into three levels of conformance: A, AA, and AAA, with AAA being the highest standard.

 

Internationalisation

W3C’s internationalisation activities ensure that web applications and content can be used by people around the world, regardless of language, region, or cultural background.

  • Character Encoding and Text Direction: Standards such as UTF-8 and guidelines on bidirectional (BiDi) text support ensure that web content is correctly displayed in multiple languages, including those with complex scripts and right-to-left writing directions.
  • Language and Locale Identification: The use of attributes like lang in HTML and standards such as BCP 47 for language tags enable accurate language identification and proper rendering of localised content.
  • Cultural Adaptation: W3C provides best practices for handling region-specific date formats, currency, numbering systems, and other cultural nuances. This is crucial for creating user-friendly, localised web applications.

Web Security

Web security is a critical area where W3C standards aim to protect both users and web applications from various threats.

  •  Content Security Policy (CSP): CSP helps prevent cross-site scripting (XSS) attacks by allowing developers to specify which sources of content are trusted and can be safely loaded by the browser.
  • Secure Contexts: Many W3C APIs, such as Geolocation and WebRTC, require a secure context (HTTPS) to function, ensuring that sensitive data is transmitted securely.
  • WebAuthn: This standard provides a secure way to authenticate users through the browser, leveraging public-key cryptography instead of passwords. It is part of the FIDO2 project and aims to enhance security by reducing reliance on traditional passwords.

 

Privacy

W3C’s privacy standards aim to provide users with greater control over their personal information and ensure that web applications handle data responsibly.

  • Do Not Track (DNT): This was a proposal to enable users to express their preference not to be tracked across websites. While it is not widely adopted, it represents an important early effort in giving users control over their privacy.
  • Tracking Protection and Privacy Interest Group (PING): These groups focus on developing standards and best practices to minimise privacy risks and enhance transparency in data handling.
  • Privacy Sandbox: Recent initiatives are focused on developing a more privacy-friendly web environment, particularly in the context of advertising and tracking.

 

Machine-Readable Data

W3C promotes the use of structured, machine-readable data to enhance the interoperability and functionality of web applications.

  • Resource Description Framework (RDF): RDF is a framework for representing information about resources in the web. It is used in the Semantic Web to link related data.
  • Web Ontology Language (OWL): OWL builds on RDF and provides a richer vocabulary for describing properties and classes, enabling more complex relationships and reasoning about data.
  • SPARQL Protocol and RDF Query Language (SPARQL): SPARQL is used to query and manipulate RDF data. It allows for complex queries across diverse data sources.
  • JSON-LD (JavaScript Object Notation for Linked Data): JSON-LD is a lightweight format for structuring linked data using JSON, making it easier to integrate with existing web technologies and enabling more powerful data interoperability.

 

W3C Link Checker

The World Wide Web Consortium provides a series of tools to help maintain high-quality web standards. One of these is the W3C Link Checker, which scans your web pages for broken or outdated links. Try it out on some websites, see if you can find broken links.

2.7 Web Elements

Syllabus

Model elements that form a web development system, including:

  • client-side (front-end) web programming
  • server-side (back-end) web programming
  • interfacing with databases that are based on Structured Query Language (SQL) or non-SQL

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • understand the components and architecture of a web development system, including the roles of client-side and server-side programming.

Success Criteria - Students can:

  • Explain the difference between client-side and server-side web programming.
  • Identify and describe the roles of different elements in a web development system.
  • Create basic web pages using client-side technologies (e.g., HTML, CSS, JavaScript).
  • Develop server-side scripts to handle requests and responses.
  • Connect and interact with both SQL and non-SQL databases from a web application.
  • Demonstrate how data flows between the client, server, and database in a web development system.

  Content

 

Client-Side (Front-End)

Definition: This refers to the development of the user interface and experience in a web application. It involves creating the visual elements and interactive aspects of a website that users see and interact with directly in their web browser.

Technologies:

  • HTML (HyperText Markup Language): Defines the structure and content of a web page.
  • CSS (Cascading Style Sheets): Styles and layouts the web page, controlling the presentation and visual design.
  • JavaScript: Adds interactivity, dynamic content, and client-side logic to web pages. It can interact with HTML and CSS to manipulate the document object model (DOM).

Frameworks/Libraries:

  • React, Angular, Vue.js: Popular JavaScript frameworks/libraries that simplify complex UI development and state management.
  • Bootstrap, Tailwind CSS: CSS frameworks that provide pre-designed components and styles.

 

 

Server-Side (Back-End)

Definition: This refers to the server-side logic and operations that support the client-side of a web application. It handles data processing, server communication, and database interactions.

Technologies:

  • Languages:
    • Python (Django, Flask)
    • JavaScript (Node.js)
    • PHP
    • Ruby (Ruby on Rails)
    • Java (Spring Boot)
    • C# (ASP.NET)
  • Operations:
    • Request handling: Receiving and responding to HTTP requests from clients.
    • Business logic: Processing data, applying rules, and controlling application flow.
    • Authentication and Authorisation: Managing user identities and permissions.

Frameworks:

  • Express.js (for Node.js)
  • Django and Flask (for Python)
  • Spring Boot (for Java)
  • Ruby on Rails (for Ruby)
  • Laravel (for PHP)

 

Interfacing with Databases

Definition: This involves connecting the back-end of the web application to databases where data is stored, retrieved, and manipulated. It includes understanding both SQL and NoSQL databases.

SQL (Structured Query Language):

  • Definition: SQL databases use structured tables with predefined schemas. They are relational and enforce data integrity through relationships between tables.
  • Examples:
    • MySQL, PostgreSQL, SQLite, Microsoft SQL Server
  • Operations:
    • CRUD operations (Create, Read, Update, Delete)
    • Joins, transactions, and complex queries

NoSQL (Non-SQL):

  • Definition: NoSQL databases are designed for unstructured or semi-structured data. They are more flexible and can handle large volumes of data with varying structures.
  • Types:
    • Document-based (e.g., MongoDB)
    • Key-Value Stores (e.g., Redis)
    • Column-based (e.g., Cassandra)
    • Graph-based (e.g., Neo4j)
  • Operations:
    • Flexible schemas, horizontal scaling, optimised for read/write performance, suited for big data and real-time applications.
