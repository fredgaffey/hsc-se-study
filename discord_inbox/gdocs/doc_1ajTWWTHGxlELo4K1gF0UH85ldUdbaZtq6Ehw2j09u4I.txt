Investigate and practise how data is transferred on the internet 
 
Data Packets 
A Packet's Tale. How Does the Internet Work? (3:29) 
 
  

. 
* Computers ask for a copy of the webpage to access including the sites IP address in the form of a packet. Internet goes through regional wires and networks until it reaches an internet hub. 
* Fiber optic cables help internet travel through the world 
* When the server reads the request it sends a packet back to the requesting device. If a site is too big it might send multiple packets 
* If data transfer is too congested or high in traffic, sites can be pulverised into smaller packets and it can take multiple routes and spread out but reaches its final destination where they are reassembled 
* The packets are sent through multiple hubs which check the validity of the packet request before letting them continue their journey 
 
When a computer or similar device attempts to access a website on the internet, a request is put forward with the device's IP address attached. The request is sent in the form of a small packet containing the device's information and it travels through fiber optic cables until it reaches an internet hub.  
At the internet hub the request packet is linked to the direction of the server/site attempting to be accessed, when that destination is reached another packet (or if the site/server is too big to be sent as one packet, Packets) is sent towards the requesting device with its own IP address.  
If a big site's packet is broken into multiple packets, they make take different routes to reach the same requesting device when there is traffic. 
 
IP addresses 
IP addresses explained (3:32) 
 
  

 
* Represent where you live on the internet, and are required to send and receive data on the internet, it an identifier. 
* The destination address is the server attempting to be accessed, source is the device attempting to access the destination 
* IP addresses are an entirely unique series of numbers. 
* An IP address has 36 possible 1s and 0s and is made of 4 8-bit binary numbers and so there are 4,294,967,296 possible addresses available for use on the internet 
* NAT (modems), is a fix for running out of IP addresses. It takes multiple addresses from inside your network and merges them into one and allows them access to the internet.  
 
IP addresses are unique identifiers built into every device which can connect into the internet. An IP is required for transfer of packets between devices and servers and for devices to be able to access websites. The destination server can only return a packet or data to the source of the connection if it has an IP address 
Since the number of IP addresses in the world is limited, NAT's have been put in use to maximise the use of every IP address. A NAT acts like a mail man delivering packets to a group of IP's within its own Network 
 
Domain System Name (DNS) 
DNS Explained in 100 Seconds (2:15) 
 
  

 
* It hosts domain names on the internet and links it to an IP address. This system later translates human readable domain names into an IP address 
* It attempts to look for server cache when first connecting, 
 
Steps: 
1. User inputting domain name into browser 
2. Browsers sends a DNS query to a resolver provided by an ISP too lookup the DNS, DNS lookup. 
3. DNS resolver receives the query and checks cache to see if it has the requested domain's IP. If it is located, the IP address will be sent directly to the device if not it continues to search for it 
4. Recursive query is when the resolver queries the root DNS server, which hold info about top-level domains (like .com, .net , .org and so on) 
5. Top-Level domain (TLD) server is reached when the root server directs to the appropriate TLD server. The TLD server holds the most up-to-date info about the domain including its IP. 
6. Authoritative name server (ANS) are contacted by the resolver for the specific domain. This server holds the latest info about the domain 
7. The ANS responds to the resolver with the requested IP address.

The term ‘big data’ encompasses not only the volume of data but also its velocity, variety, veracity and value.

What is web architecture? 
Web architecture refers to the structure, components, and principles underlying the design and workings of web-based systems and applications. It includes the software, hardware, protocols, standards, and technologies that enable the functioning of websites, web services and web applications. 
  
  
Key components of web architecture include: 
1. Client-side components 
1.1 Web browsers: software applications that retrieve, render, and display web content to users. 
1.2 Client-side scripting languages (for example, JavaScript): used to enhance interactivity and functionality within webpages. 
1.3 User interfaces (UI): design elements and layouts that enable users to interact with web applications. 
1. Server-side components 
2.1 Web servers: software programs that host and serve web content in response to client requests. 
2.2 Application servers: middleware that provides runtime environments for executing server-side scripts and applications. 
2.3 Databases: systems for storing and managing structured data used by web applications. 
1. Networking infrastructure 
3.1 Internet protocols (for example, HTTP, HTTPS, TCP/IP): standards governing communication between clients and servers over the internet. 
3.2 Domain Name System (DNS): translates domain names into IP addresses, facilitating web address resolution. 
3.3 Content delivery networks (CDNs): distributed networks of servers that deliver web content to users based on their geographic location, improving performance and reliability. 
1. Data formats and protocols 
4.1 Hypertext markup language (HTML), cascading style sheets (CSS), JavaScript (JS): standard languages for creating and styling web content. 
4.2 Representational state transfer (REST), Simple object access protocol (SOAP): protocols for exchanging data between web services and clients. 
4.3 XML, JSON: data interchange formats commonly used for transmitting structured data over the web. 
1. Security mechanisms 
5.1 Secure Sockets Layer (SSL)/Transport Layer Security (TLS): protocols for encrypting data transmitted between clients and servers, ensuring confidentiality and integrity. 
5.2 Authentication and authorisation mechanisms: techniques for verifying the identity of users and controlling access to web resources. 
5.3 Firewalls, intrusion detection systems (IDS), and other security measures: protect web applications from unauthorised access, attacks and data breaches.

Web security 
Security is crucial for PWAs to protect users' data and ensure safe browsing experiences. W3C's standards for web security, such as HTTPS, CSP, CORS and secure authentication mechanisms, help developers build secure PWAs that mitigate common security threats, including XSS, CSRF and injection attacks. By adhering to W3C's security standards, developers can instill trust and confidence in their PWAs This encourages the use of the PWA. 
3) Define HTTPS, CSP, CORS and secure authentication mechanisms. 
 
Hyper Text Transfer Protocol Secure (HTTPS) - HTTPS is the secure successor of HTTP, which is the primary protocol used to send data between a web browser and a website. HTTPS is encrypted in order to increase security of data transfer. 
 
Content Security Policy (CSP) - CSP is a security standard for web apps which allows developers to restrict the loading of resources and adds an additional layer of security 
  
Cross-origin resource sharing (Cors) - Cors is a W3C standard, it allows servers to explicitly allow certain cross-origin requests () while rejecting others. Cors allows a server to relax the same-origin policy and is safer and more flexible than earlier techniques. 
 
Secure authentication mechanisms (SAM) - Authentication is the verification of a user's identity. Users are usually validated through certificates or hardware tokens. Secure authentication mechanisms are secondary and additional mechanisms such as multi-factor authentication or bio-metric authentication and are used to increase the security of an account and website. 
 
Privacy 
Privacy is a concern for all software engineers. This is especially the case when developing PWAs because of the sensitive data they handle, such as user preferences, location information and personal data. 
W3C has privacy standards and guidelines that developers can follow to design PWAs that respect users' privacy rights and comply with regulatory requirements. Software engineers can include features like browser privacy controls, user consent mechanisms and secure data handling practices to build PWAs that prioritize user trust and privacy protection. 
Machine-readable data 
Developers building PWAs can use W3C standards for representing and exchanging machine-readable data. This enhances interoperability and automation by making it easier to understand and process by search engines, web crawlers and other applications. Being machine readable makes the PWAs content easier to discover and access. This makes it more visible and effective on the web.

The key principles 
Privacy by design is built around seven key principles[1]: 
  
1. Proactive not reactive, preventative not remedial 
  
Take a proactive approach, anticipating risks and preventing privacy-invasive events before they occur. 
  
2. Privacy as a default setting 
  
Automatically protect personal information in IT systems and business practices as the default. 
  
3. Privacy embedded into design 
  
Embed privacy into the design of any systems, services, products and business practices. You should ensure that privacy becomes one of the core functions of any system or service. 
  
4. Full functionality: positive-sum not zero-sum 
  
Incorporate all legitimate interests and objectives in a ‘win-win’ manner, not through a ‘zero-sum’ (either/or) approach. This will avoid unnecessary trade-offs, such as privacy versus security, demonstrating that it is possible to have both. 
  
5. End-to-end security – full lifecycle protection 
  
Put in place strong security measures throughout the ‘lifecycle’ of the information involved. Process personal information securely and then destroy it securely when you no longer need it.  
  
6. Visibility and transparency – keep it open 
  
Ensure that whatever business practice or technology you use operates according to the stated promises and objectives and is independently verifiable. Make people fully aware of the personal information being collected, and for what purpose.     
  
7. Respect for user privacy – keep it user centric 
  
Keep the interest of individuals paramount in the design and implementation of any system or service. You can do this by offering strong privacy defaults and user-friendly options, as well as ensuring appropriate notice is given. 
  
Privacy by design has become an internationally accepted framework for protecting privacy.  It has also been incorporated into Article 25 of the European Union General Data Protection Regulation (GDPR), which has made “data protection by design and default” a mandatory requirement in the European Union and the United Kingdom.

Describe types of algorithms associated with ML 
1) Describe types of algorithms associated with ML including: 
 
      * linear regression 
 
Linear regression algorithms are used to predict values in a continuous range. Linear regression is an algorithm modelling relationships between independent and dependent variables. Its simplicity, interpretability, and efficiency makes it a popular.  
 
      * logistic regression 
 
It is used to generate predictions for categorical data (colour, gender, job) rather than numerical continuous data (height, weight, speed) 
 
Logistic regression is a technique for prediction generation for categorical data rather than continuous numerical data. Logistic regression is ideal for binary classification problems, determining the probability of data entries belonging to one of two categories. For example, classifying animals as 'cat' or 'not a cat' based on distinguishing features (whiskers, 4 legs, claws). Here, data is represented as categorical features which are kept as binary values (0 = False, 1 =  True). Logistic regression utilizes the logistic (sigmoid) function to map input features to a probability between 0 and 1. 
 
 
 
      * K-nearest Neighbour (K-NN or KNN) 
 
KNN algorithms are a simple method used in machine learning to classify data through looking at data points closest to a new point and deciding which group it belongs to. It uses labelled data (data with known answers) to make predictions, KNN is non-parametric (meaning it doesn't make any assumptions about the data distribution), when new data points require classification, KNN finds the closest points (neighbors) which is considered the 'K', then it searches through the groups of these neighbors and assigns the new data point to a group it most belongs to. KNN can be used to predict continuous values (regression), it is most commonly used for task classification, where the goal is to assign data points to a specific category based on their features.

ORDER BY column 
It is often useful to sort a table of data by a given column. For example, you might want to sort a dataset by date to put events into a chronological order.  
To sort rows in SQL we use the ORDER BY keyword. This comes after your SELECT, FROM and WHERE statements. By default, we sort in ascending order, but if you want to be explicit you can use the keyword ASC. To sort in descending order we can use the keyword DESC. 
The structure of an ORDER BY statement is: 
ORDER BY attribute ASC|DESC; 
 




If you have a large dataset, it is impractical to display all the rows in the dataset. To do this in SQL, we use the LIMIT keyword to specify how many rows we would like to display. 
The LIMIT clause comes after the SELECT, FROM, WHERE and ORDER BY clauses.  
LIMIT number_of_rows;
