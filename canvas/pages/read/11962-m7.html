Inheritance & Polymorphism

Recall the definition of inheritance from module 2.2.2 OOP Features: Inheritance.

"Inheritance is a key concept in object-oriented programming (OOP) that allows classes to inherit attributes and methods from other classes. This enables the creation of a hierarchical structure of classes, where child classes can reuse and extend the functionality of their parent class"

 

But what if we wanted a method (that is inherited from the parent class) to do something different in the child class?

For example:

  • All animals can make a sound. However, not all animals make the same sound.

We can achieve this through polymorphism!

 

In object-oriented programming (OOP), inheritance and polymorphism are closely related concepts, often used together to promote code reuse, modularity, and extensibility. The relationship between inheritance and polymorphism lies in the fact that inheritance enables polymorphism.

 

Polymorphism

Polymorphism is a key concept in object-oriented programming (OOP) that allows for classes of objects to behave in different ways (depending on the context) without changing the interface in which they are used (i.e. the way in which we interact with the object).

To put it simply, polymorphism allows us to perform a single action in different ways.

Note: The interface of a class is simply defined as the method signatures in the class (the method names and associated parameters)

 

Method Overriding

In Python, polymorphism is achieved through a technique called Method Overriding. Method overriding is where an inherited method in a child class is declared again with the same name and parameters, but operates in a different way than the same method in the parent class.

Consider a parent class called Animal, where its interface consists of the methods:

  • getName()
  • setName()
  • make_sound()
  • eat()

All animals can make a sound through the make_sound() method and can eat through the eat() method.

 

However, we would want child classes like Dog and Cat to make different sounds when using the method make_sound() (but the way they eat remains the same).

Consider the child classes Dog and Cat.

 

The Dog child class uses method overriding to change the output of the make_sound() method to "Woof! Woof!" to suit the context of the class.

Similarly, the Cat child class uses method overriding to change the output of the make_sound() method to "Meow! Meow!" to suit the context of the class.

 

In both the Dog and Cat child classes, the make_sound() method is defined in the same way as the Animal parent class using def make_sound(self):, but the code inside of the method behaves differently.

 

We now demonstrate the use of polymorphism when these classes are instantiated as interactable objects.

Output:

Alex says generic animal sound
Max says Woof! Woof!
Tom says Meow! Meow!
Alex is eating
Max is eating
Tom is eating

 

Notice how we can interact with the objects belonging to the Animal class (and its subclasses) by using the same make_sound() method, but the subclasses behave differently from the Animal parent class.

Additionally, notice how the behaviour in the eat() method remains the same since eat() was not overridden in the Dog or Cat child classes.

Generalisation

Generalisation revolves around the concept of reusability in object oriented programming.

The process of generalisation aims to reduce copied code and improve maintainability by finding common traits among various specific classes and creating a general class from these traits.

 

Example of Generalising Classes

We achieve generalisation by extracting the essential characteristics (attributes and methods) that are shared between related or similar classes. These common characteristics then form the generalised parent class of those classes (which are now child classes).

Consider two separate classes called FullTimeEmployee and PartTimeEmployee.

Both types of employees have a name, a job title and a list of tasks. Full-time employees have a yearly salary, which is paid on a monthly basis. Part-time employees have a set number of working hours per week and are paid on an hourly rate.

Looking at the FullTimeEmployee and PartTimeEmployee classes, we can find common characteristics.

Both classes have the same:

  • attributes __name, __title and __tasks
  • methods getName(), getTitle(), getTasks(), setName(), setTitle(), addTask() and removeTask()

Additionally, the first 3 lines of the printInfo() method are the same between the classes.

 

Using these common characteristics, let us create a generalised parent class called Employee that will contain the attributes and methods that ALL types of employees should have.

To complete the generalisation process, we must modify the FullTimeEmployee and PartTimeEmployee classes so that they are child classes that inherit from the Employee parent class.

The common attributes and methods that were placed in the Employee parent class can now be removed from the FullTimeEmployee and PartTimeEmployee classes since these are inherited from the Employee class.

Notice how the FullTimeEmployee and PartTimeEmployee classes are substantially shorter than before, only containing the attributes and methods that are specific to the type of employee with common characteristics placed out of sight in the Employee parent class.

  • FullTimeEmployee contains the attributes and methods that deal with a salary
  • PartTimeEmployee contains the attributes and methods that deal with an hourly rate
  • Employee contains the attributes and methods that all types employees should have (name, job title and tasks)

A benefit of having common characteristics contained in a single class is that it allows us to make modifications to these characteristics which will apply to all child classes without the need to manually make the same modification to multiple classes.

 

Use of Polymorphism in printInfo()

The only difference in the printInfo() method between the FullTimeEmployee and PartTimeEmployee classes was the last print() statement which either showed the employee's salary or hourly rate.

  • The first three print() statements which displayed the employee's name, title and tasks have been placed in the printInfo() method of the Employee parent class.
  • The last print() statement has remained in the now overridden printInfo() method of the FullTimeEmployee and PartTimeEmployee classes, where the printInfo() method of the Employee parent class is called using super().printInfo() before running the last print() statement to show either the salary or hourly rate depending on the child class.

 

The Need for Abstraction

Currently, the Employee parent class guarantees that all types employees must have a name, a job title and a list of tasks. However, it does NOT guarantee that all types employees must be paid. In other words, nothing is preventing the programmer from accidentally (or on purpose) omitting the calculate_pay() method from a child class of Employee.

We can enforce that all Employees must have a calculate_pay() method by using ABSTRACTION.

 

Abstraction

Abstraction revolves around the concept of hiding implementation details and focusing on the essential features of a class. This benefits the programmer, helping to manage complexity by allowing them to deal with ideas rather than specifics.

In Python and many other object oriented programming languages we are able to declare classes and methods as 'abstract'.

  • For a class this means it cannot be instantiated, as such, the only way to access its attributes and methods is to create a subclass which can inherit these features which can then be used.
  • For an abstract method, this means that the implementation is not defined in the method, but will rather be defined in subclasses.

For example, consider a set of different characters in a video game.

  • We know at a minimum that all characters in this video game must move, but we don't know how each type of character will move. Some characters might walk normally on the ground, some might be able to fly and some might be able to dig underground.
  • Using abstraction, we can have an unimplemented move() method inside a generalised character class which hides the complex details of how different characters will move; leaving each type of character to implement their own move() method in each child class.

 

Example of Abstraction

We achieve generalisation by using the Abstract Base Classes (ABC) library which is a Python standard library. This library is imported at the top of the Python file by using:

  • from abc import ABC, abstractmethod

Consider the generalised Employee parent class from before.

The Employee class will need to abstracted for two reasons.

  1. To prevent the Employee class itself from being instantiated into an object. We need all employee objects to be instantiated from specific types of employees only (the child classes of Employee).
  2. To ensure that all child classes of Employee have a calculate_pay() method. We need all employee objects to have this method.

 

First, we need to import the Abstract Base Classes (ABC) library and define the Employee class as an abstract class.

  • This tells the Python interpreter that the Employee class cannot be instantiated into an object; it can only be inherited from.

 

Second, we need to add the calculate_pay() method as an abstract method using @abstractmethod tag above the method's definition and using the keyword pass inside the method's implementation.

  • This tells the Python interpreter that any class that inherits from Employee must have an implemented calculate_pay() method.

Now consider a new type of employee called InternEmployee which is a child class of the Employee class.

Notice how the calculate_pay() method is missing from the InternEmployee class. If we tried to instantiate this class as it is, then we will be met with the following error message.

Output:

Traceback (most recent call last):
  File "/Users/martin/Desktop/Python OOP/main.py", line 3, in <module>
    employee = Employee("Martin Madrid", "Software Engineer", "UNSW")
TypeError: Can't instantiate abstract class Employee with abstract method calculate_pay

 

By adding the calculate_pay() abstract method in the Employee parent class, it prevents the InternEmployee child class from being instantiated into an object without the calculate_pay() method.

By implementing all abstract methods in the Employee parent class, we can now instantiate the InternEmployee child class.

  Content

In system analysis and design, diagrams play a crucial role in visualising and understanding the structure, processes, and interactions within a system. Different types of diagrams focus on specific aspects, helping developers, analysts, and stakeholders to communicate ideas and create effective designs.

 

Class Diagrams 

The Object Oriented Paradigm is "design first" as we need to design our objects and relationships first before we begin programming so that we have a clear outline of how to structure our program. Class diagrams aid us in the designing process helping to model our objects and their relationships so we can reference the diagram as we implement a system.

 

Class diagrams are a type of diagram defined in the Unifed Modeling Language (UML), which is a standard used to visualise the design of a system. They describe the structure of a system, showing the classes in a system, their attributes, methods and the relationships between classes.

 

The basic building blocks of a class diagrams are Classes, which are represented as a rectangle, divided into three parts:

  • The class' name
  • Attributes of the class, with the type of the attribute is specified with a colon and then the type.
  • Methods that the class implements, with the parameters in parenthesis and then the return type specified after a colon

 

In a class diagram we can create many classes and then represent their structure by specifying relationships between them. These may include:

Type Use
 Example
Inheritance Represents a relationship between a child class and a parent class
Relationship

Models the relationship where a class can use or own objects from another class

Multiplicities specify the number of instances of one class that can be associated with one instance of another class.
