Outline the features of OOP that support collaborative code development including:

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand and explain how Object-Oriented Programming (OOP) features support collaborative code development, focusing on consistency, code commenting, version control, and feedback mechanisms.

Success Criteria - Students can:

  • Explain how OOP features like modularity, naming conventions, design patterns, and comments contribute to consistency and readability in collaborative development.
  • Describe the role of version control systems in managing code changes and the importance of code reviews, automated testing, and CI/CD pipelines in maintaining high code quality.

Initial Clone of a Repository

  1. Use git clone <url> to clone the repository. Remember to replace the <url> with the link that is found under: Code (green button) > HTTPS (see screenshot below).

    Reason: We must be editing our code locally on Visual Studio Code, not using the online editor on GitHub.




 

 

 Using a Branch to Add Features

  1. Change the Visual Studio Code workspace to the folder that was created from cloning the repository. Use the command git pull origin main to update the local repository with any changes that may be on the GitHub repository.

    Reason: Ensures your local repository is synchronized with the remote repository to avoid conflicts.



  2. Then, create a new branch for your feature using this command git checkout -b <new-feature-branch>. Remember to replace <new-feature-branch> with the name of the feature that you are implementing (you come up with this name).

    Reason: Creating a new branch allows you to work on the new feature without affecting the main branch. 



  3. Now, implement the code for your new feature in your local environment, i.e., Visual Studio Code.



  4. After this, you may stage all the changes you've made to the code by running the command git add .

    Reason: Staging the changes prepares them to be committed. You can also add specific files instead of all changes.



  5. Commit the changes with a message through the command, git commit -m "Add feature X". Make sure you include an appropriate message with your commit that details the changes you made.

    Reason: Commit messages should be descriptive to provide context about the changes.



  6. Push the changes to the remote repository by using git push.

    At this stage you will likely be asked to login to GitHub if you have not already. For the first push we do to a new branch, there is be no corresponding branch on the GitHub repository so the push command will fail (see screenshot). So, just copy the command in the error, git push --set-upstream origin <branch-name>,  to push it for the first time, you only need to run this command once for a new branch.

    Reason: Pushing the changes uploads your branch to the remote repository, making it available for review and merging.



  7. Create a Pull Request and Merge on GitHub
        •    Copy the link that you received when running the git push command from the previous step. Paste it into your browser; it should be in the form https://github.com/<username>/<repository>/pull/new/<branch>
        •    Fill in a meaningful title and description for your pull request, then press the "Create pull request" button
        •    Review the changes, address any comments or feedback.
        •    Once approved, merge the pull request into the main branch.

    Reason: Merging via a pull request allows for code review and ensures that the main branch is always stable.




  8. Return to Visual Studio Code and checkout the main branch which you have just merged your changes to by using git checkout main

    Reason: Switches your working directory back to the main branch to incorporate the latest changes.



  9. Pull the latest changes from the main branch with the command git pull origin main

    Reason: Ensures your local main branch is up to date with the remote main branch, including the new feature you just merged.



  10. Repeat from Step 1 whenever you want to add a new feature into your program.

    Reason: To add a new feature into the codebase.
