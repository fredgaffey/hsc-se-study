|----------|-----------|----------|-------|-------|------------|--------|

| **Environmental Specification** | The student documents a comprehensive and accurate list of all hardware and software environments, including platforms, browsers, and technical compatibility requirements. | **Performance Criteria** | The student outlines a detailed and relevant set of performance criteria, including specific security standards, usability goals, and loading times, to guide development. (3 pts) | | The student describes some performance criteria but they may be incomplete or lack specificity for all aspects. (2 pts) | | The student lists a few general performance criteria but they are not well-defined. (1 pts) | 0 pts / 3 pts |
| **IPO Input, Process, Output Chart** | The student creates a comprehensive and accurate IPO chart for each application feature, clearly detailing all inputs, processes, and outputs. (3 pts) | | The student constructs an IPO chart for some features but it is incomplete or unclear. (2 pts) | | The student provides a basic IPO chart for some features but it is incomplete or unclear. (1 pts) | 0 pts / 3 pts |
| **Gantt Chart** | Develops an intensive Gantt Chart showing the timeline for the development of the project, including specific tasks, allocations, major milestones, and resources. (4.5 to 5 pts) | Develops a thorough Gantt Chart showing the timeline for the development of most of the project, including most tasks and/or allocations, major milestones and/or timeframes for each phase/step of the project. (3.1 to 4 pts) | Develops a sound Gantt Chart showing the major items/tasks of the project, including some tasks and/or allocations, major milestones and/or timeframes for each task or phase progress tracking. (2.1 to 3 pts) | Develops a basic Gantt Chart showing the major items/tasks of the project, including basic tasks and/or major milestones to track task calendar progress. (1.1 to 2 pts) | Develops an elementary Gantt Chart showing just the timeline for the development of a limited set of the project, including general tasks or major milestones to track task calendar progress. (0.1 to 1 pts) | 0 to 5 pts |
| **Research** | The student conducts intensive research, synthesizing information from similar applications, current technologies, and best practices to inform and justify their design choices. (4.1 to 5 pts) | The student conducts thorough research, synthesizing information from similar applications, current technologies, and best practices to inform and justify their design choices. (3.1 to 4 pts) | The student conducts sound research, including information from similar applications, current technologies, and best practices to inform their design choices. (2.1 to 3 pts) | The student conducts basic research, including information from similar applications but may lack depth or detail. (1.1 to 2 pts) | Provides some relevant information. (0.1 to 1 pts) | 0 to 5 pts |
| **Data Flow Diagram (DFD)** | The student designs three data logical and accurate DFDs that correctly illustrate the flow of data for the logic process and TWO advanced features of the project, including external entities, processes, data stores, and data flows. (4.1 to 5 pts) | The student designs three data and accurate DFDs that correctly illustrate the flow of data for the logic process and TWO advanced features of the project, including external entities, processes, data stores, and data flows. (4.1 to 5 pts) | The student designs three-user DFDs that illustrate the flow of data for the major logic process and TWO advanced features of the project, including external elements, processes, data stores, and data flows. (2.1 to 4 pts) | The student designs some DFDs that show relevant design configurations. (2.1 to 4 pts) | | 0 to 5 pts |
| **Storyboard** | The student creates a detailed storyboard that demonstrates a logical layout, structure, and interactive elements for all significant screens. The storyboard describes a clear and logical user journey, effectively showing the sequence of interactions and user experience. | The student creates a thorough storyboard that demonstrates a logical layout, structure, and elements for most screens. Storyboard describes a clear logical user journey, showing the sequence of interactions and user experience. | The student creates a sound storyboard that demonstrates a layout, structure, and some elements. Storyboard describes a user journey, showing the sequence of interactions. | The student creates a basic storyboard that demonstrates a layout, structure, and user experience. | Provides some relevant information. | 0 to 5 pts |
| **Pseudocode** | The student develops a comprehensive set of detailed algorithms that demonstrates a logical layout, structure, and detailed elements for all significant scenes. | The student develops pseudocode that demonstrates a logical layout, structure, and elements for most scenes. Pseudocode describes a user logical journey. | The student develops pseudocode that demonstrates a layout, structure, and elements for some scenes. | The student provides some pseudocode that may not be detailed or well-structured. | Provides some relevant information. | 0 to 5 pts |
| **Version Control** | The student implements a version control system (e.g., Git) and demonstrates an extensive understanding of its use through a well-documented and consistent commit history for their sample 500+ well-application. (4.1 to 5 pts) | The student implements a version control system (e.g., Git) and demonstrates a thorough understanding of its use through a well-documented and consistent commit history for their sample git application. (3.1 to 4 pts) | The student implements a version control system (e.g., Git) and demonstrates a sound understanding of its use through a documented and consistent commit history for their sample git application. (2.1 to 3 pts) | The student implements a version control system (e.g., Git) and demonstrates a basic understanding of its use through a commit history. (1.1 to 2 pts) | Provides some relevant information. (0.1 to 1 pts) | 0 to 5 pts |
| **Ingdeck** | Log book demonstrates extensive planning and documentation aligned with all stages of the software engineering process. Entries are regular, chronological, and follow conventions. Reflections show high-level insight with clear evidence of decision-making, problem-solving, and development. The log book demonstrates that the student understands the task and interactive planning. (4.1 to 5 pts) | Log book includes thorough and consistent entries linked to clear stages of the development process. Reflections show good understanding of challenges. Planning is structured and shows evidence of logical insight that reflects the task and interactive planning. (3.1 to 4 pts) | Log book contains varied entries, with some regular entries, covering several stages of the project. Reflections may be descriptive rather than analytical. Planning shows general understanding. Entries are minimal or superficial, showing limited engagement with the task. Focus may be minimal or superficial, showing limited engagement with the task. (2.1 to 3 pts) | Log book includes infrequent or incomplete entries. Planning is unstructured or inconsistent with the log book content. Students demonstrate an underdeveloped understanding of the work. (1.1 to 2 pts) | | 0 to 5 pts |

## Notes
- **Points**: The total points possible for each criterion varies; some are worth 3 pts while others are worth up to 5 pts
- **Rating Levels**: Criteria are evaluated on a scale from Elementary (lowest) to Extensive (highest)
- **Not Achieved**: Some criteria show "No Marks" or "No Evidence" indicating no points were awarded
