Apply security features incorporated into software, including data protection, security, privacy and regulatory compliance.

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand how to apply security features in software to ensure data protection, privacy, and regulatory compliance.
  • Learn to implement security features in software applications using best practices.

Success Criteria - Students can:

  • Students will be able to explain the importance of data protection, security, privacy, and regulatory compliance in software development.
  • Students will be able to implement these security features in a software application.

  Content

Incorporating security features into software development is essential for safeguarding data, ensuring privacy, and adhering to regulatory requirements. These features are critical for preventing vulnerabilities, defending against attacks, and maintaining user trust. Below is an explanation of key aspects of data protection:

 

Data Protection

Data Protection

Data protection is a comprehensive approach to safeguarding data from vulnerabilities and unauthorised access while ensuring its confidentiality, integrity, and availability. It involves implementing various security measures to protect data throughout its lifecycle, whether stored, processed, or transmitted.

  • Encryption:
    Encrypt sensitive data at rest and in transit to prevent unauthorised access. Use strong encryption standards like AES (Advanced Encryption Standard) for stored data and TLS (Transport Layer Security) for data in transit.

  • Access Controls:
    Implement strict access controls to ensure only authorised users can access sensitive data. This may include role-based access control (RBAC), where users are granted access based on their organisational

  • Backups:
    Regularly back up data to secure locations to prevent data loss due to accidental deletion, corruption, or attacks like ransomware.

Security

Security

Software security is designed to protect users from threats from unauthorised parties, ensuring their data and interactions with the software remain safe and secure. This involves implementing various security measures, such as authentication, encryption, access controls, and regular security assessments, to safeguard against potential threats.

  • Authentication and Authorisation: Verifying the user's identity when attempting to access a system. Strong authentication includes:
      • Multi-factor authentication (MFA) requires providing two or more verification factors (or tokens) to gain access to a resource.
      • Strong Passwords - enforcing character restrictions or number requirements on passwords during registration. 
      •  Authorisation or authorisation to access specific resources. 
      • Roles-Based (RBAC) - assigning permissions to users based on roles within an organisation as teacher and student)
      • Access Control List - specifying which users or systems are granted permissions. For example, a file might have an ACL that specifies read, write, and execute permissions. 
  • Input Validation: Validating user-provided data is correct, safe and secure before processing, helping protect software from attacks (SQL injections, cross-site scripting and buffer overflows. To prevent this:
      • Sanitisation input must be provided on both the client and server sides.
      • Define acceptable input formats (allowing numbers only in a phone number field)
  • Security Audits: Systematically review the software, its environment, and its processes to ensure compliance with security policies, identify potential vulnerabilities, and verify the effectiveness of security measures. Audits can be performed internally by an organisation or by third-party auditors.

Privacy

Privacy

Privacy in secure software protects an individual's personal data and information. 

  • Data minimisation is a concise database that stores only what is necessary to prevent privacy breaches. 
  • User Consent: Obtaining a user from the user client of obtaining permissions before collecting or processing data. Creating UI that has buttons or checkboxes for a consent form. 
  • Data Access Controls: Ensure that only authorised personnel can access private information—authorisation only for specific roles will access private data using a roles-based authorisation system.

Regulatory Compliance

Regulatory Compliance

Achieving regulatory compliance means aligning with legal and regulatory guidelines applicable to the region. Software developers must ensure that the software meets legal obligations and protects user data. 

  • Compliance Audits:
    Regularly conduct audits to ensure that the software complies with relevant regulations. This may include reviewing data handling practices, security measures, and user consent mechanisms.

  • Data Retention Policies:
    Implement data retention policies that comply with regulations, specifying how long data is stored and when it should be deleted.

  • User Consent:
    Ensure users consent before their data is collected, processed, or shared. This is especially important for sensitive personal data.
