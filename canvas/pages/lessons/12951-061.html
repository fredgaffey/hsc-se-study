Compare Object-Relational Mapping (ORM) to SQL

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the core differences between SQL and ORM, and learn when to choose between direct SQL querying and using an ORM framework in application development.

Success Criteria - Students can:

  • Describe the differences between SQL and ORM in terms of how they interact with databases.
  • Identify scenarios where using SQL or ORM would be more appropriate based on project needs.
  • Analyse the performance trade-offs and benefits of using ORM versus writing raw SQL queries.

  Content

 

What is ORM?

ORM is a programming technique that allows you to interact with the database by using the object-oriented programming (OOP) model. With ORM, you manipulate database tables as though they were programming language classes, and rows are represented as instances (objects) of those classes.

Popular ORM frameworks include Hibernate (Java), SQLAlchemy (Python), Django ORM (Python), and Entity Framework (C#).

  • Abstraction of SQL: Instead of writing SQL queries, ORM frameworks generate SQL code on behalf of the developer based on the objects and methods in the application code. This creates an abstraction layer between the database and the application code, allowing developers to interact with databases without manually writing SQL.
  • Example of ORM Usage:
# Using Django ORM in Python to query users
users = User.objects.filter(age__gt=30).order_by('last_name')

This ORM query performs the same operation as the SQL query above but uses Python-like syntax to query the database. The ORM framework translates this into an SQL statement under the hood.

 

Advantages of ORM:

  • Increased Productivity: By automating CRUD CRUD: An acronym for Create, Read, Update, Delete, which represents the four basic operations performed on data in a database or storage system. operations, developers can focus on the business logic rather than manually writing SQL queries.
  • Database-Agnostic: ORM frameworks allow developers to switch between different databases (e.g., from MySQL to PostgreSQL) with minimal code changes, as the SQL is abstracted away.
  • Less Boilerplate: Common database operations are handled by the ORM framework, leading to less repetitive code and improved maintainability.
  • Object-Oriented Approach: ORMs allow you to work with native language objects (classes and objects), which is more intuitive for developers familiar with object-oriented programming. This can also lead to better integration with the rest of the application.

Disadvantages of ORM:

  • Performance Overhead: ORMs typically introduce some performance overhead because the generated SQL queries may not be as optimised as hand-written SQL. This is especially noticeable in large or complex queries.
  • Less Fine-Grained Control: While ORMs simplify many operations, they can make it more difficult to fine-tune queries for performance or handle very specific use cases that require complex SQL logic.
  • Learning Curve: Using an ORM effectively requires understanding both the ORM framework and the underlying database concepts. Inexperienced developers might misuse the ORM and create inefficient database queries. 

 

SQL vs ORM

 

Feature SQL ORM
Level of Abstraction Low: Direct database access through SQL queries High: Access through programming language objects
Performance High for complex queries, fine-tuned optimisations Lower performance due to abstraction overhead
Ease of Use Requires knowledge of SQL and database schema Easier for developers familiar with OOP, no SQL needed
Portability Low: SQL may need adaptation for different DBs High: ORMs are designed to work with multiple databases
Maintenance Can be harder to maintain as the app grows Easier due to less boilerplate and abstraction
Granular Control High: Full control over the query execution Low: ORM abstracts query execution details
Flexibility High: Complex queries are easier to implement Limited: Complex queries can be hard to implement in ORM
Learning Curve Steep: Requires SQL and database knowledge Moderate: Requires understanding of both ORM and DB basics

 

When to Use SQL vs ORM

Use SQL when:

  • Performance is critical, and you need full control over database queries (e.g., in performance-sensitive applications like banking systems or data-heavy analytics).
  • You need to write complex queries with multiple joins, nested subqueries, or optimizations that are hard to express in ORM.
  • The project requires database-specific features such as stored procedures, triggers, or specific SQL dialects that the ORM cannot easily handle.

Use ORM when:

  • The project is more CRUD-heavy, and you need to automate routine database interactions (e.g., simple web apps).
  • Portability is important, and the ability to switch databases without modifying code is a key requirement.
  • You want to speed up development by avoiding the need to write SQL and managing database objects using the language’s OOP principles.
  • You need to rapidly prototype an application without worrying about database details at first.
