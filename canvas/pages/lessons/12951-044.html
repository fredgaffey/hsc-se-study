2.4 Securing the Web

Syllabus

Explain the processes for securing the web, including:

  • Secure Sockets Layer (SSL) certificates
  • encryption algorithms
  • encryption keys
  • plain text and cipher text
  • authentication and authorisation
  • hash values
  • digital signatures

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Explain the various processes and technologies used to secure web communications and data, including SSL certificates, encryption algorithms, keys, and methods of authentication and authorisation.

Success Criteria - Students can:

  • Describe the role of Secure Sockets Layer (SSL) certificates in establishing secure connections and ensuring data privacy on the web.
  • Explain how encryption algorithms and encryption keys transform plain text into cipher text to protect sensitive information.
  • Explain the use of hash values and digital signatures in verifying data integrity and ensuring secure communication.

  Content

 

SSL Certificates

 

Definition

SSL certificates are digital certificates used to establish a secure, encrypted connection between a web server and a client (typically a web browser). They are part of the broader category of Transport Layer Security (TLS) certificates.

 

Components:

  • Certificate Authority (CA): A trusted organisation that issues SSL certificates after verifying the identity of the entity requesting the certificate.
  • Public and Private Keys: The certificate includes a public key, which is paired with a private key held by the server. These keys are used to encrypt and decrypt data.
  • Digital Certificate: This file contains the public key and information about the server and the CA.

Process:

  1. Handshake: When a browser connects to a server, the server sends its SSL certificate.
  2. Certificate Verification: The browser verifies the certificate’s authenticity by checking it against a list of trusted CAs.
  3. Session Key Generation: If the certificate is trusted, the browser generates a session key and encrypts it using the server’s public key.
  4. Secure Communication: The server decrypts the session key with its private key, establishing an encrypted communication channel using the session key.

Encryption Algorithms

Symmetric Encryption:

  • AES (Advanced Encryption Standard): A widely used symmetric encryption algorithm known for its speed and security. It uses keys of 128, 192, or 256 bits.
  • DES (Data Encryption Standard) & 3DES: Older symmetric algorithms. DES uses a 56-bit key and is considered insecure today, while 3DES applies DES three times for improved security.
  • How It Works: A single key is used to both encrypt and decrypt the data. Both parties must securely share and keep this key confidential.

Asymmetric Encryption:

  • RSA (Rivest-Shamir-Adleman): A common asymmetric encryption method used for secure data transmission. It relies on the difficulty of factoring large numbers.
  • ECC (Elliptic Curve Cryptography): Provides similar security to RSA but with smaller keys, making it faster and more efficient.
  • How It Works: Two keys are used—one public and one private. Data encrypted with the public key can only be decrypted by the corresponding private key and vice versa.

 

Encryption Keys

Key Generation: Keys are generated using mathematical algorithms. For symmetric encryption, a random number generator is often used. For asymmetric encryption, key pairs are generated mathematically.

Key Management: Secure storage and exchange of keys are critical. Methods like Public Key Infrastructure (PKI) are used to manage keys in a structured manner.

Key Length: The security of an encryption key is determined by its length (measured in bits). Longer keys are harder to break. For example, a 2048-bit RSA key is more secure than a 1024-bit key.

 

Plain Text and Cipher Text

Plain Text:

  • Refers to readable data before encryption. Examples include emails, passwords, and financial information.

Cipher Text:

  • This is the scrambled, unreadable version of plain text after encryption. It appears as a random string of characters and can only be converted back to plain text with the appropriate key.

Solving Ciphers

Test your skills by decoding the messages using different ciphers. It’s a good way to practice and understand how ciphers work. Give it a try.

 

Look for Patterns: Pay attention to letter frequencies and patterns in the text. Common letters in English (like E, T, A, O) can give you clues.

Authentication and Authorisation

Authentication:

  • Process: Confirms the identity of a user or system. Common methods include:
    • Passwords/PINs: A secret known to the user.
    • Biometrics: Fingerprints, facial recognition, or retinal scans.
    • Tokens: One-time passwords (OTP) or security tokens.
    • Multi-Factor Authentication (MFA): Combines multiple methods, such as a password and a biometric scan, to enhance security.

Authorisation:

  • Process: Determines what resources or actions an authenticated user is allowed to access. Often implemented using Role-Based Access Control (RBAC) or Attribute-Based Access Control (ABAC).
  • Example: An authenticated user may have access to view documents but not to modify or delete them.

 

 

Hash Values

Hash Functions:

  • Purpose: Convert input data of any size into a fixed-size string. Common algorithms include SHA-256 and MD5.
  • Properties:
    • Deterministic: The same input will always produce the same hash.
    • Collision-Resistant: It’s computationally infeasible to find two different inputs that produce the same hash.
    • Non-Reversible: It’s practically impossible to reverse the hash to obtain the original input.

Use Cases:

  • Password Hashing: Instead of storing passwords, systems store hashed versions. During login, the user’s input is hashed and compared to the stored hash.
  • Data Integrity: Verifies that files or messages have not been altered. For example, software downloads often provide a hash value for the user to verify against the downloaded file.

 

Digital Signatures

Components:

  • Hashing: The document or message is first hashed.
  • Signing: The hash is then encrypted with the sender’s private key, creating the digital signature.

Process:

  1. The sender creates a hash of the message.
  2. The hash is encrypted with the sender’s private key, forming the digital signature.
  3. The signature is sent along with the original message.
  4. The recipient decrypts the signature using the sender’s public key to obtain the hash.
  5. The recipient generates a hash of the received message and compares it to the decrypted hash.
  6. If the hashes match, it confirms that the message is authentic and unaltered.

Applications:

  • Email Security: Confirms the sender’s identity and the integrity of the email content.
  • Software Distribution: Verifies that software has not been tampered with since it was signed by the developer.
