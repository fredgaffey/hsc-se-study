3.15 Closed Loop

Syllabus
Design, develop and implement programming code for a closed loop control system

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • design, develop, and implement programming code for a closed loop control system.

Success Criteria - Students can:

  • understand the basic principles of closed loop control systems and their applications.
  • identify the components required for a closed loop control system, including sensors, actuators, and controllers.
  • design a closed loop control system, including the selection of appropriate sensors and actuators.
  • develop programming code to control the system based on feedback from the sensors.
  • implement the programming code into a microcontroller or similar platform.
  • test the closed loop control system to ensure it responds correctly to varying inputs and maintains the desired output.
  • analyse the performance of the closed loop control system and make necessary adjustments to improve accuracy and stability.

  Content

Recall that a Closed Loop System is which uses feedback to constantly monitor their environment and modify their course. Revise this content here: 3.10 Open & Closed Control Systems.

 

Use your knowledge of algorithms and mechatronics in order to complete the problem below.

 

Closed Loop: VexCode VR

Open up VexCode VR, create a new text project and select the playground Dynamic Castle Crasher.

 

Challenges:

Level 1: Create an algorithm to knock over all five buildings in one Castle layout using the VR Robot.

Level 2: Improve your algorithm to knock over all buildings in three different Castle layouts.

Level 3: Improve your algorithm to knock over all buildings in five Castle Layouts in eight minutes or less.

 

Hints

  • Each time the Playground is reset, the layout of the buildings randomly change. There are ten total Castle Crasher Playground layouts.
  • Keep in mind that the algorithm should be written so that the VR Robot can knock over all five buildings regardless of the Playground layout.
  • Castle building pieces will be detected as objects by the Distance sensor.
  • Be careful not to fall off the side of the Playground because there are no walls!
  • Use the position of robot block from the Sensing category or the location values from the Playground Dashboard to detect the position of the VR Robot on the Playground. This can be used to ensure the VR Robot does not fall off of the Playground.

  • The Dynamic Castle Crasher Playground coordinates range from -1000mm to 1000mm for both the X and Y axes. For more information visit Coordinate System- Playground Features article. 
  • Use the color sensing block from the Sensing category to detect the hazard area (red stripe) around the Playground. The hazard area is detected as color "red" to the DownEye sensor.

  • Use the timer value block from the Sensing category to keep track of the time it takes to complete one or more Playground layouts.

Integrate Sensors: VexCode VR

Open up VexCode VR, create a new text project and select the playground Dynamic Wall Maze.

 

Challenges:  

Level 1: Create an algorithm in which the VR Robot solves one maze.  

Level 2: Create an algorithm that solves three mazes without any project modifications.

Level 3: Improve your algorithm to solve all nine mazes without any project modifications.  

 

Hints

  • The Dynamic Wall Maze will change each time it is refreshed. There are nine different mazes. 
  • Try to solve each maze in the most efficient path. You can use the Print blocks along with the Timer value block to display how long it takes to solve each maze.
  • The algorithm should be written so that the VR Robot can solve multiple Wall Mazes, regardless of their layouts. 
  • Use the DownEye sensor to report specific colors.  For example, use this to detect the start and finish of the maze. 

  •  The Pressing bumper sensor can be used to detect if the VR Robot bumper touches a wall. 

  • Nest an if then else statement inside a while   loop so the VR Robot sensors are continuously reporting information.

Control Algorithms: VexCode VR

Open up VexCode VR, create a new text project and select the playground Disk Transport.

 

Level 1: Using the electromagnet, pick up and place one disk of each color inside the correct colored goals located outside the Castle walls.

Level 2: Using the electromagnet, pick up and place all four disks of each color inside the correct colored goals located outside the Castle walls.

Level 3: Using the electromagnet, pick up and place three disks of each color inside each colored goal, then hide the remaining 3 disks behind the wall around the Castle!

 

Hints

  • The electromagnet can only pick up one disk at a time.
  • Each square in the Disk Transport measures 200mm by 200mm
  • The disks are placed in the center of each grid square, however the electromagnet is at the front of the robot. Adjust your drivetrain values appropriately!
  • Pick up and drop disks by passing in either BOOST or DROP into the magnet.energize() function.

 

Competition Challenges:

Level 1: How fast can you move the 4 disks to the matching goals? Use the timer to measure your speed. The fastest time wins! 

Level 2: Use the timer to see how fast you can move all of the disks into the matching goals. The fastest time wins! 

Level 3: See how fast you can move and hide the disks. The fastest time wins!

 

 

3.18 UI

Syllabus
Design, develop and implement a user interface (UI) to control a mechatronic system

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • be able to design, develop, and implement a user interface (UI) to control a mechatronic system.

Success Criteria - Students can:

  • design a user interface that is intuitive and user-friendly for controlling a mechatronic system.
  • develop the UI using appropriate software tools and programming languages.
  • implement the UI to effectively control various functions and components of the mechatronic system.

  Content

The integration of User Interface (UI) in robotics marks a significant advancement in the way humans interact with machines. A well-designed UI is pivotal in enhancing the functionality, efficiency, and safety of robots, making them more accessible and effective for a variety of applications. This essay delves into the myriad ways UI is utilised in robotics, highlighting its critical importance.

 

Control Interfaces

One of the fundamental applications of UI in robotics is in control interfaces. These interfaces allow users to directly manipulate and control robotic systems.

  • Manual control interfaces, such as joysticks and touch screens, enable operators to guide robots in performing precise tasks. For instance, in manufacturing, robots are often manually controlled to assemble intricate components.
  • Teleoperation interfaces extend this capability to remote locations. Such systems are indispensable in environments where direct human intervention is risky or impossible, such as space exploration, underwater missions, or disaster response scenarios.

 

Monitoring and Feedback

Effective monitoring and real-time feedback are crucial for the efficient operation of robots.

  • Dashboard displays are essential UI components that provide real-time data on robot status, performance metrics, and diagnostics. These dashboards enable operators to monitor multiple robots simultaneously, ensuring they operate within optimal parameters.
  • Visual feedback through integrated cameras and sensors further enhances situational awareness, allowing operators to make informed decisions based on real-time imagery and sensor data. This is particularly vital in precision tasks such as robotic surgery or detailed assembly processes.

User Experience (UX)

The success of robotic systems heavily relies on the user experience (UX) offered by their UIs.

  • Intuitive design is paramount, ensuring that interfaces are user-friendly and reduce the learning curve for new users. For instance, in healthcare, robots assist in patient care, and the UI must be straightforward enough for medical staff to use without extensive training.
  • Haptic feedback adds another layer of interaction, providing tactile sensations that enhance control, especially in teleoperation scenarios. This feedback can simulate the sense of touch, allowing operators to feel the environment the robot is interacting with, thus improving precision and control.

Safety and Compliance

Ensuring safety is a critical aspect of robotics, and UIs play a crucial role in this domain.

  • Emergency stop and safety protocols are integrated into UIs to provide quick and reliable methods to halt robot operations in case of emergencies. This is essential in environments where humans and robots work in close proximity, such as in collaborative robotics in manufacturing.
  • Compliance and monitoring interfaces ensure that robots operate within predefined safety parameters, adhering to industry standards and regulations. These interfaces help in monitoring robot behaviour and implementing corrective measures when deviations occur.

 

Case Study: NASA

In all systems that involve interactions between humans and machines, the element that defines the quality of that interaction is the human/machine interface, also known as the user interface. A graphical user interface (GUI) can make the human interaction more engaging and intuitive, constrain user inputs to valid ranges and units, supply tabular and plot-based output where needed, and provide users with data from sensors on the robots that are needed for control.

JPL Robotics has created a number of very successful user interfaces tailored to the robotic systems being controlled. These robots have ranged from multi-arm manipulators for microgravity deployment or terrestrial surgical applications, to legged prototype-rovers for rough terrains, to multi-wheeled rovers including flight systems such as the Mars Pathfinder Sojourner Rover, the Mars Exploration Rovers (MER), Spirit and Opportunity, the Phoenix Lander, the Mars Science Laboratory (MSL) rover Curiosity, and the current Mars 2020 (M2020) rover and Helicopter, Perseverance and Ingenuity.

 

Key Interfaces Developed at JPL:

  1. RSVP (Robot Sequencing and Visualisation Program)

    • Used for all surface operations in Mars missions since 1997.
    • Creates all command sequences for robotic operations sent to Mars rovers and landers.
    • Tools within RSVP:
      • RoSE (Rover Sequence Editor): Supports all commands in the mission-command dictionary and interfaces with simulation tools.
      • HyperDrive: Provides multiple 3D graphics interfaces to stereo images and 3D terrain-model data for planning rover motions.
      • ArmSketch: Visual sequencing tool for generating arm sequences with optimised path and collision avoidance.
      • MobSketch: Visual sequencing tool for generating drive sequences.
      • ROCS (Robotic Operations and Computational Services): Provides stateless, RESTful API for rover simulation, planning, and operations.

  2. SSim (Surface Simulation)

    • Flight-software-in-the-loop simulation software predicting rover command outcomes before uplink to Mars.
    • Supports quick iteration of command development by rover planners.
    • Takes inputs like rover command sequences, terrain models, and rover memory state to output motion history and command durations.
    • Used in both MSL and M2020 for sequence validation and verification.

  3. Honeycomb 3D Visualisation Platform

    • General, web-based 3D visualisation platform for understanding robotic systems from development to operations.
    • Used in Mars 2020 for visualising autonomy products from the enhanced driving navigation system.
    • Displays flight products during autonomous driving to help operators understand and debug the process.
    • Allows toggling of displays, timeline scrubbing, and interaction with 3D views to analyze rover decisions.
    • Planned for expansion to other missions.

 

Applications and Impact:

  • RSVP: Critical for planning and executing complex rover missions, enabling precise control and movement on Mars.
  • SSim: Enhances mission success by simulating and validating commands, ensuring accurate and reliable rover operations.
  • Honeycomb: Improves understanding of autonomous driving decisions, facilitating mission planning and execution.

3.19 Unit Tests

Syllabus
Create and use unit tests to determine the effectiveness and repeatability of each component’s control algorithm

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • be able to create and use unit tests to determine the effectiveness and repeatability of each component’s control algorithm in a mechatronic system.

Success Criteria - Students can:

  • write unit tests for control algorithms of various components within a mechatronic system.
  • use these unit tests to evaluate the effectiveness and accuracy of the control algorithms.
  • analyse the results of the unit tests to identify any inconsistencies or errors in the control algorithms.
  • demonstrate the ability to refine and improve control algorithms based on the outcomes of the unit tests.

  Content

In control systems, ensuring that individual components operate effectively and consistently is critical for overall system performance. Unit testing plays a key role in achieving this by isolating and evaluating each component's control algorithm. By systematically testing these algorithms, we can verify their accuracy, detect potential errors, and ensure they produce repeatable results under various conditions. This page explores the importance of unit tests, provides steps to create them, and highlights their role in improving the reliability and precision of control systems.

 

What are Unit Tests?

Unit tests are a type of software testing that focus on individual components or modules of a system to determine whether they function as expected. In the context of control algorithms:

  • A unit refers to a single component or section of the control system.
  • The goal is to verify that the control algorithm performs correctly under specific conditions.

Unit testing ensures:

  1. Effectiveness – The control algorithm works as designed and produces the expected outcome.
  2. Repeatability – The algorithm produces consistent results when tested repeatedly under the same conditions.

 

Why are Unit Tests Important?

Unit testing is critical for the development and maintenance of control algorithms because it:

  • Detects errors early, reducing the cost and time of fixing issues.
  • Ensures that individual components work as expected before integrating them into larger systems.
  • Provides confidence that changes to the system do not break existing functionality.
  • Validates the accuracy, consistency, and performance of control algorithms.

In control systems, where precision and reliability are essential, unit tests help confirm that a component can handle real-world inputs effectively.

 

Creating Unit Tests

 

Define Test Scenarios

  • Identify expected inputs and outputs for the component.
  • Consider edge cases (e.g., maximum or minimum values, unexpected inputs, or boundary conditions).

For example:

Test Input (Scenario) Expected Output
Component input = 0 Control output = 0
Component input = 100 Control output = expected max
Component input = invalid data Control output = error handled

Write the Unit Tests

Write code or instructions that:

  1. Input specific test values into the control algorithm.
  2. Check the actual output against the expected output.

Test Repeatability

  • Run each test multiple times to check for consistent results.
  • Record and compare outputs to ensure the algorithm behaves reliably.

Evaluate Test Results

  • Analyse discrepancies between expected and actual outputs.
  • Document and address any issues found.

 

Example: Unit Test for a Control Algorithm

Scenario: A temperature control algorithm adjusts the output power to maintain a desired temperature.

Test Input Expected Output Pass/Fail
Target Temp = 20°C Output = Stable at 20°C Pass
Target Temp = 100°C Output = Max Power Pass
Target Temp = -10°C Output = Min Power Pass
Sensor Error/Invalid Output = Error Handling Pass

 

Key Considerations for Effective Unit Testing

  • Test Coverage: Ensure you test a wide range of conditions, including normal, edge, and error cases.
  • Automation: Use tools or software frameworks to automate tests for efficiency.
  • Consistency: Repeated tests must produce consistent results for reliability.
  • Documentation: Clearly document your test scenarios, expected outcomes, and any issues encountered.
