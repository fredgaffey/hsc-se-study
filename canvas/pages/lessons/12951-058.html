2.16 Web Requests

Syllabus

Observe and describe the back-end process used to manage a web request, including:

  • role of webserver software
  • web framework
  • objects
  • libraries
  • databases

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • understand the back-end process of handling a web request and recognise how different components interact to manage user data and deliver a response.

Success Criteria - Students can:

  • describe how a web framework organises and routes requests.
  • identify the function of objects and how they relate to database tables.
  • explain how libraries provide additional functionalities to applications.
  • describe the relationship between the web framework and the database for handling data storage and retrieval.

  Content

 

Role of Webserver Software

The web server is the software responsible for accepting HTTP (or HTTPS) requests from clients (typically browsers) and delivering responses back to the client, which may include HTML pages, JSON data, images, or files.

 

Request Handling

  • Request Handling: The webserver receives the request from the client and determines whether it can serve the requested resource (like a static file) directly or if the request needs to be processed further.

Static Content Delivery

  • Static Content Delivery: If the request is for a static file, such as an HTML page, image, or CSS file, the webserver directly delivers that content to the client. Static files don’t require additional server-side processing.

Proxying to Application Server

  • Proxying to Application Server: For requests that require dynamic content generation, such as retrieving user data or processing form submissions, the webserver forwards the request to an application server. In this case, the webserver acts as a “reverse proxy,” forwarding the request to the web framework.

Popular Webservers

  • Apache: Apache is an open-source HTTP server that can handle both static and dynamic content. It uses modules to manage different types of content.
  • Nginx: Known for being lightweight and efficient at handling a large number of concurrent requests. It often acts as a reverse proxy for dynamic content.
  • IIS (Internet Information Services): A web server from Microsoft used for hosting websites and web applications on Windows servers.

 

Web Framework

A web framework provides the structure and reusable components that simplify the development of a web application. It takes care of the complex tasks involved in handling HTTP requests, URL routing, database access, and rendering views.

 

Flask provides a flexible framework to structure and manage web requests. Its simplicity makes it a great choice for small to medium-sized applications.

  • In Flask, routing is straightforward. Each route corresponds to a URL pattern that the application responds to. The @app.route() decorator is used to map a URL to a Python function (also known as a view function).
@app.route('/profile/<username>')
def profile(username):
    return f"User profile page of {username}"

 

  • Flask supports middleware that processes requests before and after they reach the route. Middleware can handle tasks such as authentication, request logging, or modifying the request data.
@app.before_request
def log_request():
    print(f"Request method: {request.method}, Request path: {request.path}")

 

Objects

In a back-end system, objects typically represent key entities or concepts in the domain of the application. They are instances of classes that structure and store data, often correlating with database tables (in relational databases) or collections (in NoSQL databases).

 

Object-Relational Mapping (ORM)

Object-Relational Mapping (ORM): Many web frameworks use an ORM to map these objects to database tables. This makes it easier to work with databases using an object-oriented programming paradigm rather than writing raw SQL queries.

  • Example: In Django, models are Python classes that represent database tables. For example, a User model might be written as:
class User(models.Model):
    username = models.CharField(max_length=100)
    email = models.EmailField(unique=True)

 

Data Manipulation

Objects allow developers to interact with data as if they were working with in-memory objects in code, even though the data might actually be stored in a database.

user = User.objects.get(id=1)  # Retrieves a user from the database
user.username = "NewName"  # Updates the username
user.save()  # Commits the changes to the database

 

 

Libraries

Libraries are reusable sets of functions and tools that provide additional functionality and speed up development by abstracting common tasks. These are often external packages installed via a package manager (e.g., pip for Python or npm for Node.js).

 

Types of Libraries

  • Utility Libraries: Provide helper functions for common tasks, like manipulating strings, formatting dates, or handling arrays.
  • Database Libraries: Provide functions to interact with databases, sometimes extending the ORM.
  • Authentication and Authorisation: Libraries like OAuth or JWT (JSON Web Tokens) are used to handle secure authentication flows.
  • Form Processing Libraries: Handle user input validation and sanitation

Integration Libraries

For integrating with third-party services, such as payment gateways (Stripe, PayPal), email services (SendGrid), or cloud storage (AWS S3).

  • Example: A payment library might provide methods to interact with Stripe’s API, making it easier to charge a customer or process refunds without manually building API calls.
stripe.Charge.create(
  amount=2000,
  currency="usd",
  source="tok_mastercard",
  description="Charge for user@example.com"
)

 

 

Databases

Databases are essential for storing, managing, and retrieving the data that the web application needs. Based on the type of data and application requirements, different databases are used.

 

Relational Databases (SQL)

These are structured databases where data is stored in tables with rows and columns. SQL databases are highly structured and enforce relationships between tables using foreign keys.

  • Examples: MySQL, PostgreSQL, SQLite.
  • Use Cases: When the data is structured and relationships between entities are important, such as for e-commerce platforms, user management systems, etc.
  • Example SQL query:
SELECT * FROM users WHERE email = 'user@example.com';

 

Non-Relational Databases (NoSQL)

These are databases designed for unstructured or semi-structured data. They are more flexible and allow for storing data in formats like JSON or key-value pairs.

  • Examples: MongoDB, Cassandra, Redis.
  • Use Cases: When you need to store large amounts of unstructured data or when schema flexibility is important, such as for real-time applications, content management systems, or logging systems.
  • Example NoSQL query (MongoDB):
db.users.find({ email: 'user@example.com' });

 

Interactions Between Framework and Database

  • Database Queries: During a request, the web framework may interact with the database to retrieve or update data.
  • Connection Management: Web frameworks manage database connections through connection pools, allowing efficient and concurrent access to the database.
  • Query Optimisation: The framework often provides built-in query optimisation, caching, and indexing options to improve performance.
