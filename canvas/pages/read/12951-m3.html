Developing Secure Code: Advanced Implementation

In this cycle, we transition from the conceptual foundations of security to the practical implementation of secure code. We will examine the intricate details of application vulnerabilities and how to construct robust defences against sophisticated attacks.

This cycle focuses on the following crucial areas of software engineering:

  • Designing, developing, and implementing safe Application Programming Interfaces (APIs).
  • Optimising code for efficient execution through proper memory, session, and exception management.
  • Identifying and mitigating critical vulnerabilities in user action controls, including XSS, CSRF, and race conditions.
  • Protecting systems against file-based attacks and hardware vulnerabilities like side-channel attacks.

1.11 APIs

Syllabus
Design, develop and implement a safe application programming interface (API) to minimise software vulnerabilities.

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the concept of safe API design and the importance of reducing software vulnerabilities.

Success Criteria - Students can:

  • Identify common security vulnerabilities in APIs.
  • Implement techniques to secure an API in Python.
  • Develop a safe API that handles requests and responses securely.

  Content

 

What is an API?

An application programming interface (API) is the intermediary that allows two software applications to interact with each other. An API specifies how two machines—usually a client/user and a server—should interact. These include a set of rules, protocols and definitions that determine how API requests/responses should be formatted.

APIs are generally designed using a client-server model through API requests and responses between the client and a server. The client submits an API request, and the server responds to that specific request. 




In an API, the "interface" is generally not directly visible and abstracted away from the end-user side. Instead, the API includes endpoints and specific URLs that clients can request. For example, an endpoint might be /api/v1/users to retrieve a list of users.

REST APIs

REST APIs (Representational State Transfer APIs) are client-server APIs that transfer state resources from the server to the client user. State transfer means that when the client user interacts with a server, transferred data represents the current state of that specific resource. Hence, it allows the client to "know" and "work with" the resource's current state without maintaining a continuous connection with the server.

The practical implementation of REST APIs uses web-based protocols like HTTP/HTTPS (i.e. the framework you use in your Python Flask server)

For example, if a client-user wishes to access weather data from the server, the data transferred from the API would be the current state of the current available forecast.

Dynamic API Calls

The next topic, Programming for the Web, delves deeper into web pages. Before that, we’ll conceptually explore secure software APIs, focusing on how API calls are made between the server and the client browser to update the web page. 

A web page updates content dynamically through API requests to the server backend or database. You would typically make API calls using the request function in the Flask library in Python. However, web browsers (Google Chrome, Safari, Firefox, etc) can only execute JavaScript (JS) - a high-level scripting language. Hence, your browser can execute JavaScript (similar to python3 server.py) while you are on your browser. 

You are not expected to write JavaScript in the HSC. However, you are expected to interpret JavaScript code.

Secure APIs Structure

There are various APIs, but the most widely recognised—and the one we will focus on—is HTTP, the application protocol commonly used in web development. There are two primary ways of sending data via an API: through the body or the header: 

  • Header: Contains metadata about the request, such as authentication tokens, cookies, and content types. This information helps the server understand how to process the request.
  • Body: Carries the main data payload, such as form inputs, JSON objects, or file uploads, that the client wants to send to the server for processing. 

In deployment, your application protocol should be HTTPS over HTTP as it enables encryption of API data.

Techniques for Securing APIs

Authentication and Authorisation

Authentication and Authorisation

To protect an API, it is essential to ensure that only authorized users can access specific endpoints. Authentication verifies the identity of a user, while authorization controls what the user is allowed to do.

Common techniques include:

  • API Keys: Simple, unique identifiers sent with each request to verify the client.
  • OAuth2: A more secure and flexible token-based authorization mechanism.


Example of Authorization in Python (using Flask)

 

Input Validation and Sanitation

Input Validation and Sanitation

Input validation is crucial to prevent malicious inputs from entering the API. It ensures that data received by the API conforms to expected types, formats, and values.  

Input Validation: Checks that the input is in the correct format
(e.g., checking that an email is valid).

 


Input Sanitation: Removes or escapes potentially harmful characters from user input
to prevent attacks like SQL injection or command injection.

 

Rate Limiting

Rate Limiting

Rate limiting restricts how often users can make requests to your API, helping to mitigate abuse and prevent Denial of Service (DoS) attacks. It is a good practice to set thresholds for how many requests a client can make within a certain time frame.

Example in Python (using Flask-Limiter)

Secure Data Transmission (HTTPS)

Secure Data Transmission (HTTPS)

To protect sensitive data during transmission, always use HTTPS rather than HTTP. HTTPS encrypts data to prevent man-in-the-middle (MITM) attacks, ensuring that data remains confidential and secure as it moves between client and server.

 

Flask app with HTTPS ('adhoc' used for development purposes)

Error Handling in Secure APIs

Error Handling in Secure APIs

A secure API should handle errors gracefully without exposing sensitive information about the system. Error messages should be informative enough to guide the user but not detailed enough to reveal potential vulnerabilities.

For example, avoid returning stack traces or internal server errors directly to users. Instead, return general error messages with appropriate HTTP status codes.

  Content

 

Designing and implementing efficient code is essential for performance and user experience, resource conservation, and ensuring your application can scale. Whether you’re writing a small script or a large web app, keeping memory use in check, managing user sessions well, and handling errors effectively is crucial.

Memory Management

Efficient memory management ensures that system resources are optimally utilised, preventing memory overconsumption and potential system crashes. In Python, memory is managed automatically, but developers must be mindful of practices that can improve efficiency, particularly when working with large data sets.

 

Best Practices for Managing Memory

  • Avoid Unnecessary Object Creation: Reusing objects where possible minimises allocation.
  • Use Generators for Large Data Sets: Generators process items one at a time rather than loading entire data sets into memory, making them ideal for handling large data collections.

 

We can use the yield generator keyword in Python to yield one item at a time. This is unlike the return keyword, which would be used to return all items at once.

 Think of a return like a delivery person bringing you every item you ordered in one massive delivery. You need to make space for it all right away. But with this, it’s more like the delivery person bringing you one item at a time, only when you need it. No need for extra storage space!

 

Example of the use of a generator for the same memory
(yield "pauses" the function processing each item one by one)

 

Session Management

Session management is essential in web applications to maintain user state across multiple requests. Efficient session management ensures that resources are not overused and that user data is handled securely.

 

Techniques for Efficient Session Management:

  • Use Session Expiry: Implementing session timeouts reduces memory consumption by closing inactive sessions.
  • Store Minimal Data: Only essential information should be stored in sessions to minimise the head.

Expectation Management

Proper exception management ensures that an application can gracefully handle errors without crashing or exposing sensitive information to users. Effective error handling also contributes to the application's overall reliability.

 

Best Practices for Exception Handling:

  • Catch Specific Exceptions: Avoid catching broad exceptions. Instead, handle only those exceptions that are expected.
  • Log Errors for Debugging: Logging captures detailed error information, which can help in debugging and improving the system without revealing sensitive system details to the user.

Further Examples

Memory Management Techniques

Efficient memory management is critical for writing scalable and high-performance applications. In Python, memory is automatically managed through garbage collection, but developers can still optimise code to reduce memory usage. Strategies such as using generators, which yield items one by one instead of holding entire datasets in memory, help to minimise memory consumption.

Profiling tools allow developers to track memory usage during execution, helping them identify and eliminate memory bottlenecks. Understanding memory management ensures that applications perform smoothly, even when handling large amounts of data or running in resource-constrained environments.

 

Session Expiry and Security

Effective session management is essential for maintaining user state and ensuring security in web applications. Session expiration policies prevent inactive sessions from consuming server resources indefinitely while enhancing security by logging inactive users out after a specified period.

Storing minimal data in sessions reduces the risk of exposing sensitive information and keeps resource usage low. Additionally, securing sessions through encryption of session cookies and implementing HTTPS for communication prevents session hijacking and other attacks. Proper session management balances security, performance, and resource efficiency.

Error Logging and Debugging

A cornerstone of robust application design is handling errors in a way that provides useful feedback to developers without exposing sensitive system information to users. Exception management ensures that when an error occurs, it is gracefully handled without crashing the application or causing a poor user experience.

Logging errors in detail allows developers to trace and fix issues while debugging tools help identify problems at runtime. Effective error management improves software reliability and maintainability, ensuring issues can be addressed quickly without impacting user satisfaction or system security.

1.13 Minimise Vulnerabilities

Syllabus
Design, develop and implement secure code to minimise vulnerabilities in user action controls, including:
• broken authentication and session management
• cross-site scripting (XSS) and cross-site request forgery (CSRF)
• invalid forwarding and redirecting
• race conditions

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand common vulnerabilities related to user action controls in software applications.
  • Implement secure coding practices to minimize the risks of attacks that exploit these vulnerabilities.

Success Criteria - Students can:

  • Students can identify vulnerabilities such as broken authentication, XSS, CSRF, and race conditions.
  • Students are able to write secure code to mitigate these vulnerabilities.

  Content

 

In modern software development, applications are frequently exposed to numerous threats, particularly in handling user interactions. Vulnerabilities in user action controls, such as broken authentication, cross-site scripting (XSS), and race conditions, can leave applications susceptible to attacks that compromise data integrity, security, and user privacy.

 

Broken Authentication

Broken authentication and session management could allow attackers to bypass authentication mechanisms, hijack user sessions to impersonate users and gain unauthorised access to server resources. 

Broken authentication occurs when authentication mechanisms are not implemented securely. 

  • Weak passwords: Lack of input validation where client users are allowed to set short, easily guessable passwords.
  • Password storage: Passwords are stored as plaintext in the database. If the database is stolen, users' passwords are exposed. 
  • Password reuse: Allowing users to reuse old passwords weakens security over time.

 

Mitigation Strategies:

  • Enforce strong password policies: Require complex passwords and encourage multi-factor authentication (MFA) for critical operations. Regex expressions and validation for expected passwords. 
  • Communication channels: Ensure that all authentication-related requests use HTTPS to encrypt data transmitted between the client and the server.
  • Account lockout mechanisms: Implement a mechanism that temporarily locks the account after multiple failed login attempts to prevent brute force attacks.

Broken Session Management

Session management controls how sessions are created, maintained, and destroyed. Insecure session management can lead to session hijacking and fixation attacks.

  • Session Hijacking: Attackers can steal active session tokens and impersonate users.
  • Session Fixation: Attackers provide a session ID to a victim before logging in and then hijack their session using the same ID.


Mitigation Strategies:

  • Random Generated Tokens:  Each user session is associated with a unique session token.
  • Hashed Storage: Session tokens are cryptographically hashed to ensure attackers cannot deduce the token generation algorithm.
  • Session Expiration: Implement session timeouts and expiration of tokens 

XSS

Cross-Site Scripting (XSS) is a client-side vulnerability where an attacker injects malicious JavaScript into a website's backend storage or directly into its content. When this malicious script is executed in the victim's browser, the attacker can gain unauthorised access to sensitive information or perform actions as the victim. 

Mitigation Strategies:

    •    Input validation and sanitization: Always validate and sanitize user inputs before processing them. Ensure that special characters like <, >, and " are properly escaped.
    •    Output encoding: Encode any user-generated data before displaying it on a webpage. Use functions that escape HTML, JavaScript, and CSS elements in the output.
    •    Content Security Policy (CSP): Implement a strict Content Security Policy to restrict the execution of inline scripts and reduce the risk of script-based attacks.

CSRF

Cross-site request forgery occurs when an attacker tricks a user into performing unwanted actions where they are already authenticated. An attacker forges a request by exploiting the fact that the user is already authenticated, with session tokens stored in the browser.

If the attacker can trick the user into interacting with a malicious website (hence, "cross-site"), the browser automatically includes the stored session tokens when making the request. The server cannot distinguish between a legitimate user-initiated request and the forged one (as the session token is passed in), and assumes the authenticated user initiated it and grants authorisation.  

Mitigation Strategies:

CSRF Cheat Sheat

  • CSRF Token: Create CSRF tokens to verify where a request is coming from. Each CSRF token is linked to a specific user session, making it unique for every user. Allow access to server resources only if both the CSRF token and session token match the user's session.
  • Brower Storage: Configure HTTP-only cookies with the SameSite attribute to ensure cookies are only sent with requests from the same front-end URL, preventing them from being shared with other sites.

IMPORTANT: Cross-Site Scripting (XSS) can defeat most CSRF mitigation techniques! 
If a <script> tag executes a API request within it, even with HTTP-only cookies, all credentials can be sent with the cookies, making them vulnerable.

Invalid Forwarding and Redirecting

Invalid forwarding and redirecting occur when attackers manipulate URL parameters to redirect users to unintended locations or bypass authentication and authorization checks. 

Risks:

    •    Open Redirect Vulnerabilities: Attackers can manipulate redirect parameters to send users to malicious websites, leading to phishing attacks or malware distribution.
    •    Unintended Access to Restricted Pages: An attacker could exploit forwarding mechanisms to bypass access controls and access sensitive pages without proper authorization.

Mitigation Strategies:

    •    Whitelist redirect destinations: Instead of allowing freeform redirects, restrict redirects to a predefined list of trusted URLs.
    •    Implement proper access controls: Ensure that redirects and forwards check the user’s authentication status and permissions before granting access to the destination.
    •    Parameter validation: Validate and sanitize any user-controlled input, such as URLs and parameters, before redirecting users.

 

Race Conditions

Race conditions occur when multiple processes or threads access and manipulate shared resources in an unsynchronised manner, leading to data corruption or unintended behaviour. These vulnerabilities are particularly prevalent in multi-threaded applications or systems that handle concurrent requests.

By default, Flask servers run synchronously (each request is processed sequentially). However, there are ways to run the server asynchronously, such as via an ASGI server like Hypercorn or Uvicorn. 

You are not expected to have a Flask server run asynchronously, but your code should be designed to easily adapt to an asynchronous platform using existing async and await features.

 

Risks:

    •    Data Integrity Issues: When multiple users or processes attempt to modify the same data simultaneously, it can lead to inconsistent or incorrect data being saved or processed.
    •    Exploitation of Time Gaps: Attackers can exploit the time gap between checking a condition and performing an operation. For example, in a banking application, an attacker might be able to transfer money multiple times by exploiting race conditions between balance checks and transaction approvals.

Example of a simple race condition where the order of threads changes the result

Mitigation Strategies:

    •    Locking mechanisms: Use locking mechanisms (e.g., mutexes or semaphores) to ensure that only one process can access a critical section of code or resource at a time.
    •    Atomic operations: Where possible, use atomic operations to ensure that critical tasks are completed in one step, avoiding interruptions by other processes.
    •    Queue management: Implement queue systems that control the order of operations and prevent concurrent access to sensitive data or resources.

 

Why User Action Control Security is Critical

Ensuring security in user action controls is a vital aspect of secure software development. These vulnerabilities directly impact the user experience and can lead to severe breaches, including unauthorised access, data theft, or manipulation of system processes. Understanding these threats and implementing strong defences helps to build trust between users and the application, while also safeguarding sensitive information.

 

GuidedCTF

Explore a hands-on exercise in SQL injection vulnerability exploitation by following this link.

 

Emerging Threats and Solutions

With the rise of more sophisticated attack techniques, traditional defences against vulnerabilities like XSS and CSRF are no longer sufficient. Emerging solutions include:

    •    Web Application Firewalls (WAFs): Automatically filter and monitor HTTP requests to block attacks such as XSS, SQL Injection, and CSRF before they reach the application.
    •    Zero Trust Architecture: Every user action must be verified and authenticated, regardless of their previous authentication state, ensuring that every interaction is treated as potentially harmful unless proven otherwise.

 

Practical Implementation Tips

To ensure a secure development lifecycle:

    •    Security Audits and Code Reviews: Regularly perform audits and peer code reviews with a focus on identifying potential vulnerabilities in user action controls.
    •    Integrating Security Tools: Leverage tools such as static analysis scanners and automated vulnerability testing platforms (e.g., OWASP ZAP) in your CI/CD pipeline.
    •    Security Training: Developers should receive regular training on secure coding practices to stay current with the latest vulnerabilities and mitigation techniques.

1.14 File Security

Syllabus
Design, develop and implement secure code to protect user file and hardware vulnerabilities from file attacks and side channel attacks

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Students will learn how to design, develop, and implement secure Python code to protect user files and hardware from file attacks and side-channel attacks.

Success Criteria - Students can:

  • design secure code that addresses file and hardware vulnerabilities.
  • develop Python code that protects user files from file attacks.
  • implement techniques to defend against side-channel attacks.
  • understand how to prevent unauthorised access to sensitive user data.
  • apply security best practices to safeguard against file and hardware-based threats.

  Content

Designing secure software is critical in preventing unauthorised access to user data and protecting system hardware from malicious exploitation.

    •    File Attacks: How to prevent vulnerabilities related to file access and manipulation.
    •    Side-Channel Attacks: How to mitigate hardware vulnerabilities that leak sensitive information indirectly.

 

 What Are File Attacks?

File attacks exploit weaknesses in how a program accesses or handles files. Attackers often use methods like file inclusion, directory traversal, and buffer overflow to gain unauthorised access, alter, or corrupt files.

Examples of File Attacks:

  • Path Traversal Attack: Manipulating file paths to access directories outside the intended location (e.g., ../../../etc/passwd).
  • Insecure File Upload: When a web application improperly handles file uploads, allowing attackers to upload malicious files (e.g., .php files).
  • Buffer Overflow: Writing more data into a buffer than it can hold, causing memory corruption, which may lead to arbitrary code execution.

Visualisation of a software buffer overflow.
Data is written into A, but is too large to fit within A, so it overflows into B.

 

What Are Side-Channel Attacks?

Side-channel attacks exploit indirect information leakage such as timing, electromagnetic emissions, or power consumption to infer sensitive data.

Examples of Side-Channel Attacks:

  • Timing Attacks: By measuring the time it takes to process different inputs, an attacker can deduce private data (e.g., cryptographic keys).
  • Power Analysis: Observing power consumption during cryptographic operations to derive keys.
  • Electromagnetic Emanation: Analysing electromagnetic emissions to recover sensitive information processed by hardware.

 

The Role of Secure Code

Secure coding involves writing software that minimises the risk of exploitation. It ensures that both user files and hardware components are safeguarded from malicious actors.

Core Security Objectives: Ensure Confidentiality (keeping data private), Integrity (data can’t be altered maliciously), and Availability (systems remain operational and accessible).

 

Secure Code Design Principles

Principle of Least Privilege (POLP)

  • Each process, user, or system component should operate with the minimum level of access necessary to perform its function. This limits the damage that could be done if a vulnerability is exploited.
  • Example: A file handler should only have permission to access files it is required to process, rather than full directory access.

 

Input Validation

  • One of the most critical steps to secure file handling. All inputs from users should be treated as untrusted and validated/sanitized before further processing.
  • Example: Reject file names with unexpected characters (e.g., ../ to prevent path traversal attacks).

Fail-Safe Defaults

  • When a program fails, it should do so in a way that maintains system security. Deny access by default unless explicitly allowed.
  • Example: If a file access check fails, default to denying the operation rather than allowing access.

Preventing File Attacks

File Permissions and Access Control

  • Assign appropriate file permissions (read, write, execute) to limit unauthorised access. Set files to read-only where necessary.
  • Example: Avoid running web applications with elevated permissions like root/admin.

File Path Sanitisation

  • Validate and normalise file paths to avoid directory traversal vulnerabilities.
  • Example: Instead of allowing users to provide relative file paths, resolve all paths to absolute ones and check if they are within the allowed directory structure.

Secure File I/O Operations

  • Ensure that file operations (e.g., opening, reading, writing files) are done securely.
  • Techniques:
    • Use secure libraries for handling file I/O.
    • Ensure file locks to avoid race conditions where two processes might access the same file simultaneously.
    • Restrict file uploads to specific directories and file types.

File Encryption

  • Encrypt sensitive files at rest using modern encryption standards (e.g., AES-256) to protect against unauthorised access if a file system is compromised.

Mitigating Side-Channel Attacks

Constant-Time Algorithms

  • Many cryptographic algorithms and operations vary their execution time depending on input, allowing attackers to infer sensitive information. Using constant-time algorithms prevents timing discrepancies.
  • Example: Implement constant-time comparison for password validation to avoid timing attacks.

Blinding and Masking

  • Mask sensitive data during computations to prevent attackers from correlating external observations (such as power consumption or timing) with the actual data.
  • Example: Apply blinding techniques during cryptographic operations, where the input is randomised before being processed and then corrected afterward.

Reducing Information Leakage

  • Limit external signals like power usage or electromagnetic emissions from hardware that could be analysed by attackers.
  • Example: Use shielding to prevent electromagnetic emissions from leaking sensitive information processed by hardware.

Defensive Coding Techniques

  • Be mindful of operations that may unintentionally reveal sensitive data.
  • Example: Insert artificial delays or noise into program execution to obscure timing information.

Secure Code Development Best Practises

Regular Code Review and Testing

  • Always conduct manual code reviews with a focus on security. During code reviews, look for:
    • Improper input validation.
    • Unsafe file handling or insecure defaults.
    • Hard coded credentials or secrets.
  • Ensure that reviewers pay special attention to critical security areas like user authentication, file access, and data encryption.
  • Create automated test cases to ensure your application behaves securely under various conditions, including edge cases and malicious inputs.
  • Ensure that test cases check for:
    • Injection vulnerabilities (e.g., SQL, command injection).
    • Unexpected file or input handling behaviours.
    • Secure handling of sensitive data like passwords.

Dependency Management

  • Regularly update your dependencies to ensure you’re using the latest versions that contain security patches.
  • Before updating, review change logs and test your application to confirm the updates don’t introduce breaking changes.

Checking outdated dependencies with pip list --outdated

Memory Management

  • Properly handle memory allocation and de-allocation to prevent buffer overflows and memory leaks.
  • Avoid Exposing Sensitive Data:
    • Do not store sensitive information, like passwords or private keys, in memory longer than necessary.
    • Be cautious about logging or printing sensitive information, even during development.
  • Techniques:
    • Use safer functions like strncpy instead of strcpy when programming in C.
    • Perform boundary checks to avoid writing outside of allocated buffers.

Logging and Monitoring

  • Log suspicious file access or unusual program behaviour, but avoid logging sensitive information like user passwords or encryption keys.
  • Example: Use monitoring tools to detect unusual file access patterns, like a large number of read/write operations on sensitive files.
