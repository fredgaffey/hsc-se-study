Success Criteria - Students can:

  • identify and explain the importance of using suitable test data in software testing.

  • identify and select faulty and abnormal data to test the code's robustness.
  • create test data sets that cover boundary values, path coverage, and faulty and abnormal data.

  Content

Testing is a critical phase in the software development lifecycle, aimed at identifying and fixing bugs before the software is deployed. The selection of appropriate test data plays a pivotal role in the testing process, as it directly influences the test's effectiveness in uncovering defects. Test data can be categorized into boundary values, path coverage data, and faulty or abnormal data, each targeting different aspects of software behavior.

 

Boundary Values

Boundary Value Analysis is a testing technique that focuses on the values at the edge of input domains. It is based on the principle that errors are more likely to occur at the boundaries of input value ranges.

Key Concepts:

  • Boundary Values: Include the minimum and maximum values, just inside/outside boundaries, and typical values just beyond the extremes.
  • Advantages: Highly effective in finding errors in input validation and data processing.
  • Techniques:
    • Identify the input ranges for all input variables.
    • Determine the boundary values for each range.
    • Create test cases for these boundary values.

Example: If an input field accepts numbers from 1 to 100, the boundary values would be 0, 1, 2, 99, 100, and 101.

Python Example:

Consider a function that verifies if an age is within the legal driving age (18-65 inclusive) in a certain jurisdiction.


Path Coverage

Path coverage testing ensures that all possible paths through a given part of the code are executed at least once. This approach helps in identifying untested parts of a codebase.

Key Concepts:

  • Path Coverage: Involves creating test cases to cover every possible path through the software, including loops and conditional branches.
  • Advantages: Ensures a comprehensive testing of the logic and decision-making processes within the code.
  • Techniques:
    • Develop test cases that will navigate each path.
    • Consider loops and their iterations for comprehensive coverage.

Example: For a simple conditional statement, paths would include both the true and false branches of the condition.

Python Example:

Consider a simple function that categorizes an input number into positive, negative, or zero.

 

Faulty and Abnormal Data

 

Testing with faulty and abnormal data involves intentionally providing incorrect, invalid, or unexpected data to the system to observe how it behaves, ensuring that it can handle such situations gracefully.

Key Concepts:

  • Faulty Data: Data that is incorrect or malformed.
  • Abnormal Data: Data that is unusual or unexpected, but not necessarily incorrect.
  • Advantages: Helps in testing the robustness and error handling capabilities of the software.
  • Techniques:
    • Identify data types and inputs that are prone to errors.
    • Create test cases with invalid formats, extreme values, and unexpected input combinations.
    • Evaluate the system's response to ensure it fails safely without causing harm or data corruption.

Example: Entering a string of characters where a numerical input is expected, or submitting a file with an unsupported format.

Python Example:

A function expects a numerical grade between 0 and 100 but receives various types of abnormal data.
