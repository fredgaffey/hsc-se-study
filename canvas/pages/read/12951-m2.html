  • Utilising vital developer strategies and tools, including SAST, DAST, code reviews, and penetration testing.
  • Designing defensive code with robust data input handling, validation, and sanitisation to prevent malicious exploits like SQL injection.

  Content

 

Using Cryptography and Sandboxing in 'Security by Design'

The 'security by design' approach involves integrating security measures into the software development process rather than adding them as an afterthought. Cryptography and sandboxing are two critical components of this approach, which significantly protect software from various threats.

 

Cryptography

   Definition

Cryptography is securing information by transforming it into an unreadable format, which can only be deciphered by those with the correct key. This technique is essential for protecting sensitive data and ensuring its confidentiality, integrity, and authenticity.

Contribution to 'Security by Design':

  • Confidentiality: Cryptography ensures that sensitive information remains private by encrypting data to only be accessible to authorised users. This is crucial in preventing data breaches and unauthorised access.
  • Integrity: Cryptographic techniques such as hashing verify that data has not been altered during transmission or storage, thus maintaining its integrity.
  • Authentication: Cryptography is used in authentication processes to verify the identities of users and devices, ensuring that only authorised parties can access the system.
  • Non-repudiation: Digital signatures, a form of cryptographic evidence, provide proof of the origin and integrity of data, preventing parties from denying their actions.

Example

  • Encryption: In this Flask application, cryptography encrypts data before storing or transmitting it. The data is converted into an unreadable format using a key required for decryption.
  • Decryption: When the data needs to be accessed, it is decrypted using the same key, converting it back into its original readable format. This ensures that sensitive information remains secure throughout its lifecycle.

Sandboxing

   Definition

Sandboxing is a security mechanism that isolates running programs or processes, limiting their access to the system and preventing them from making permanent changes. This technique executes untrusted code safely without risking the entire system's security.

 

Contribution to 'Security by Design':

  • Isolation: By isolating applications or processes in a sandbox, developers can prevent potential threats from spreading to the rest of the system. This containment reduces the risk of malware infections and system breaches.
  • Testing: Sandboxing allows developers to test new or untrusted code in a controlled environment. Any malicious behaviour or unexpected outcomes are contained within the sandbox, protecting the main system.
  • Mitigating Risks: Even if an application or process within a sandbox is compromised, the impact is limited to the sandboxed environment, thereby reducing the overall security risk.

Example

In software development, sandboxing is often used during testing to run potentially harmful code or untrusted applications without affecting the production environment. It ensures that the damage is contained even if the code has vulnerabilities.

  • Sandboxing Execution: In this example, the Flask application accepts code from the user and runs it in a sandboxed environment using the subprocess module. The code is executed with restricted permissions and a timeout, ensuring it does not affect the main system.
  • Controlled Environment: If the code contains harmful instructions or behaves unexpectedly, the damage is contained within the sandbox. This approach allows developers to test untrusted code securely without compromising the overall system's security.

1.7 Privacy by Design

Syllabus
Use and explain the 'privacy by design' approach in the development of software solutions, including: 
- proactive not reactive approach
- embed privacy into design
- respect for user privacy

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the core principles of software development's‘ privacy by design' approach.
  • Learn how to implement privacy-first practices throughout the software development lifecycle.

Success Criteria - Students can:

  • Students will be able to explain the key principles of 'privacy by design'.
  • Students will be able to integrate privacy-focused features into software solutions.
  • Students will respect user privacy by embedding it directly into the software design.

  Content

 The 'privacy by design' approach means that privacy considerations are incorporated from the beginning of the software development process. It's not an afterthought but rather a proactive and essential part of the design process to safeguard user privacy throughout the software's lifecycle.

The three main principles of privacy by design are:

  • Proactive, not reactive approach
  • Embed privacy into design
  • Respect for user privacy

Each plays a crucial role in protecting users' personal information and complying with privacy regulations.

Proactive not reactive approach

   Definition

A proactive approach ensures that potential privacy issues are addressed before they occur. Instead of reacting to privacy breaches after they happen, developers anticipate and mitigate risks early in the design process.

 

Privacy by design is not reactive to privacy risks that materialise or occur. Instead, it is proactive by aiming to prevent any privacy threats from occurring. In the initial stages of the software development cycle, privacy impact assessments (PIAs) are conducted to identify and evaluate potential risks.



Developers will ensure the software design addresses these privacy issues proactively - where privacy protections are embedded into the software architecture and design before deployment.

How It Works:

  • Risk Assessment:
    Conduct privacy risk assessments during the planning and design stages to identify potential vulnerabilities and mitigate them before deployment.

  • Prevention Over Detection:
    Build privacy features that prevent issues rather than relying solely on detection mechanisms. This means implementing measures like anonymising data, minimising data collection, and encrypting sensitive information.

Example in Software Development:

A proactive approach would involve setting up privacy controls like consent mechanisms and data anonymisation during the project's initial stages and ensuring that these are embedded before the software is even deployed.

Embed privacy into design

   Definition

Embedding privacy into the design means that privacy measures are integrated directly into thesoftware'ss architecture, ensuring privacy is considered at every step of the development process. Privacy considerations should be incorporated into the core design and the software architecture. Privacy by design should include systematic embedding of privacy, data minimisation and encryption techniques to protect user privacy. 

How It Works:

  • Privacy as a Default:
    Systems should be designed with privacy features enabled by default. Users should not have to take extra steps to protect their privacy—it should be built into the system.

  • Minimal Data Collection:
    Limit the amount of personal data collected to the minimum required for the software to function, reducing the risk of data exposure.

Example in Software Development:

During the design phase, developers should ensure that all features respect user privacy by limiting data collection and securing stored data.



 

Respect for user privacy

   Definition

Respecting user privacy means giving users control over their data and ensuring transparency in handling their data. Users should be informed about what data is being collected and how it will be used, and they should be given options to manage or delete their information.

 

Respect for User Privacy aims to prioritise the interests and needs of individual users as the centre of Privacy by Design and is user-centric. The goal is to ensure that users have an active role in managing their data. 

This includes providing unambiguous consent to the use of private data. User Privacy should also be respected by limiting user data sharing with external third parties, ensuring confidentiality. 

How It Works:

  • User Control:
    Provide users with options to edit, delete, or export their information to manage their data. This shows respect for their ownership of the data.

  • Transparency:
    Clearly communicate with users about how their data is being used. Implement privacy policies that explain data practices in simple, understandable language.

Example in Software Development:

Incorporating user controls and transparency into the application's interface allows users to manage their personal information easily.

1.8 Test Security & Resilience

Syllabus
Test and evaluate the security and resilience of software by determining vulnerabilities, hardening systems, handling breaches, maintaining business continuity and conducting disaster recovery

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the core principles of software development's ‘privacy by design’ approach.
  • Learn how to implement privacy-first practices throughout the software development lifecycle.

Success Criteria - Students can:

  • Students will be able to explain the key principles of ‘privacy by design’.
  • Students will be able to integrate privacy-focused features into software solutions.
  • Students will respect user privacy by embedding it directly into the software design.

  Content

Testing and evaluating software security and resilience ensures systems remain robust against attacks, can handle security breaches effectively, and recover quickly to maintain business continuity. This process involves determining vulnerabilities, hardening systems, handling breaches, and implementing disaster recovery plans.

 

Determining Vulnerabilities

   Definition

Vulnerabilities are weaknesses in software that attackers can exploit. Identifying and addressing these vulnerabilities is critical for building secure software.

How Vulnerabilities Are Addressed:

  • Penetration Testing (Pen Testing):
    Penetration testing involves ethical hackers attempting to exploit system weaknesses to identify potential vulnerabilities before attackers do.

  • Automated Vulnerability Scanning:
    Tools like Nessus and Qualys are used to scan systems for known vulnerabilities, comparing the system against databases of known security issues.

  • Code Audits and Reviews:
    Regular manual code reviews ensure secure coding practices and help identify weaknesses such as input validation issues or improper access control.

Example:
Financial institutions continuously automate vulnerability scanning to detect flaws in their infrastructure. They supplement this with periodic penetration testing by security specialists who simulate real-world attack scenarios, allowing the organisation to discover and fix vulnerabilities before attackers can exploit them.

Hardening Systems

   Definition

Hardening involves securing a system by reducing its potential attack surface. This is achieved by limiting services, closing unused ports, and enforcing strict security policies.

How Systems Are Hardened:

  • Minimising Attack Surface:
    Disable or remove unnecessary services, applications, and features to reduce the points of entry for attackers.

  • Regular Patching and Updates:
    Systems are regularly updated with security patches to fix vulnerabilities. In industries like healthcare, maintaining updated systems is often a regulatory requirement.

  • Configuration Management:
    Secure configurations are enforced across systems using tools like Chef, Puppet, or Ansible, ensuring all systems are hardened with uniform security policies.

Example:
A global tech company enforces strict access control policies and regularly patches its systems using automated tools to ensure no known vulnerabilities are left unpatched. They also apply least-privilege access controls, ensuring users can only access the data and systems necessary for their role.

Handling Breaches

   Definition

A security breach occurs when an attacker gains unauthorised access to a system. Effectively handling a breach involves detecting, containing, and mitigating the damage caused.

How Breaches Are Managed:

  • Incident Response Teams (IRTs):
    Organisations have dedicated teams trained to detect, contain, and mitigate security breaches. These teams follow incident response plans, which outline procedures for addressing breaches.

  • Containment and Mitigation:
    When a breach is detected, affected systems are isolated to prevent the attacker from moving laterally within the network. Mitigation involves fixing the exploited vulnerability and preventing further attacks.

  • Forensic Investigation:
    After containment, forensic investigators analyse logs and network traffic to determine how the breach occurred and what data was compromised.

Example:
In 2020, a leading tech company detected a breach where hackers accessed their internal systems. Their incident response team immediately isolated the compromised servers, preventing the attack from spreading further. A forensic investigation revealed how the attackers had entered through an unpatched vulnerability, prompting an immediate patch and policy update.

Maintaining Business Continuity

   Definition

Business continuity ensures that essential operations can continue despite system disruptions or breaches. The goal is to minimise downtime and maintain operational capability.

How Business Continuity Is Maintained:

  • Redundancy and Failover:
    Critical systems have backup or redundant systems that automatically take over in the event of a failure. Cloud-based failover systems ensure that if one server goes down, another seamlessly takes over.

  • Data Backups:
    Regular backups ensure that the organisation can restore its systems in case of a data loss. Cloud backups or offsite storage ensures that data is protected even if physical infrastructure is compromised.

  • Business Continuity Plans (BCPs):
    Companies create detailed business continuity plans that outline how to maintain operations during a system outage or attack. These plans include steps for failover, key personnel assignments, and system recovery.

Example:
An e-commerce platform that operates globally uses a failover system to switch traffic between data centres in case one fails. By routing traffic through other servers, the company ensures minimal downtime, maintaining the ability for customers to make purchases during system maintenance or failure.

Conducting Disaster Recovery

   Definition

Disaster recovery focuses on restoring systems after a significant event, such as a security breach or natural disaster. The aim is to recover quickly and minimise long-term impact.

 

How Disaster Recovery Is Conducted:

  • Disaster Recovery Plans (DRPs):
    A Disaster Recovery Plan includes the steps needed to restore critical systems and services. This involves prioritising which systems to restore and ensuring resources are in place for recovery.

  • Backup Restoration:
    Regularly testing the restoration of backups ensures that backups are reliable and can be used in the event of data loss or system failure. Offsite or cloud backups are commonly used for redundancy.

  • Recovery Time Objective (RTO) and Recovery Point Objective (RPO):
    Organisations set goals for how quickly services must be restored (RTO) and how much data loss is acceptable (RPO). These metrics help define recovery processes and ensure that critical services are restored within acceptable timeframes.

Example:
A bank that stores financial transactions in real-time performs regular disaster recovery drills to ensure it can restore operations within minutes of a failure. Data is mirrored across multiple servers, ensuring that the most recent transactions can be recovered and no critical data is lost.

  Content

Code review

Sources of Error

Often, as programmers, we overlook errors within the code we write. This can stem from any number of reasons. Personal bias may be up there, and it is the same with negligence, but a far more frequent source of such errors comes from our understanding. We understand this code and believe it's the best way to do this specific task because we wrote it. We often don't see a need to question or refine our approach, not because of ego, but simply because we don't spare any more thought to our ideas and how we implement

 

The idea is that when a programmer needs to debug their code, they should explain the program line-by-line to a rubber duck. This results in a greater depth of code analysis and can help identify problem areas or find better approaches to issues. If your code is errored and you feel stuck, this might be one way to think through your problem rationally. And don't worry; you don't need a don't duck for this; it's purely metaphoricit'sYou can explain your code to any object, toy, dog, cat, or some fancy esoteric pet you might have around, or even.

As incredible as chatting to a rubber duck about your code may sound, it doesn't precisely. And, of course, the duck can't exactly talk, meaning you're stuck with your thoughts throughout the process. Sure, the thoughts might be more organised, but that doesn't always help; it's fresh out of you and doesn't account for sources of mistakes, bias and overconfidence, for example.

That's why we are involved in the process! Another person can bring a fresh perspective to your code and, this time around, even voice it. Of course, it's better if they are themselves programmers, even better if they have more knowledge to share, and even better if they are part of your team.

Professional Setting

If you are in a professional setting, or specifically in an experienced team, running your code by others to identify errors or mistakes is called a Code Review.

This has several aspects to it, though most organisations will have this as a last 'sanity check' before the code is deployed or added to the project but after the bots and testing software have had their way with it (we will cover these in the following sections), though some may place it before. Generally, these are done in the text through comments, as nobody has the time to hold a meeting after every change of code, but everyone has time to write up a couple of lines of text about some error they found while glancing the code over.

This is a more formal process than you may be used to. The scale of the professional software environment is much greater than the one you typically study in, with large teams cooperating on larger projects. So, let's run through an example code review in the developer platform you should all be familiar with at this point: GitHub.

 

Static application security testing (SAST)

Testing Software

We can have our digital tools check our code for us. They won’t be perfect either, as they can only do what we taught them to do. But they are accurate and can be relied on to do a job a relatively infinite amount of times without fail, which isn’t the case with people. As we saw prior, these are generally run after code is deemed “completed” by the programmer but can be run at any stage of development to ensure you’re on the right track.

Now, let’s look at our first digital Method of Testing.

 

SAST

Passive. That’s generally what the Static in the name represents. The defining characteristic of this testing method is that it looks through your code without running it.

The software used here is the programming equivalent of Microsoft Word Spellcheck. It looks through your code and tries to find possible issues and flaws based on information and patterns it has in its database. Generally, these are common flaws previously identified and added in. Much like our beloved Spellcheck holds a dictionary of words and checks grammar based on them, a SAST tool holds a dictionary of vulnerability patterns, meaning it works a bit in reverse, checking that none of these unsafe practices and patterns are within the code you give it. It then generates a report of its findings and recommendations for improving your code.

Let’s make an analogy that will help us contrast this methodology with another one later on. A SAST tool sits on the couch until you come and give it code to review. It takes out a highlighter and, still on the couch, circles everything you got wrong. It returns it to you, tells you what you should do, and keeps you sitting on the couch.

If that sounds a bit dull… It is, but there are two reasons. Firstly, it’s one-half of two methodologies used together, so hold your breath. Secondly, SAST tools are handy since they are pretty fast and tell you if you’re on the right track without using too much time or resources.

Bandit is a tool for performing Static Application Security Testing (SAST) on Python code, including Flask applications. By integrating Bandit into your development workflow, you can proactively identify and remediate security vulnerabilities early in the coding process, enhancing the overall security posture of your application.

Dynamic application security testing (DAST)

DAST is a black-box testing method that evaluates an application's security while running. It simulates external attacks on the application to identify vulnerabilities that attackers could exploit.

How DAST Works:

  • Testing in a Live Environment:
    DAST tools simulate attacks on the running application by sending inputs, such as malformed requests or known attack patterns, to see how the application responds.

  • Common Tools:
    Tools like OWASP ZAP (Zed Attack Proxy) and Burp Suite perform DAST by identifying security issues such as cross-site scripting (XSS), insecure authentication mechanisms, and weak session management.

 

Vulnerability assessment

The Vulnerability Assessment process, a comprehensive approach to system security, involves identifying, quantifying, and prioritising vulnerabilities within a system. Programmers are responsible for ensuring the system's security by conducting checks before sending the code for review or production. This assessment entails a thorough analysis and documentation, typically a checklist of items to be reviewed and verified, ensuring robust system security.

In an extensive application, the process generally includes the following steps:

1. Identifying possible vulnerabilities.
2. Analysing the findings to determine potential issues and risks associated with the identified vulnerabilities.
3. Perform a risk assessment to evaluate the likelihood and consequences of each risk and prioritise the risks for mitigation.
4. Remediation of the identified risks and vulnerabilities may involve removing vulnerabilities, managing risks in alternative ways, and establishing preventive measures or contingencies for potential risks.

Penetration testing

On the other hand, Penetration Testing involves simulating cyberattacks to evaluate a system's security. It is an authorised attempt to breach Penetration testing, often called "pen testing," which simulates real-world cyberattacks to identify security vulnerabilities that malicious actors could exploit. Pen testing helps determine an application's security posture by actively attempting to breach its defences.

How Penetration Testing Works:

  • Simulated Attacks:
    Ethical hackers (pen testers) use various methods to exploit known and unknown vulnerabilities in a system. This can include attempting to bypass authentication, gain access to sensitive data, or escalate privileges.

  • Manual and Automated Approaches:
    Pen testers use automated tools and manual techniques to simulate realistic attacks. Tools like Metasploit and Kali Linux are often used alongside manual methods to perform penetration tests.

This process typically follows a five-step approach:

1. Planning and reconnaissance: Gathering information about the target system.
2. Scanning: Using tools to understand how the target system responds to various intrusion attempts.
3. Gaining Access: Attempting to exploit vulnerabilities to gain access to the system.
4. Maintaining Access: Trying to sustain access to achieve the test's goals while overcoming protective measures.
5. Analysis and Reporting: Compiling the results and providing recommendations based on the penetration test findings.

  Content

In software development, ensuring that data input is handled securely is critical to maintaining the integrity and security of the system. Implementing defensive data input handling practices is essential to protecting the system from common attacks such as SQL injection, cross-site scripting (XSS), and other input-based vulnerabilities.

Input Validation

Input validation ensures that the data entered by users meets the expected format before it is processed or stored by the system. This is the first line of defence against invalid or malicious input.

  • Types of Validation:

    • Server-side Validation: This occurs on the server, validating the data after it has been sent to it. It is more secure but may introduce delays as it requires communication with the server.
    • Client-side Validation: Performed on the client (e.g., in the browser) before data is sent to the server. This improves user experience but can be bypassed, so it should never be the only validation step.

  • Examples of Input Validation:

    • Type Checking: Ensure the input is of the expected data type (e.g., a number, string, date).

    • Length Checking: Restrict input data length (e.g., the string must be < 20).

    • Range Checking: Validate that numerical inputs fall within an expected range (e.g., age must be between 0 and 120).
      if age >= 0 and age <= 120:
    • Mandatory Fields:  Ensure that required fields are not left blank.

Data Sanitisation 

Data sanitisation involves cleaning user input by removing or escaping characters that could be interpreted as executable code, thereby preventing malicious data from compromising the system.

  • Why it’s important: Untrusted input, if not properly sanitised, can lead to security vulnerabilities like SQL injection and XSS, where attackers can manipulate input to execute unintended commands.

  • Sanitisation Techniques:

    • Escaping characters: Replacing potentially dangerous characters (like <, >, ', etc.) with safe representations.
    • Whitelist-based filtering: Accepting only known good input (e.g., allowing only alphanumeric characters for usernames).
    • Converting Data Types: Command-line inputs are strings, and the code requires the type to be a number/integer for calculations. For example,
      age = input("Enter your age: ") # input is a string
      age = int(age) # Convert to integer for numerical operations 

Error Handling

Error handling is a critical practice that ensures that when unexpected input or issues occur, the system can respond gracefully without exposing sensitive information or crashing.

  • Principles of Secure Error Handling:

    • User-friendly messages: Provide generic error messages to the end-user that do not disclose sensitive system information.
    • Detailed logging: Record detailed error information for developers or system administrators to investigate while keeping this information hidden from the user.

  • Example: Handling an error when an invalid file format is uploaded could involve rejecting the upload, notifying the user of acceptable formats, and logging the specific technical error for debugging.

In Python, error-handling messages can be used with the print() function. These error statements help log errors and provide feedback to guide users in correcting their inputs. For example, print("Password must be at least 20 characters") .

Example of Defensive Data Input Handling in Python:

  • The is_valid_username function validates that the username is alphanumeric and between 5-15 characters.
  • The re.escape() method sanitises input by escaping special characters, preventing SQL injection or similar attacks.
  • Error handling is implemented to provide a generic message when the user accesses an invalid route, keeping the system secure while offering meaningful feedback.
