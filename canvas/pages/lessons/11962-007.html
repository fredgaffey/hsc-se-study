1.1 Software Development Steps

Syllabus
Explore fundamental software development steps used by programmers when designing software including:

  • requirements definition
  • determining specifications
  • design
  • development
  • integration
  • testing and debugging
  • installation
  • maintenance

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • be able to explore the fundamental steps involved in software development and evaluate their impact on software design and quality.

Success Criteria - Students can:

  • describe the different steps involved in software development and provide examples of their use in different contexts.
  • explain how each step contributes to the overall software development process and the quality of the final product.
  • evaluate the importance of software development methodologies and provide evidence to support their arguments.

  Content

Software development follows a structured process made up of clearly defined stages. Each stage must be completed before moving on to the next to ensure the project progresses smoothly. This is especially important because development teams consist of individuals with different roles and expertise. For instance, coding cannot begin until a detailed plan for the solution has been created. The people responsible for writing the code are often not the same as those who handle the planning and design.

 

 

Requirements Definition

The first step in the software development process is to clearly and accurately understand the requirements of the problem. Any mistakes or omissions at this stage can be extremely costly to fix later in the development process. System analysts, who specialise in gathering and defining requirements, play a key role here.

 

 Key Terminology

  • Requirements - The specific features, characteristics, or behaviours that a system needs to meet its intended purpose. Each requirement must be clearly defined and testable to ensure it can be verified.

 

During this stage, the requirements of the system are identified and agreed upon with the client. It is crucial to fully understand the users' needs, expectations, and objectives before beginning the design of the software.

Requirements define the specific features, functions, and behaviours the system must have to fulfil its purpose. For a project to be successful, each requirement must be clear, accurate, and measurable, as these requirements will later serve as the basis for testing the final solution.

 

Software Specifications

After identifying what the software needs to accomplish (the requirements), the next step is figuring out how to make it happen. This is where specifications come into play. They act as detailed, technical instructions for turning the requirements into a working solution. While requirements focus on what the software should do from a user or business perspective, specifications explain the how in technical detail.

 

 Key Terminology

  • Functional specifications - The specific actions the software will perform. For instance, if the software needs to calculate the average of student scores, the functional specification would outline how the scores will be entered (input), how the calculation will be done (process), and how the result will be displayed (output).

  • Non-functional specifications - The overall qualities of the software, such as performance, security, and usability. These standards determine how well the software operates rather than what it does.

 

Specifications are crucial because they translate the broader goals of the requirements into actionable plans for developers. They provide the detailed framework needed to ensure the software is built correctly and fulfils its purpose.

Refining requirements into specifications involves breaking down each requirement and defining it in precise technical terms. For example, a general request like "I want fast software" might be refined to specify "The software should process data in under three seconds."

Throughout the development process, specifications serve as a benchmark for evaluating the software. They guide developers and ensure that the final product meets the agreed-upon standards and expectations.

 

Design

Design involves planning the structure of the software, including its architecture, tools, programming languages, data models, and user interface.

 

 Key Terminology

  • Algorithms - Step-by-step instructions to solve a problem or complete a task. To design an algorithm, break down the problem into smaller steps and test it with different inputs to ensure it works correctly.
  • Subroutines - Simplify complex tasks by dividing them into smaller, manageable parts. Learn how to pass data into and out of subroutines using parameters and variables. Use testing methods like drivers to check if subroutines perform as expected.
  • Modular programming - Creating reusable code components called modules. Use existing modules or build custom modules to make programs more efficient and organised.


User interface design should match the needs of the intended audience. Consider factors like screen size, layout, and consistency to make the interface user-friendly and visually clear.

Help systems assist users in understanding the software. Include features like tutorials, wizards, and context-specific help to provide clear and relevant guidance.

When choosing a programming language or technology, consider the project’s requirements, the hardware it will run on, and the skills of the developers. Evaluate performance through benchmarking to select the most suitable option.

Development

During the development phase, the actual coding of the software takes place. Developers write and compile code to create functions and features outlined in the design phase. After development, the process and loop back to the design phase. This allows for modifications in design based on challenges or insights gained during development.

In this course we will be using Python as the main programming language to develop software.

 

The process of development varies depending on the approach used:

  • Waterfall Approach: In this linear approach, development occurs after the design phase is fully completed. The entire system is coded as a single project, focusing on implementing all planned features in one continuous phase before moving to testing. This method is suitable when requirements are well-defined and unlikely to change.
  • Agile Approach: Development happens incrementally over multiple iterations, called sprints. Each sprint focuses on coding a small part of the product, progressively adding functionality until the software is complete.

 

During development, it is crucial to ensure that the code performs its intended tasks, handles unexpected data appropriately, and protects against potential security vulnerabilities. Debugging is a key part of this process, with modern tools like integrated development environments (IDEs) providing automated features to detect and fix errors efficiently.

A widely used practice in development is Test-Driven Development (TDD), where tests are written first, defining the criteria the code must meet. The code is then written and refined until it passes all these tests, ensuring it meets the specifications. This contrasts with traditional methods where testing is performed after the code is written.

Integration

After writing code, it often needs to be integrated with other existing systems, such as older legacy systems, external databases, or APIs. Different parts of the software, like individual modules, may be developed by multiple people simultaneously. These modules must then be combined into one working system.

 

Version Control Systems (VCS) help manage this process by tracking changes to the code. They allow multiple programmers to work on the same project without overwriting each other’s work. VCS also provides a backup of the code, ensuring that previous versions can be accessed if needed.

 

Testing and Debugging

Testing and debugging are crucial steps in the software development process to ensure the final product works as intended. Once coding is complete, testing focuses on checking the product for errors and ensuring it meets the original requirements.

 

 Key Terminology

  • Alpha testing - Testing done by the software development team using real data before the product is released.
  • Beta testing - Giving the product to a small group of external users to test it in real-world conditions. These users report any issues or suggest improvements.

 

Testing is part of quality assurance, which ensures the product meets industry standards and performs well. This process also checks if the design and development stages were successful.

 

Testing happens at different levels:
  • Unit testing checks small sections of code.
  • Program testing checks the entire program.
  • System testing checks how the program works as a whole.

 

Test data is created to simulate real usage, including large file sizes, response times, and various transactions. Automated tools often help manage and report on the testing process.

The results of testing are used to identify and fix problems. Each requirement and specification is checked against the final product to confirm it is fully implemented. Any faults found are corrected, ensuring the software meets its goals.

Installation

Once a new software product is ready, it needs to be installed and put into use. This process often involves replacing an older system with the new one, and there are different methods to do this, depending on the situation.

 

The main methods are:

  • Direct cut-over: The old system is immediately replaced with the new one.
  • Parallel: Both systems run at the same time until the new one proves reliable.
  • Phased: The new system is introduced in stages, one part at a time.
  • Pilot: The new system is tested by a small group first before being rolled out to everyone.

 

Each method has its benefits and is chosen based on the needs of the project.

Maintenance

Maintenance is the process of improving and fixing software after it has been released to ensure it continues to meet user needs. Over time, this often involves correcting errors (bugs), enhancing performance, or adding new features to adapt to changing requirements.

 

 Key Terminology

  • Software Maintenance - The ongoing process of fixing issues, improving performance, and updating software to ensure it remains functional and relevant to user needs.

 

To decide on changes, developers communicate with users to understand issues or requests. Small changes, like bug fixes, might be released as patches, while larger changes, like redesigning the interface, may require a full upgrade. The process of making these updates often restarts the software development cycle.

Good documentation of the original software is essential for maintenance. It helps developers—often different from the original team—understand the code and make changes efficiently. Many companies even have separate teams specifically for software maintenance.

Software evolves over time as new versions are released. These updates typically fix bugs and add new features based on user feedback. Companies must prioritize requests for changes, often using surveys or support data to decide which modifications will have the greatest impact.

 

Understanding Software Development Steps

In order to better understand the steps explored above, let's consider a simple scenario. 

Let's imagine we are tasked with developing a library management system for a local library. The system should allow librarians to manage books, members, and borrowing transactions. We will walk through the fundamental software development steps in the context of this scenario.

Requirements Definition

First, we need to gather and define the requirements of the system by interviewing stakeholders, such as librarians and library staff. Through this process, we determine that the system must be able to:

  • Add, edit, and delete book records
  • Add, edit, and delete member records
  • Record book borrowing and returning transactions
  • Generate reports on overdue books and member activities
  • Handle book reservation requests

Determining Specifications

Based on the requirements, we create a detailed specification document that outlines two key areas:

  • Functional specifications: These describe the system's specific features and capabilities, such as:

    • Adding or editing book and member records
    • Recording borrowing and returning of books
    • Generating overdue reports

  • Non-functional specifications: These define the performance, security, and usability expectations, such as:

    • The system must process transactions quickly, with no delays
    • Data must be secured to prevent unauthorised access
    • The system should be user-friendly and easy to navigate for staff

This combination ensures the system not only performs the required tasks but also meets quality and user expectations.

Design

We then design the system by creating a high-level architecture and detailed component plans. This includes:

  • User interface mockups that show how screens will look and how users will interact with the system
  • Class diagrams to outline the code structure and relationships between features
  • Planning how the different components (e.g., user input, processing, and reporting) will connect to ensure smooth operation

At this stage, we also decide on the technologies to use, such as programming languages (e.g., Python, Java) and frameworks.

Development

With the design ready, we move to the development phase. Developers:

  • Build the user interface, including forms for managing books and members
  • Write the backend logic to process borrowing and returning transactions
  • Integrate components to ensure data flows correctly between the user interface and the backend

This phase often involves collaboration, with developers working on different parts of the system simultaneously.

Integration

Once the individual components are developed, we integrate them into a single, fully functioning system. For example:

  • Ensuring the user interface communicates with the backend correctly
  • Verifying that data from borrowing and returning books is processed and stored accurately

Integration ensures that all parts of the system work together as intended.

Testing and Debugging

The library management system is then rigorously tested to identify and resolve any issues. Testing includes:

  • Unit testing – verifying that individual features, like adding a member record, work correctly
  • End-to-end testing – ensuring that complete workflows, such as borrowing a book, function as expected

Feedback from librarians and staff is gathered to confirm the system meets their needs. Any bugs or issues are fixed, and the system is re-tested.

Installation

Once testing is complete, the library management system is deployed on the library's computers or servers. To ensure a smooth transition, we may also:

  • Install the system on user devices
  • Provide training for librarians and staff to help them use the new system effectively

Maintenance

After the system is installed and operational, maintenance begins. This involves:

  • Fixing any new issues that arise (e.g., bugs or crashes)
  • Updating the system to meet new requirements, such as adding features for improved usability
  • Providing regular updates to ensure security and compatibility with new technologies
