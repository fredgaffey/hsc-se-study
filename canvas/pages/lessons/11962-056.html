Syllabus
Identify the hardware requirements to run a program and the effect on code development including:
assessing the relationship of microcontrollers and the central processing unit (CPU)
the influence of instruction set and opcodes
the use of address and data registers

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • develop an understanding of the hardware requirements necessary to run a program and how these requirements affect code development, including the roles and interactions of microcontrollers and CPUs, the impact of instruction sets and opcodes, and the function of address and data registers.

Success Criteria - Students can:

  • assess and explain the relationship between microcontrollers and the central processing unit (CPU) in the context of code execution.
  • analyse and discuss how the instruction set and opcodes influence program functionality and performance.
  • identify and describe the roles of address and data registers in the process of program execution.
  • evaluate hardware requirements for specific programs and determine their impact on code development and performance.
  • demonstrate the ability to make informed decisions about hardware requirements based on program needs and development goals.

  Content

Different systems have different requirements. A security camera has different functions and hardware than a smart light. Depending on the requirements of each system, our microcontroller may need more pins, Bluetooth capability, or more memory. For example, a smart light would need wireless capability, whereas a security camera would need a camera attached and a powerful enough processor to look at camera data and track faces in real time. 

 

Microcontrollers

Mechatronic systems are designed to perform specific fixed tasks and, to save cost and space, they do not execute their code on a normal computer or powerful microprocessor (CPU). Mechatronic systems execute their code in a microcontroller which contains a very small microprocessor, some memory to store program code and data and input/output pins to sense and react to their environment.

To help prototype mechatronic systems, microcontrollers are widely available on circuit boards which include a method to connect and upload code. These boards are called microcontroller boards and may include extra functionality such as sensors, LEDs and buzzers.

 

Relationship of microcontrollers and the central processing unit

Most systems would include a central processing unit (CPU), which processes input and produces output. However, by itself a CPU is useless as there would be no place to store the outputs of the CPU, as well as use it to interface with the environment. In embedded systems, a microcontroller is used for this purpose. A microcontroller contains a CPU, alongside memory and registers (fast, set slots of memory stored within the CPU used for operations) to store the outputs of the CPU, as well as pins to connect peripherals to the CPU.

Instruction set and opcodes

Each processor has an instruction set, which determines what instructions do based on the data that is given to the processor. The processor reads the instruction which is a number of bytes of machine code, where the bits that distinguish what instruction it is is called the opcode. The opcode tells the processor what to do, i.e. add two numbers together, move this number into memory. We can use the CHIP-8 programming language as an example as it uses opcodes as lines of code.

Note that CHIP-8 is not an instruction but is solely a teaching example in these notes

An opcode in CHIP-8 takes the form of ZZZZ where Z is a hexadecimal number. The opcode for adding two numbers is 8XY4, where X and Y specify the register slot. If we wanted to add two numbers together and the numbers were in registers 1 and 2, our instruction would be 8124.

Example excerpt from https://en.wikipedia.org/wiki/CHIP-8

We can differentiate between types of CPU instruction sets, which are complex instruction set computers (CISC) and reduced instruction set computers (RISC). CISCs are processors in which opcodes can specify the processor to perform multiple low-level instructions in one opcode, including high-level abstracted instructions such as control flow. RISCs are processors which have two separate types of instructions, which are instructions that load and store from memory and registers, and instructions that use the ALU in conjunction with registers. This means to add a number, it cannot be in memory, it must be in the CPU registers. Thus CISC uses less instructions and system resources but is slower and more power hungry, while RISC uses more instructions and system resources but is faster and more efficient.

 

RISC (Reduced Instruction Set Computers)

Advantages

Disadvantages
  • Less power draw
  • Simpler
  • Faster execution speed
  • More instructions needed
  • Larger executable size
  • More memory required

 

CISC (Complex Instruction Set Computers)

Advantages

Disadvantages
  • Less instructions needed
  • Smaller executable size
  • Less memory required
  • More power draw
  • Complex
  • Slower execution speed

 

For example, the RISC instruction set, ARM, has instructions which are generally 4 bytes in length, while x86 - which is regarded as a CISC instruction set - has instructions that may be anywhere from 1 byte to 15 bytes in length.

Please note that current instructions sets may include features of both CISC and RISC

 

The use of address and data registers

To identify the hardware requirements to run a program and the effect on code development, we must understand the role and use of address and data registers in computing systems.

 

Hardware Requirements and Address Registers

Different programs require different hardware capabilities, depending on their complexity and purpose. Address and data registers are critical components of a computer's central processing unit (CPU) and play a vital role in program execution.

Address Registers: These are special-purpose registers used to store memory addresses. They are essential for accessing and managing memory locations during program execution. For instance, a program that performs extensive data manipulation might require a CPU with multiple address registers to handle the addresses of various data points efficiently. Address registers facilitate the CPU in quickly accessing specific memory locations, which is crucial for both reading from and writing to memory.

 

Data Registers and Their Impact on Code Development

Data Registers: These are used to store actual data values that the CPU needs to process. The number and size of data registers directly impact a program's performance and the complexity of operations it can perform. For example, a program that involves heavy numerical computations would benefit from having a CPU with larger and more numerous data registers, allowing it to handle more data simultaneously and execute complex instructions more efficiently.

 

Example of Use in Code Development

To illustrate, consider a simple arithmetic operation in assembly language:

MOV R1, #5     ; Move the value 5 into register R1
MOV R2, #10    ; Move the value 10 into register R2
ADD R3, R1, R2 ; Add the values in R1 and R2, store the result in R3

In this example:
- `R1`, `R2`, and `R3` are data registers.
- The CPU uses address registers internally to fetch the instructions and operands from memory.
- The `MOV` instructions place data into the data registers.
- The `ADD` instruction performs the operation using the data in these registers.

 

Effect on Code Development

The availability and design of address and data registers influence how programmers write and optimise their code. For instance, a CPU with a limited number of registers might require more frequent access to slower main memory, leading to potential performance bottlenecks. Conversely, a CPU with ample registers can perform more operations in parallel and reduce the need for memory accesses, leading to more efficient and faster code execution.

In summary, the hardware requirements to run a program, particularly the use of address and data registers, significantly affect how code is developed and optimised. Understanding these requirements helps in choosing the right hardware for specific applications and in writing efficient, high-performance programs.
