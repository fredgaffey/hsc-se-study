  Content

 The Object-Oriented Paradigm

Object-oriented programming (OOP) is a programming paradigm that structures computer code using the concept of objects, making the code easier to understand and manage. Instead of just writing lines of instructions one after the other (procedural programming), we organise our code into special groups called classes. Think of classes as templates or blueprints for creating specific types of objects.

An object is a bit like a playable character in a multiplayer video game.

All players have data (attributes) that are associated with them:

  • Gamertag
  • Position
  • Health Stats
  • Attack Stats
  • Defence Stats

Players also have actions (methods) to handle specific tasks that affect their own attributes or the attributes of other players:

  • Move up/down/left/right
  • Heal
  • Deal damage
  • Block attack

Players can also spawn (instantiation) multiple times depending on how many users join the game, all with the same set of methods and attributes.

The game programmer can also stop people from cheating in the game by seeing the current coordinate position of all players. The programmer achieves this by keeping the position attribute private to the player themselves (encapsulation), so that players can't access another player's position.

We may also want different subtypes of players (inheritance), like heroes, villains, healers, and demons.

Overall, OOP helps us keep things organised and makes it easier to reuse and fix our code. It's a bit like building with Lego blocks – you have different pieces that fit together to create something bigger (your program).

A note on terminology between Procedural Programming and Object Oriented Programming. In classes,

  • Variables are called Attributes
  • Functions/Procedures are called Methods

 

 Procedural Programming vs Object-Oriented Programming

The main difference between procedural programming and object-oriented programming is in their fundamental approach to organising code and data.

In procedural programming, the code is organised around procedures or functions, with a focus on the sequential execution of these procedures to achieve a task. Data is often global and can be accessed from anywhere in the program, leading to potential issues with data integrity and code maintenance.

On the other hand, object-oriented programming (OOP) organises code around objects, which encapsulate both data and behaviour. Objects are instances of classes, which serve as blueprints defining the structure and behaviour of objects. OOP emphasises modularity, encapsulation, inheritance, and polymorphism, allowing for more organised, reusable, and easier-to-maintain code compared to procedural programming.

In summary, procedural programming revolves around functions or procedures, while object-oriented programming revolves around objects and classes.

  Content

In 2.1, The Object-Oriented Paradigm, we provided a high-level overview of the main concepts of object-oriented programming. In module 2.2, we will discuss these concepts in more detail.

Classes

A class is like a blueprint or template for creating objects. It defines the properties (attributes) and behaviours (methods) that objects of that class will have. Think of a class as a recipe for creating objects. It encapsulates data (see encapsulation heading below) for the object and provides methods to operate on that data.

Here's how we construct a generic Person class in Python:

Class Name

In Python, a class is defined using the class Keyword followed by the class name. It is a standard programming convention to capitalise the first letter of a class name (e.g. Person, Animal, Vehicle).

Attributes

After defining a class, we need to list the attributes that a Person should have. Since the value of these attributes varies from person to person, we will initially set each of these to None.

Constructor Method

We now need to add a constructor method that builds an object out of the Person class.

A constructor in Python is a special method that gets called automatically when a new object of a class is created. It is used to initialise the object's state, using the arguments to pass values specific to the person being created into our previously empty attributes. In Python, the constructor method is named __init__. It allows you to perform any necessary setup operations when creating a new instance of a class.

Note: In Python, self is a reference to the current instance of a class. It's used inside methods to access the attributes and other methods of the containing class. For example, self.firstName refers to the firstName attribute defined above the constructor method whereas firstName inside the constructor refers to the method's parameter.

Methods

Finally, we can add in the methods that perform actions based on the attributes.

Methods in Python are functions defined within a class. They are used to define the behavior of objects created from that class. Methods can access and modify the attributes (data) of an object and perform actions related to that object.

Objects

An object is an instance of a class. It is created using the blueprint provided by the class (this is called instantiation). Each object has its own set of properties and can perform actions defined by the class.

In Python, you instantiate an object by calling the class name followed by parentheses containing any arguments required by the class's constructor (the __init__ method). This process creates a new instance of the class, which is an object with its own set of attributes and methods.

In the context of our Person class, we can create multiple Person objects, each representing a different person with unique attributes. We can also access the components of our instantiated class (i.e. accessing the object's attributes and using the object's methods).

Encapsulation

Encapsulation is one of the fundamental principles of object-oriented programming (OOP).

Encapsulation allows us to hide the attributes (data) within a class and makes them available only through well-defined interface methods (getter and setter methods). The only way to access and modify hidden attributes are through these interface methods. This helps in maintaining consistency and security for the data in an object.

We can also hide certain methods which are only used from within the class itself and don't need to be accessed by other objects or the rest of the program.

Attributes and methods can be set to three different visibility modifiers:

  • Public (default) - Accessible inside or outside the class.
  • Protected _ - Accessible within the class or its sub-classes
  • Private __ - Accessible only within the class.

 

The key ideas behind the use of encapsulation are:

  1. Data Hiding: Encapsulation allows you to hide the internal state of an object from outside interference. This means that the implementation details of the class are hidden as private and cannot be accessed directly from outside the class.

  2. Access Control: Encapsulation enables you to control access to the attributes of a class. By defining access modifiers like public, private, and protected, you can specify which parts of the class are accessible from outside and which are not.

  3. Abstraction: Encapsulation provides a way to abstract the implementation details of a class. It allows you to focus on what an object does rather than how it does it, promoting a clear separation between the interface and implementation.

Encapsulation helps in achieving modularity, reusability, and maintainability of code by reducing dependencies and preventing unintended modifications to the internal state of objects.

 

In Python, encapsulation can be achieved by using private attributes and methods, indicated by prefixing them with a double underscore __.

Consider our example class Person. Using encapsulation, we can ensure that the age attribute is never set to a value less than or equal to 0 by first making it private using a two underscore (__) prefix.

Since the __age attribute is now hidden from everything outside the Person class in our program, we must write a getter method (getAge()) and setter method (setAge()) for the __age attribute.

Getter and setter methods are like guards for the information inside an object. They control how you can see and change that information (i.e. other objects cannot directly access the __age attribute, they can only use the getter and setter methods that the programmer provides).

Getter Method: getAge()

  • Getter methods are used to access the value of a private attribute from outside the class. In this program, getAge() is a getter method that allows retrieving the value of the private attribute __age.
  • It returns the value of __age.

Setter Method: setAge()

  • Setter methods are used to modify the value of a private attribute from outside the class, usually with some validation.
  • In this program, setAge(age) is a setter method that sets the value of the private attribute __age.
  • Before setting the age, it checks whether the input age is non-negative (greater than 0). If it's not, it prints a message indicating that the age cannot be less than or equal to 0 (the attribute remains as None).
  • If the input age is valid, it sets the value of __age to the input value.

Constructor:

  • Since we now have a setter method (setAge()) that guards the __age attribute against unwanted inputs, we can replace the variable assignment self.__age = age in the constructor with self.setAge().

Below, we instantiate the Person class but the __age attribute is now private instead of public.

When accessing and printing the values of the firstName and address attributes, we are not given any errors because they are public and easily accessible to everything in our program.

However, if try to access and print the value of the private __age attribute, we are given an error which says that the program cannot find the attribute __age (which is what we want since we've hidden that attribute from everything outside the Person object).

Inheritance

Inheritance is a key concept in object-oriented programming (OOP) that allows classes to inherit attributes and methods from other classes. This enables the creation of a hierarchical structure of classes, where child classes can reuse and extend the functionality of their parent class.

When a class inherits from another class, it automatically gains access to all the attributes and methods that are defined in the parent class. This means that the child class can use and manipulate the data and behaviours defined in the parent class without redefining them.

Inheritance in OOP can be understood as an "is-a" relationship, which represents a form of classification or categorisation. In this context, the child class is said to be a more specialised version of the parent class.

Student Class

We can create a new Student class as a child class of Person (since Student is a type of Person).

We will do this in a new file called Student.py.

Your folder structure should now look like this:

 

In Student.py, we will need to import the Person class from Person.py at the top of the file.

The Student class then defines its parent class Person in brackets () next to the class name.

The Student class inherits everything (attributes and methods) that the Person class has, plus a few extra things specific to a student:

  • studentId (specific identifier for a student in a school)
  • subjects (a list of HSC subjects that a student takes)

We now need a constructor method __init__() so that we can instantiate the Student class into objects.

This constructor method's parameters should have the same parameters as the Person class's constructor method.

  • firstName, lastName, age, address, phoneNo, email

The constructor method's parameters should also have the additional attributes that were introduced in the Person class.

  • studentId

The reason why we don't handle subjects in the constructor method because we want to initially leave it as an empty list. We can use setter methods later to add/remove subjects after being instantiated as an object.

In Python, we can use super() to access the public/protected methods and attributes from the parent class.

In the Student class's constructor, we don't want to call each setter method again for the attributes that are inherited from the Person class.

Using super(), any attributes that are directly inherited from the Person class (firstName, lastName, age, address, phoneNo, email) can set their values by simply re-using the Person class's constructor.

  • super().__init__(firstName, lastName, age, address, phoneNo, email)

Any new attributes are then set after calling the Person class's constructor.

  • self.setStudentId(studentId)

We then implement the getter and setter methods (just as we did for the Person class's attributes).

  • getStudentId
  • getSubjects
  • setStudentId
  • addSubject - Adds the string name of a subject in the subjects list
  • removeSubject - Removes the string name of a subject in the subjects list

Plus any other methods that define the behaviours of the Student class.

  • numberOfUnits

In main.py, to use the Student class we need to import it using

  • from classes.Student import Student

We can then instantiate a Student object before adding each subject that the student does (addSubject()).

Like any other object, we can access its public methods (getStudentId(), getSubjects(), numberOfUnits()).
