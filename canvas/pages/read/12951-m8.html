Programming for the Web: Backend and Beyond

While the frontend creates the visual experience for users, the backend is the invisible engine powering web applications. This cycle dives deep into the architecture, tools, and processes that run on the server side, ensuring applications are dynamic, secure, and scalable.

Throughout this cycle, we will cover the following key areas:

  • The fundamental role of backend development in managing data, security, and the overall success of a web application.
  • The lifecycle of a web request and the interplay between webservers, frameworks, objects, libraries, and databases.
  • The use of scripting languages, specifically shell scripts, for automating server-side tasks.
  • Database interaction using SQL and Object-Relational Mapping (ORM) to retrieve and manipulate stored data.
  • Best practices for collaboration between frontend and backend teams.
  • The design and implementation of Progressive Web Apps (PWAs) with a focus on UI/UX, accessibility, and inclusivity.

2.15 Backend Development

Syllabus
Assess the contribution of back-end web development to the success of a web application

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • understand the role of back-end web development in ensuring the functionality, performance, security, and scalability of a web application

Success Criteria - Students can:

  • explain the main components of back-end development (server, database, APIs, security).
  • assess how a well-implemented back end contributes to a web application’s performance, security, and scalability.
  • provide examples of successful web applications that rely on strong back-end development to meet user needs.

  Content

Back-end web development refers to the server-side components of a web application. It involves managing the database, server, and application logic. While front-end development focuses on what users see and interact with, back-end development ensures the app functions properly, processes requests, and delivers the correct data.

 

Recall: Components of Back-End
  • Server: Handles client requests, processes data, and sends responses
  • Database: Stores and manages data that the application needs to function
  • APIs (Application Programming Interfaces): Allow communication between different parts of the application or between external services
  • Security: Ensures that data is stored and transferred securely (e.g., authentication and encryption)

 

 

Contribution to Web Application

Back-end web development is the backbone of a web application. It ensures the application runs smoothly, securely, and efficiently behind the scenes. A strong back-end infrastructure supports key aspects like performance, scalability, data management, security, and integration, all of which are crucial for the overall success and growth of the application. 

 

Performance and Speed

The back end plays a crucial role in determining the speed and responsiveness of a web application. When a user interacts with the front end (such as clicking a button or submitting a form), the request is sent to the back end, which processes it and returns the necessary data. Well optimised back-end processes ensure minimal delays, which enhances the overall user experience.

  • Example: In an e-commerce application, when a user searches for a product, the back-end queries the database to retrieve the relevant results. If the back end is inefficient or poorly structured, it could lead to long wait times or even timeouts, frustrating the user and potentially causing them to leave the site.

Scalability

Scalability is the ability of a web application to handle growth, whether it’s more users, larger datasets, or increased functionality. A scalable back end allows the application to handle high traffic without crashing or experiencing significant slowdowns.

  • Vertical Scaling: Adding more resources (like CPU or memory) to a single server.
  • Horizontal Scaling: Adding more servers to handle the workload.

Back-end technologies, such as load balancers, distributed databases, and cloud services, enable scalability. A scalable back end ensures that an application can grow along with its user base, without performance degradation.

  • Example: Social media platforms like Facebook or Instagram handle millions of concurrent users and enormous amounts of data. Their back-end systems are designed to scale horizontally, allowing them to manage this load effectively without crashing.

Data Management and Integrity

Back-end development is essential for managing how data is stored, retrieved, and updated. This includes designing and maintaining databases that handle structured (e.g., SQL databases) or unstructured (e.g., NoSQL databases) data. A robust back end ensures that user information, content, and transactions are handled efficiently and with high integrity, preventing data loss or inconsistencies.

  • Example: In a banking application, the back end ensures that data such as account balances and transaction history are accurately stored and updated in real time. Proper data management guarantees that users see the correct information without errors or discrepancies.

Security

A key responsibility of back-end development is ensuring the security of the web application. The back end manages user authentication, authorisation, and encryption of sensitive data. Security measures include safeguarding the database against SQL injections, securing APIs, and implementing HTTPS to encrypt data transferred between the client and the server.

  • Authentication: Verifying a user’s identity (e.g., login systems).
  • Authorisation: Controlling what resources a user can access based on their role.
  • Data Encryption: Ensuring that sensitive information like passwords and financial data are stored securely.

 

  • Example: An online banking application’s back end is responsible for securing user accounts, ensuring only authorised users can access personal financial information, and encrypting sensitive data during transmission.

Reliability and Availability

Reliability refers to the ability of the web application to perform its functions correctly and consistently, even in the face of errors or system failures. Back-end development ensures that the web app can recover quickly from unexpected issues such as server crashes or network failures. It also involves designing fail over mechanisms, where backups are automatically activated if something goes wrong.

High availability ensures that the application is accessible to users 24/7. This is achieved through techniques like database replication, server clustering, and the use of cloud services.

  • Example: Netflix ensures reliability and availability by using distributed server architecture and multiple data centres across the globe. Even if one server fails, users can continue to stream content without disruption because the back-end systems automatically route them to another server.

API and Third-Party Integration

A modern web application often relies on third-party services for added functionality (e.g., payment gateways, social media logins, geolocation services). The back end is responsible for integrating these external APIs (Application Programming Interfaces) into the web application securely and efficiently.

Effective back-end development ensures that data is passed between the application and third-party services without errors and that performance is not hindered. This can also extend the capabilities of the app, making it more versatile and useful to the user.

  • Example: Uber integrates with Google Maps and third-party payment services through its back-end APIs. This seamless integration enables real-time location tracking and secure payments without disrupting the user experience.

 

Real World Examples

These real-world examples demonstrate that back-end web development is fundamental to ensuring scalability, performance, security, and data management in high-traffic applications. In each case, the back end is what enables these companies to deliver reliable, seamless services to millions of users globally, contributing to their overall success.

 

  Amazon

Back-End Contribution:

Amazon’s success as the largest e-commerce platform is heavily reliant on its robust back-end infrastructure, which supports millions of users, thousands of vendors, and enormous amounts of transaction data.

  • Performance: Amazon uses distributed databases and caching mechanisms to ensure fast product search and retrieval. This allows users to browse thousands of products quickly without noticeable delay.
  • Scalability: The back-end system is built to handle massive traffic surges, such as on Prime Day or Black Friday. Amazon achieves this scalability by using cloud services like AWS (Amazon Web Services), which allows the infrastructure to expand or contract based on demand.
  • Data Management: The back end efficiently manages customer data, product inventory, and transaction histories. The system ensures data integrity for orders, payments, and shipping.
  • Security: Amazon uses sophisticated encryption and token-based authentication mechanisms to protect user data, especially during payment transactions.

Success Impact: Without a scalable and secure back-end infrastructure, Amazon wouldn’t be able to process millions of orders, handle thousands of sellers, and provide real-time updates on shipping or inventory. The back end’s capability to handle these elements is crucial to the platform’s ability to grow and meet customer demands worldwide.

  Uber

Back-End Contribution:

Uber’s ride-hailing service connects drivers with passengers, and its success hinges on a highly efficient and scalable back-end system.

  • Performance: Uber’s back end manages real-time data to match passengers with available drivers based on their locations, traffic conditions, and estimated wait times. The back end ensures that this happens quickly, minimising waiting time for users.
  • Scalability: The back-end system is designed to handle millions of users across different cities and countries. Uber’s infrastructure dynamically scales based on peak usage times (e.g., during holidays or major events). The platform uses a microservices architecture, allowing various back-end components to scale independently.
  • Data Management: Uber’s back-end system manages various types of data, including user profiles, ride histories, and payment information. It also stores real-time data like GPS locations for drivers and passengers.
  • Integration: The back-end seamlessly integrates with third-party services for payments (e.g., credit cards, digital wallets) and location services like Google Maps for navigation and route optimisation.
  • Security: Uber’s back end secures user data and handles payment processing, using encryption and secure payment gateways to protect both drivers and passengers.

Success Impact: The reliability and speed of Uber’s back end is crucial for providing a seamless experience to users. The ability to scale efficiently allows Uber to serve millions of rides per day, while ensuring users feel safe and confident in their transactions.

2.16 Web Requests

Syllabus

Observe and describe the back-end process used to manage a web request, including:

  • role of webserver software
  • web framework
  • objects
  • libraries
  • databases

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • understand the back-end process of handling a web request and recognise how different components interact to manage user data and deliver a response.

Success Criteria - Students can:

  • describe how a web framework organises and routes requests.
  • identify the function of objects and how they relate to database tables.
  • explain how libraries provide additional functionalities to applications.
  • describe the relationship between the web framework and the database for handling data storage and retrieval.

  Content

 

Role of Webserver Software

The web server is the software responsible for accepting HTTP (or HTTPS) requests from clients (typically browsers) and delivering responses back to the client, which may include HTML pages, JSON data, images, or files.

 

Request Handling

  • Request Handling: The webserver receives the request from the client and determines whether it can serve the requested resource (like a static file) directly or if the request needs to be processed further.

Static Content Delivery

  • Static Content Delivery: If the request is for a static file, such as an HTML page, image, or CSS file, the webserver directly delivers that content to the client. Static files don’t require additional server-side processing.

Proxying to Application Server

  • Proxying to Application Server: For requests that require dynamic content generation, such as retrieving user data or processing form submissions, the webserver forwards the request to an application server. In this case, the webserver acts as a “reverse proxy,” forwarding the request to the web framework.

Popular Webservers

  • Apache: Apache is an open-source HTTP server that can handle both static and dynamic content. It uses modules to manage different types of content.
  • Nginx: Known for being lightweight and efficient at handling a large number of concurrent requests. It often acts as a reverse proxy for dynamic content.
  • IIS (Internet Information Services): A web server from Microsoft used for hosting websites and web applications on Windows servers.

 

Web Framework

A web framework provides the structure and reusable components that simplify the development of a web application. It takes care of the complex tasks involved in handling HTTP requests, URL routing, database access, and rendering views.

 

Flask provides a flexible framework to structure and manage web requests. Its simplicity makes it a great choice for small to medium-sized applications.

  • In Flask, routing is straightforward. Each route corresponds to a URL pattern that the application responds to. The @app.route() decorator is used to map a URL to a Python function (also known as a view function).
@app.route('/profile/<username>')
def profile(username):
    return f"User profile page of {username}"

 

  • Flask supports middleware that processes requests before and after they reach the route. Middleware can handle tasks such as authentication, request logging, or modifying the request data.
@app.before_request
def log_request():
    print(f"Request method: {request.method}, Request path: {request.path}")

 

Objects

In a back-end system, objects typically represent key entities or concepts in the domain of the application. They are instances of classes that structure and store data, often correlating with database tables (in relational databases) or collections (in NoSQL databases).

 

Object-Relational Mapping (ORM)

Object-Relational Mapping (ORM): Many web frameworks use an ORM to map these objects to database tables. This makes it easier to work with databases using an object-oriented programming paradigm rather than writing raw SQL queries.

  • Example: In Django, models are Python classes that represent database tables. For example, a User model might be written as:
class User(models.Model):
    username = models.CharField(max_length=100)
    email = models.EmailField(unique=True)

 

Data Manipulation

Objects allow developers to interact with data as if they were working with in-memory objects in code, even though the data might actually be stored in a database.

user = User.objects.get(id=1)  # Retrieves a user from the database
user.username = "NewName"  # Updates the username
user.save()  # Commits the changes to the database

 

 

Libraries

Libraries are reusable sets of functions and tools that provide additional functionality and speed up development by abstracting common tasks. These are often external packages installed via a package manager (e.g., pip for Python or npm for Node.js).

 

Types of Libraries

  • Utility Libraries: Provide helper functions for common tasks, like manipulating strings, formatting dates, or handling arrays.
  • Database Libraries: Provide functions to interact with databases, sometimes extending the ORM.
  • Authentication and Authorisation: Libraries like OAuth or JWT (JSON Web Tokens) are used to handle secure authentication flows.
  • Form Processing Libraries: Handle user input validation and sanitation

Integration Libraries

For integrating with third-party services, such as payment gateways (Stripe, PayPal), email services (SendGrid), or cloud storage (AWS S3).

  • Example: A payment library might provide methods to interact with Stripe’s API, making it easier to charge a customer or process refunds without manually building API calls.
stripe.Charge.create(
  amount=2000,
  currency="usd",
  source="tok_mastercard",
  description="Charge for user@example.com"
)

 

 

Databases

Databases are essential for storing, managing, and retrieving the data that the web application needs. Based on the type of data and application requirements, different databases are used.

 

Relational Databases (SQL)

These are structured databases where data is stored in tables with rows and columns. SQL databases are highly structured and enforce relationships between tables using foreign keys.

  • Examples: MySQL, PostgreSQL, SQLite.
  • Use Cases: When the data is structured and relationships between entities are important, such as for e-commerce platforms, user management systems, etc.
  • Example SQL query:
SELECT * FROM users WHERE email = 'user@example.com';

 

Non-Relational Databases (NoSQL)

These are databases designed for unstructured or semi-structured data. They are more flexible and allow for storing data in formats like JSON or key-value pairs.

  • Examples: MongoDB, Cassandra, Redis.
  • Use Cases: When you need to store large amounts of unstructured data or when schema flexibility is important, such as for real-time applications, content management systems, or logging systems.
  • Example NoSQL query (MongoDB):
db.users.find({ email: 'user@example.com' });

 

Interactions Between Framework and Database

  • Database Queries: During a request, the web framework may interact with the database to retrieve or update data.
  • Connection Management: Web frameworks manage database connections through connection pools, allowing efficient and concurrent access to the database.
  • Query Optimisation: The framework often provides built-in query optimisation, caching, and indexing options to improve performance.

2.17 Scripting Languages

Syllabus
Develop a web application using an appropriate scripting language with shell scripts to make files and directories, and searching for text in a text file

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Learn how to develop a basic web application using an appropriate scripting language

Success Criteria - Students can:

  • Identify and use a suitable scripting language to develop a functional web application with both front-end and back-end components.

  • Construct shell scripts that automate tasks such as creating files, directories, and searching for text in files

  • Implement shell scripts within the context of their web application, demonstrating how shell scripts can automate backend tasks like file management and data processing.

  Content

Shell scripts are powerful tools used to automate tasks on the command line, offering efficiency and control over system processes. In the context of web development, they allow developers to manage files and directories, run repetitive tasks, and manipulate text files directly from the terminal. By integrating shell scripts into web applications, server-side operations can be streamlined, making development and maintenance more efficient.

 

What is a Shell Script?

A shell script is a program written for a command-line interface (CLI) that allows you to automate tasks by executing a series of commands. These scripts are interpreted by the shell (such as Bash on Linux or macOS) and can perform tasks like file manipulation, system monitoring, or even web server management.

In a web development environment, shell scripts are often used for:

  • Automating server setup and configuration.
  • Managing files and directories for data storage.
  • Running maintenance tasks like log file cleanup.
  • Searching and manipulating text files, such as configuration files or logs.

Shell scripting plays an essential role in the backend operations of a web application, especially when it comes to automating repetitive tasks, which increases efficiency and reduces the potential for human error.

 

Basic Bash Script Commands

Here are some fundamental Bash commands that you can use within shell scripts. These commands will help you manipulate files, directories, and text, which are essential operations in web development.

 

Creating and Managing Directories

mkdir: Creates a new directory.

mkdir my_directory

This creates a directory named my_directory.

 

rmdir: Removes an empty directory.

rmdir my_directory

 

cd: Changes the current directory.

cd my_directory

 

Creating and Managing Files

touch: Creates an empty file.

touch myfile.txt

This command creates a new file named myfile.txt.

 

rm: Removes a file.

rm myfile.txt

 

cp: Copies a file or directory.

cp source.txt destination.txt

 

Searching for Text in Files

grep: Searches for specific patterns or text in files.

grep "search_term" file.txt

This command searches for "search_term" in the file.txt and returns the lines where the term appears.

 

cat: Outputs the content of a file.

cat file.txt

 

Automating Tasks

You can combine these commands into a script to automate tasks. For example, to create a directory, a file inside it, and then search for specific text:

#!/bin/bash

# Create a directory
mkdir project_directory

# Navigate into the directory
cd project_directory

# Create a file
touch notes.txt

# Add text to the file
echo "This is a sample project. TODO: Finish the setup." > notes.txt

# Search for the word "TODO" in the file
grep "TODO" notes.txt

 

The hash bang at the beginning of a script is a special sequence of characters (#!/) followed by the path to the interpreter that should be used to execute the script. 

#!/bin/bash

 

The purpose of it is to ensure that the correct interpreter is used, even if the user runs the script from a different shell or terminal that may not default to Bash. By specifying #!/bin/bash, the script will always run using the Bash interpreter, regardless of the environment in which it's executed.

If you were to leave it out, the script would still work if executed explicitly with Bash (like running bash script.sh), but it wouldn’t run correctly if executed without specifying Bash, since the system might try to run it with a different shell (e.g., sh or zsh) or treat it as a regular file.

 

 

Shell Scripts in Web Development

  1. Automating Server Management:

    Shell scripts play a critical role in automating server-side tasks like file management, backups, and configurations. Automating these tasks increases the efficiency and reliability of web applications.

  2. Handling Log Files and Data:

    Web servers generate extensive logs, which require regular monitoring and maintenance. Shell scripts can be used to search, filter, and process logs to ensure smooth operation or identify potential issues.

  3. Efficient File and Directory Management:

    Managing the file system is central to web development. Tasks like creating directories for user uploads, setting permissions, or organising static assets can be automated using shell scripts to save time and ensure consistency.

  4. Streamlining Development Processes:

    Repetitive tasks such as server restarts, running tests, or performing database backups are ideal candidates for automation with shell scripts. This results in faster development cycles and fewer errors.

  5. Customising Web Application Behaviour:

    Background tasks such as scheduled data backups or log rotations can be automated through shell scripts, ensuring that the application performs key maintenance operations without requiring manual intervention.

Syllabus

Apply a web-based database and construct script that executes SQL, including:

  • selecting fields

  • constraints using WHERE keyword

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • apply SQL commands in a web-based database environment to effectively retrieve and manipulate data, with a focus on selecting fields, using ‘GROUP BY’, executing common SQL queries, applying constraints, and performing table joins.

Success Criteria - Students can:

  • implement SQL commands to select specific fields from a database.
  • apply the GROUP BY clause to group data effectively.
  • construct common SQL queries, including filtering data with the WHERE clause.
  • apply join tables using various types of joins.

  Content

 

What is SQL?

SQL (Structured Query Language) is a domain-specific language designed for managing and manipulating relational databases. It is the standard language used to interact with databases that store data in tables (rows and columns) and is integral to modern web-based applications. SQL allows users to perform various operations on data, including querying (retrieving data), updating, deleting, and inserting new records, as well as managing database structure and access control.

 

Key Characteristics of SQL

SQL’s key features are essential for efficiently managing and interacting with relational databases. These include the ability to retrieve data with SELECT, filter results using WHERE, and sort or group data using ORDER BY and GROUP BY. SQL also supports aggregating data with functions like COUNT() and SUM(), and allows combining data from multiple tables through joins. These features are crucial for performing detailed queries and analyses on structured datasets.

 

Declarative Language

SQL is considered a declarative language, meaning that instead of explicitly coding how the data should be retrieved or manipulated, you declare what you want, and the database system figures out the optimal way to do it. For example, you specify which data you want (SELECT statement), but you don’t control the internal processes that the database engine uses to retrieve it.

Relational Databases

SQL is used primarily with relational databases, which organise data into tables. Each table contains rows and columns, where rows represent records (individual data entries) and columns represent fields (specific data attributes like name, age, or salary). Relationships between different tables can be established via key fields, enabling complex queries that span multiple tables.

Standardised Language

SQL is governed by various standards, with the most well-known being ANSI SQL. Although different database management systems (DBMS) like MySQL, PostgreSQL, Oracle, and Microsoft SQL Server may have slight variations, they all generally adhere to the SQL standard. This standardisation makes SQL a widely transferable and universal language in the database domain.

SQL Operations

SQL allows for a wide range of operations, from querying data to modifying the structure of the database. Some key operations include:

  • Data Retrieval: Using SELECT statements to query data from one or more tables.
  • Data Manipulation: Inserting, updating, or deleting records with INSERT, UPDATE, and DELETE commands.
  • Data Definition: Creating and modifying tables, indexes, and relationships using commands like CREATE TABLE and ALTER TABLE.
  • Data Control: Managing access to the database with GRANT and REVOKE to control user permissions.

 

Constructing SQL Commands

Constructing SQL statements involves creating structured queries that perform specific actions on a database. A typical query begins with the SELECT statement to define which fields to retrieve. Data is pulled from the relevant table(s) specified in the FROM clause, and you can refine the results using the WHERE clause to filter the dataset based on specific conditions. The GROUP BY clause can be used to aggregate data, while ORDER BY helps you organize the results in a specific sequence. By combining these elements, you can construct complex queries to extract and analyze the data you need from a relational database.

 

SELECT

In SQL, the SELECT statement is used to retrieve specific data from a table. The fields you want to display must be explicitly defined.

 

Basic Syntax:

SELECT field1, field2, field3
FROM table_name;

 

Example:

SELECT first_name, last_name 
FROM employees;

 

FROM

For the purposes of this course, we use a simplified approach to joining tables. Instead of explicitly using JOIN clauses, you can list multiple tables in the FROM clause, and SQL will automatically link the tables based on common fields, provided those fields are correctly referenced in the WHERE clause.

 

HSC SQL Example:

SELECT employees.first_name, departments.department_name
FROM employees, departments
WHERE employees.department_id = departments.department_id;

 

In this version:

  • You simply list the tables (e.g., employees, departments) in the FROM clause.
  • Then, specify the relationship between the tables using a condition in the WHERE clause (e.g., employees.department_id = departments.department_id).

This method simplifies the syntax for educational purposes, but the logic behind how the tables are joined remains the same.

 

SQL JOIN Keyword

In real-world SQL, joins are typically done using explicit JOIN clauses, such as INNER JOIN, LEFT JOIN, and RIGHT JOIN, which provide more control over how the data is combined. These joins require a more formal structure but are commonly used in professional database management.

Standard SQL Example (INNER JOIN):

SELECT employees.first_name, departments.department_name
FROM employees
INNER JOIN departments
ON employees.department_id = departments.department_id;

 

WHERE

The WHERE clause is used to specify conditions that must be met for records to be included in the results. This is critical for narrowing down large datasets and focusing on the information you need.

 

Basic Filtering with WHERE:

SELECT field1, field2
FROM table_name
WHERE field1 = 'value';

 

Example: Retrieve all employees who work in the "Sales" department:

SELECT first_name, last_name
FROM employees
WHERE department = 'Sales';

 

Relational Operators Available in SQL:

  • =: Equals
  • != or <>: Not equals
  • >: Greater than
  • >=: Greater than or equal to
  • <: Less than
  • <=: Less than or equal to

Logical Operators:

  • AND: Combines conditions, both must be true.
  • OR: At least one condition must be true.
  • NOT: Negates the condition.

Example with Logical Operators:

  • Find employees in the "Sales" department who earn more than 50,000:
SELECT first_name, last_name
FROM employees
WHERE department = 'Sales' AND salary > 50000;

 

ORDER BY

The ORDER BY clause in SQL is used to sort the results of a query based on one or more columns. By default, SQL sorts the data in ascending order (A–Z or 0–9), but you can also specify descending order (Z–A or 9–0) if needed. This is particularly useful when you want to organise your query results in a specific way, such as alphabetically, by date, or numerically.

 

Syntax for ORDER BY:

SELECT field1, field2 
FROM table_name 
ORDER BY field1 [ASC|DESC]; 

 

Sort Results in Ascending Order 

SELECT first_name, last_name
FROM employees
ORDER BY last_name ASC;

This query retrieves the first and last names of employees and orders them alphabetically by last_name.

 

Sort Results in Descending Order:

SELECT first_name, last_name, salary 
FROM employees 
ORDER BY salary DESC;

This query retrieves employee names and their salaries, ordering the results from the highest salary to the lowest using DESC.

 

GROUP BY

The GROUP BY clause groups rows that have the same values in specified columns. This is typically used in conjunction with aggregate functions like SUM(), COUNT(), AVG(), MAX(), and MIN().

 

Basic Syntax:

SELECT field1, COUNT(*)
FROM table_name
GROUP BY field1;

 

Example:

SELECT department, COUNT(*)
FROM employees
GROUP BY department;

 

Using the GROUP BY Clause with Aggregate Functions

When you need to summarise data, such as calculating totals or averages, you will use aggregate functions alongside GROUP BY.

Available Aggregate Functions:

  • SUM(field): Returns the total sum of values in a field.
  • AVG(field): Returns the average of values in a field.
  • COUNT(field): Counts the number of rows or occurrences.
  • MAX(field): Returns the highest value in a field.
  • MIN(field): Returns the lowest value in a field.

Example:

  • Calculate the total sales per department:
SELECT department, SUM(sales)
FROM employees
GROUP BY department;

2.19 Object-Relational Mapping

Syllabus
Compare Object-Relational Mapping (ORM) to SQL

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the core differences between SQL and ORM, and learn when to choose between direct SQL querying and using an ORM framework in application development.

Success Criteria - Students can:

  • Describe the differences between SQL and ORM in terms of how they interact with databases.
  • Identify scenarios where using SQL or ORM would be more appropriate based on project needs.
  • Analyse the performance trade-offs and benefits of using ORM versus writing raw SQL queries.

  Content

 

What is ORM?

ORM is a programming technique that allows you to interact with the database by using the object-oriented programming (OOP) model. With ORM, you manipulate database tables as though they were programming language classes, and rows are represented as instances (objects) of those classes.

Popular ORM frameworks include Hibernate (Java), SQLAlchemy (Python), Django ORM (Python), and Entity Framework (C#).

  • Abstraction of SQL: Instead of writing SQL queries, ORM frameworks generate SQL code on behalf of the developer based on the objects and methods in the application code. This creates an abstraction layer between the database and the application code, allowing developers to interact with databases without manually writing SQL.
  • Example of ORM Usage:
# Using Django ORM in Python to query users
users = User.objects.filter(age__gt=30).order_by('last_name')

This ORM query performs the same operation as the SQL query above but uses Python-like syntax to query the database. The ORM framework translates this into an SQL statement under the hood.

 

Advantages of ORM:

  • Increased Productivity: By automating CRUD CRUD: An acronym for Create, Read, Update, Delete, which represents the four basic operations performed on data in a database or storage system. operations, developers can focus on the business logic rather than manually writing SQL queries.
  • Database-Agnostic: ORM frameworks allow developers to switch between different databases (e.g., from MySQL to PostgreSQL) with minimal code changes, as the SQL is abstracted away.
  • Less Boilerplate: Common database operations are handled by the ORM framework, leading to less repetitive code and improved maintainability.
  • Object-Oriented Approach: ORMs allow you to work with native language objects (classes and objects), which is more intuitive for developers familiar with object-oriented programming. This can also lead to better integration with the rest of the application.

Disadvantages of ORM:

  • Performance Overhead: ORMs typically introduce some performance overhead because the generated SQL queries may not be as optimised as hand-written SQL. This is especially noticeable in large or complex queries.
  • Less Fine-Grained Control: While ORMs simplify many operations, they can make it more difficult to fine-tune queries for performance or handle very specific use cases that require complex SQL logic.
  • Learning Curve: Using an ORM effectively requires understanding both the ORM framework and the underlying database concepts. Inexperienced developers might misuse the ORM and create inefficient database queries. 

 

SQL vs ORM

 

Feature SQL ORM
Level of Abstraction Low: Direct database access through SQL queries High: Access through programming language objects
Performance High for complex queries, fine-tuned optimisations Lower performance due to abstraction overhead
Ease of Use Requires knowledge of SQL and database schema Easier for developers familiar with OOP, no SQL needed
Portability Low: SQL may need adaptation for different DBs High: ORMs are designed to work with multiple databases
Maintenance Can be harder to maintain as the app grows Easier due to less boilerplate and abstraction
Granular Control High: Full control over the query execution Low: ORM abstracts query execution details
Flexibility High: Complex queries are easier to implement Limited: Complex queries can be hard to implement in ORM
Learning Curve Steep: Requires SQL and database knowledge Moderate: Requires understanding of both ORM and DB basics

 

When to Use SQL vs ORM

Use SQL when:

  • Performance is critical, and you need full control over database queries (e.g., in performance-sensitive applications like banking systems or data-heavy analytics).
  • You need to write complex queries with multiple joins, nested subqueries, or optimizations that are hard to express in ORM.
  • The project requires database-specific features such as stored procedures, triggers, or specific SQL dialects that the ORM cannot easily handle.

Use ORM when:

  • The project is more CRUD-heavy, and you need to automate routine database interactions (e.g., simple web apps).
  • Portability is important, and the ability to switch databases without modifying code is a key requirement.
  • You want to speed up development by avoiding the need to write SQL and managing database objects using the language’s OOP principles.
  • You need to rapidly prototype an application without worrying about database details at first.

2.20 Collaborative Work Practises

Syllabus
Describe how collaborative work practices between front-end and back-end developers improve the development of a web solution

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Understand the importance of collaboration between front-end and back-end developers in creating efficient, high-quality web solutions.

Success Criteria - Students can:

  • Explain how communication and shared practices between front-end and back-end developers enhance integration.
  • Describe specific ways that collaborative practices improve the overall development process, such as reducing bugs, improving performance, and speeding up iterations.

  Content

In web development, front-end and back-end developers play distinct but interconnected roles. Front-end developers focus on building the part of the website that users interact with, while back-end developers ensure that the server, database, and business logic function properly. Collaborative work between these two teams is essential for building efficient, high-performing web solutions. By fostering clear communication, shared responsibilities, and integrated workflows, teams can reduce errors, improve development speed, and deliver a seamless user experience.

 

Recall
  • Front-End Development: Refers to the creation of the user interface (UI) and user experience (UX) that the end-user interacts with directly. It involves languages and technologies like HTML, CSS, JavaScript, and frameworks such as React or Angular.
  • Back-End Development: Focuses on server-side logic, databases, APIs, and everything that supports the front-end. Common languages for back-end development include Python, Java, Ruby, and frameworks like Django or Node.js. Back-end development ensures data storage, processing, and application functionality.

 

Clear Communication

Importance: Clear communication ensures that both teams understand the requirements and constraints of each other’s work.

Examples:

  • Front-end developers need to know how data is structured, what APIs are available, and how to handle responses (e.g., data formats like JSON or XML).
  • Back-end developers need to understand front-end user experience goals to ensure that server responses are fast, well-structured, and align with the user interface needs.

Best Practices:

  • Use collaborative tools like Slack, Microsoft Teams, or Jira for regular updates and issue tracking.
  • Create shared documentation for API structures, expected data formats, and error handling to avoid misunderstandings.

Efficient Integration

Importance: Early and continuous collaboration reduces the risk of integration issues, where front-end and back-end components don’t work together as expected.

Examples:

  • Aligning on how data is passed between the front-end and back-end—whether through APIs, web services, or server-side rendering—ensures smooth integration.
  • For instance, a front-end developer working on a product page needs to know exactly how product data will be delivered (e.g., pagination or filtered results from an API).

Best Practices:

  • Front-end and back-end teams should collaborate early in defining API endpoints, agreeing on data formats (e.g., JSON or XML), and setting up testing environments.
  • Use API testing tools like Postman or Swagger to ensure smooth interactions between the front-end and back-end components.

Rapid Prototyping

Importance: Working together during prototyping allows both teams to test functionality quickly and make adjustments before full-scale development.

Examples:

  • Back-end developers can create early API mocks, which front-end developers can use to build and test UI components without waiting for the full back-end functionality to be completed.
  • This approach helps detect issues, such as data inconsistencies or performance bottlenecks, early in the development process.

Best Practices:

  • Create a feedback loop where both teams test small features incrementally rather than waiting for full development to be completed.
  • Front-end developers can focus on UI functionality and interactivity while back-end developers fine-tune the server-side logic and database queries.

Shared Responsibility

Importance: Both teams must consider how their work impacts overall performance. A slow back-end can result in poor front-end performance, and vice versa.

Examples:

  • Front-end developers should minimise unnecessary API calls or overly complex UI components that strain resources.
  • Back-end developers must ensure that database queries are optimised and that API responses are lightweight and efficient, reducing server load times.

Best Practices:

  • Conduct joint performance reviews to identify areas where performance can be optimised (e.g., reducing API response times, minimising page load times).
  • Use performance monitoring tools like Google Lighthouse for front-end and server-side monitoring tools like New Relic for back-end performance.

Problem Solving

Importance: Collaboration allows teams to troubleshoot issues that might involve both the front-end and back-end, leading to faster resolution and a more comprehensive solution.

Examples:

  • A performance issue such as slow page loads could be due to inefficient API calls (back-end) or excessive rendering (front-end). By working together, both teams can pinpoint the issue more effectively.
  • A front-end bug may seem unrelated to the back-end at first but could be traced to incorrect or delayed data from an API.

Best Practices:

  • Conduct joint debugging sessions where both front-end and back-end developers analyse issues together.
  • Use error tracking tools like Sentry or LogRocket that capture both front-end and back-end errors, enabling both teams to work off the same set of data.

2.21 Progressive Web Apps

Syllabus

Design, develop and implement a progressive web app (PWA), including:

  • the application of design and user interface (UI) and user experience (UX) principles of font, colour, audio, video and navigation
  • a UI that considers accessibility and inclusivity

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • understand how to design and develop a Progressive Web App (PWA) with a focus on applying user interface (UI) and user experience (UX) design principles, ensuring accessibility and inclusivity.

Success Criteria - Students can:

  • design and implement a PWA that applies key UX/UI principles, including effective use of fonts, colors, multimedia, and clear navigation.
  • create a user interface that is accessible to all users, with features such as screen reader compatibility and inclusive design elements.

  Content

A Progressive Web App (PWA) is a hybrid between a web application and a native mobile application. It uses modern web technologies like HTML, CSS, JavaScript and APIs to provide an experience similar to that of a traditional native app, but it is accessible through a web browser without needing to be downloaded from an app store. The “progressive” part refers to its ability to enhance functionality depending on the device and browser capabilities.

 

PWA Key Features

  • Progressive: It works for every user, regardless of browser choice, as it’s built with progressive enhancement at its core.
  • Responsive: It fits any form factor — whether on desktop, mobile, or tablet — using responsive design techniques.
  • Offline Capabilities: Through Service Workers, PWAs can cache essential resources and operate even when the device is offline or has poor network conditions.
  • App-like Feel: PWAs mimic the look and feel of a native app using the app shell model. This means fast, smooth transitions between screens and a consistent experience.
  • Installable: Users can add the PWA to their home screen without visiting an app store. Once installed, it behaves like a standalone app, launching in its own window without the browser UI.
  • Secure: PWAs are always served over HTTPS, ensuring that the content delivered is safe and tamper-proof.

 

Developing a PWA differs from a traditional full stack by heavily focusing on client-side capabilities like offline access and a UI accessible across various devices, using technologies like service workers and responsive design. In contrast, traditional full-stack apps rely more on server-side logic and consistent internet connectivity.

From a practical and development perspective, a PWA generally includes the following key features: 

Caching

Caching allows web apps to store frequently accessed assets (such as HTML, CSS, JavaScript, and images) in the browser. This means these assets can be loaded from the local cache on subsequent visits without fetching from the web server, giving it offline capabilities. 

​

Caching is a way of storing copies of important data or files in a special place so they can be accessed quickly without having to re-download. 

  1. First Visit: When you visit a website for the first time, your browser downloads all the necessary files from the server to display the page (like index.html, styles.css and JavaScript files).

  2. Saving Files: The browser stores these files locally in its cache (a special storage area) while downloading.

  3. Reusing Files: The next time you visit the same website, the browser checks its cache instead of downloading everything again. If the files haven’t changed, it loads them directly from the cache, loading the website much faster.

Service Workers

A service worker that helps manage your web app and configure offline capabilities. 

A service worker is like a "helper" that sits between your web app and the Internet. When your browser requests a webpage or image from the server, the service worker can decide whether to fetch it from the Internet or use a saved version (called a cache). After configuring a service worker, it can effectively automate decisions on whether to cache or fetch files from the server.

  • Runs Separately: Service workers operate independently from the web app, which allows them to continue functioning even if the page is closed. 
  • Event-Driven: Service workers are built around an event-based model. Hence, they respond to specific user and system events, such as API fetching, installation, and activation. 

Web Manifest

A web manifest.json is a JSON file that provides metadata or critical information about your web app and the UI design when the app is launched. 

Traditional web apps typically rely on fetching to load a page's appearance. A web manifest automates this process by defining the structure of the PWA on the client's device or browser. 

  • App Appearance: Defines how the app appears when launched, including its icons, screens, and theme colours.
  • Behaviour: Specifies the display mode (e.g., fullscreen, standalone) and orientation, determining how the app interacts with the device's UI.
  • Navigation: Sets the start URL, determining which page loads when the app is launched from the home screen. Usually, this is handled by server-side routing (via Flask) or client frameworks (via React or Angular)  

Responsive Design

UI design that is responsive to different devices and browsers. PWAs aim to deliver a native-like experience, and users might access them from various devices, such as smartphones, tablets, and desktops. Designing our UI, we should consider:

  • Flexible Layouts: PWAs use fluid grids that scale content proportionally based on the screen size. This ensures that elements like buttons, text, and images resize appropriately, whether on a small mobile screen or a large desktop monitor
  • Media Queries: CSS media queries help define different styles for screen sizes or device characteristics. For example, you might adjust font sizes or change navigation menus for mobile versus desktop views
  • Viewport: Setting the HTML viewport meta tag ensures that the app is scaled and displays properly on different devices. This prevents users from needing to zoom in or scroll horizontally to see content

UI/UX Principles

 When designing a PWA, it’s crucial to create an interface and experience that is not only visually appealing but also intuitive and user-friendly.

 

UI vs UX

UI (User Interface) refers to the visual elements and layout that users interact with, such as buttons, icons, and menus, while UX (User Experience) focuses on the overall feel and usability of the app, ensuring that interactions are intuitive, efficient, and enjoyable for the user.

 

Fonts

  • Readability: Select fonts that ensure readability across various devices and screen sizes. Avoid overly decorative fonts that might reduce legibility, especially on smaller screens.
  • Web-safe Fonts: Use fonts that are either available on most devices (like Arial, Verdana, or Times New Roman) or utilise web fonts from libraries like Google Fonts. Ensure they are lightweight to maintain performance.
  • Consistency: Maintain font consistency across the app by limiting the number of typefaces and styles. Use font hierarchies (e.g., larger fonts for headers, smaller for body text) to guide users.

Colour

  • Contrast: Ensure sufficient contrast between text and background colours to make content readable, especially for users with visual impairments. You can use tools like WCAG colour contrast checkers to verify accessibility.
  • Branding and Visual Identity: Use colour schemes that align with your app’s branding and purpose. Colours evoke emotions; for example, blue conveys trust, while green suggests growth or success.
  • Colour Psychology: Consider how colour impacts user perception. Choose your palette based on the emotions or actions you want to encourage.
  • Accessibility: Ensure colour-blind users can navigate and understand the app by avoiding colour-dependent actions (e.g., only using colour to convey meaning). Incorporate additional visual cues such as icons or text.

Audio and Video

  • Appropriate Use: Use multimedia elements like audio or video to enhance the user experience without overwhelming the interface. For example, videos can be used for tutorials, but they should not auto-play with sound, which can disrupt user experience.
  • Performance Considerations: Multimedia should be optimised to reduce loading times. Use techniques such as lazy loading and responsive media queries to ensure smooth performance on all devices.
  • Accessibility: Provide captions for videos and transcripts for audio to make the content accessible to users who are deaf or hard of hearing.

Navigation

  • Intuitive Structure: Simplify navigation so users can easily find what they need. Follow the “three-click rule” — users should reach any part of the app within three taps or clicks.
  • Consistent UI Patterns: Use familiar patterns such as hamburger menus, tabs, and bottom navigation bars to make navigation intuitive.
  • Sticky Elements: Consider using sticky navigation bars that remain visible as users scroll to give them easy access to primary navigation options.
  • Interactive Feedback: Provide clear feedback when a user interacts with navigation elements, like button animations or visual cues (hover effects, loading indicators).

 

 

Accessibility and Inclusivity

Accessibility ensures that your PWA can be used by as many people as possible, including those with disabilities. Inclusivity means that the app design takes into account different cultural backgrounds, devices, and levels of ability.

 

Accessibility

  • Screen Reader Support: Ensure your app’s content is compatible with screen readers. Use semantic HTML (e.g., <header>, <nav>, <article>, etc.) to structure your app properly. Provide alt text for images and make sure every actionable element is keyboard-accessible.
  • Keyboard Navigation: Users who rely on a keyboard or other input devices should be able to navigate through the entire PWA. Elements such as buttons, links, and form fields should be focusable using the keyboard (using the tab key).
  • ARIA (Accessible Rich Internet Applications): Use ARIA attributes to enhance accessibility, especially for dynamic content. For instance, aria-live can alert users of important updates, or aria-expanded can indicate if a dropdown is open.
  • Contrast Ratios: The Web Content Accessibility Guidelines (WCAG) recommend a contrast ratio of 4.5:1 for normal text and 3:1 for large text to ensure readability for visually impaired users.
  • Forms and Labels: Always associate form inputs with labels so users relying on screen readers can understand what information is being requested.

Inclusivity

  • Language Support: Provide language options for international users. Ensure the app can switch seamlessly between different languages and that text expansion (in languages like German or Arabic) is accounted for.
  • Cultural Sensitivity: Avoid using icons, symbols, or colours that could be misinterpreted across different cultures. For example, the colour red may mean “danger” in some cultures, but in others, it signifies celebration or good luck.
  • Diverse User Needs: Design for different physical and cognitive abilities. This might involve simplifying complex tasks, providing visual and text cues, or giving users the option to adjust font sizes and contrast settings.
  • Flexible Interfaces: Allow users to customise the app to suit their needs, such as changing font sizes, colour schemes (dark mode), and enabling or disabling animations.
