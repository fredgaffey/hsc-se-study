Syllabus
Analyse the logic and structure of written algorithms including
- determining inputs and outputs
- determining the purpose of the algorithm
- desk checking and peer checking
- determining connections of written algorithms to other subroutines or functions

  Learning Intention and Success Criteria

Learning Intention - Students will:

  • Analyse the logic and structure of written algorithms by identifying inputs, outputs, and purposes, as well as to engage in desk checking and peer checking processes to ensure connections with other subroutines or functions are understood.

Success Criteria - Students can:

  • Accurately identify inputs and outputs in a given algorithm.
  • Clearly understand and articulate the purpose of the algorithm.
  • Effectively perform desk checking to verify the correctness of the algorithm.
  • Engage in peer checking to receive and provide feedback on algorithm logic and structure.
  • Demonstrate the ability to determine how the algorithm connects with other subroutines or functions within a program.

  Content

Analysing algorithms to understand their logic and structure is a fundamental skill in software engineering. It involves understanding how a set of instructions (the algorithm) solves a particular problem. A well-analysed algorithm ensures efficiency, clarity, and effectiveness in solving problems.

 

Inputs and Outputs

  • Inputs: These are the data or variables that are fed into an algorithm. Understanding inputs is crucial as they directly affect how the algorithm operates.
  • Outputs: These are the results produced by the algorithm. Knowing the desired output helps in shaping the steps of the algorithm.

Algorithm Purpose

  • This involves understanding what the algorithm is designed to achieve. Is it sorting data, solving a mathematical problem, or processing user input?
  • Understanding the purpose helps in evaluating the effectiveness of the algorithm and its suitability for a task.

Desk Checking & Peer Checking

  • Desk Checking: This is a manual process of tracing the execution of an algorithm using a sample set of inputs. It helps in understanding the flow and identifying any logical errors.
  • Peer Checking: Involves having another person (preferably a peer) review the algorithm. This collaborative approach can uncover issues that the original author might have missed.

Connections to Subroutines

  • Algorithms often interact with other parts of the software, like subroutines or functions. Understanding these interactions is crucial for ensuring the algorithm integrates smoothly into the larger system.
  • It’s important to analyse how data is passed between these components and how they affect the overall functionality.

Examples

Number Guessing Game

Given below is psuedocode for a Number Guessing Game.

BEGIN NumberGuessingGame

minNumber = 1

maxNumber = 100

attempts = 0

secretNumber = GenerateRandomNumber(minNumber, maxNumber)

Display "I have chosen a number between " + minNumber + " and " + maxNumber

REPEAT

Display "Enter your guess:"

Get userGuess

attempts = attempts + 1

IF userGuess < secretNumber THEN

Display "Too low. Try again."

ELSEIF userGuess > secretNumber THEN

Display "Too high. Try again."

ELSE

Display "Congratulations! You've guessed the number in " + attempts."

ENDIF

UNTIL userGuess = secretNumber

END NumberGuessingGame

 

1. Desk Checking and Peer Checking

  • Desk Checking: This involves manually going through the pseudocode line by line to simulate what would happen during its execution. It helps identify logical errors and ensures that the program's flow makes sense. For example, manually checking that the loop continues until the correct guess is made.
  • Peer Checking: Having another person review the pseudocode can uncover issues the original author might overlook. Peers can provide feedback on the clarity of the logic and suggest improvements or identify bugs, such as ensuring the random number generation is within the specified range.

 

2. Inputs and Outputs

  • Inputs: The inputs in this program include the user's guess (userGuess) of the secret number. These are obtained through the Input statement within the loop.
  • Outputs: Outputs consist of prompts and feedback to the user, such as asking for a guess, indicating whether the guess is too low or too high, or congratulating the user upon a correct guess. The output also includes the number of attempts made to guess the correct number.

 

3. Determining Connections of Written Algorithms to Other Subroutines or Functions

  • The main program connects to the RandomNumberGenerator module through the GenerateRandomNumber(min, max) function. This function is essential for generating the secret number that the user tries to guess. It demonstrates how subroutines or modules can be utilised within a larger program to perform specific tasks, in this case, generating a random number within a defined range.

 

4. Purpose of Algorithm

  • The primary purpose of this algorithm is to create an interactive number guessing game where the user attempts to guess a randomly generated number within a certain range.

Mystery Program

An algorithm is included below, however the names of the variables have been obfuscated. It is our job to analyse the algorithm to understand its logic and structure.

BEGIN MysteryProgram

Display "Enter the first number: "

Get X

Display "Enter the second number: "

Get Y

Display X, Y

Z = X

X = Y

Y = Z

Display X, Y

END MysteryProgram

 

1. Desk Checking and Peer Checking

  • Desk Checking: This involves going through the algorithm step-by-step to understand the changes happening to the variables.
  • Peer Checking: By discussing the steps and the effect of the operation with peers, students can share insights or confusions, which can lead to a deeper understanding of the process. This collaborative analysis can help uncover the algorithm's purpose through observation and reasoning.

2. Inputs and Outputs

  • Inputs: The algorithm starts by asking the user for two numbers, X and Y, establishing the initial state of the variables.
  • Outputs: It then presents the values of X and Y both before and after the operation, allowing the user to observe the effect of the algorithm on these variables.

 

3. Determining Connections of Written Algorithms to Other Subroutines or Functions

  • The algorithm does not make use of other subroutines or functions

 

4. Purpose of Algorithm

  • The purpose of this algorithm is revealed through its execution: it swaps the values of two variables. This is a foundational technique in programming, enabling the handling and manipulation of data in a controlled manner. Understanding how to swap values is crucial in various applications, such as sorting algorithms, where the position of elements needs to be rearranged. The method of using a temporary storage (Z) to hold a value while the swap is performed is a classic solution to avoid data loss during the operation.
  • Notice how hard it is to read this algorithm? This is why it is important to use meaningful variable names when designing your algorithms so that another programmer can easily understand your code.
