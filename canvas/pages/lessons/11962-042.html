Inheritance & Polymorphism

Recall the definition of inheritance from module 2.2.2 OOP Features: Inheritance.

"Inheritance is a key concept in object-oriented programming (OOP) that allows classes to inherit attributes and methods from other classes. This enables the creation of a hierarchical structure of classes, where child classes can reuse and extend the functionality of their parent class"

 

But what if we wanted a method (that is inherited from the parent class) to do something different in the child class?

For example:

  • All animals can make a sound. However, not all animals make the same sound.

We can achieve this through polymorphism!

 

In object-oriented programming (OOP), inheritance and polymorphism are closely related concepts, often used together to promote code reuse, modularity, and extensibility. The relationship between inheritance and polymorphism lies in the fact that inheritance enables polymorphism.

 

Polymorphism

Polymorphism is a key concept in object-oriented programming (OOP) that allows for classes of objects to behave in different ways (depending on the context) without changing the interface in which they are used (i.e. the way in which we interact with the object).

To put it simply, polymorphism allows us to perform a single action in different ways.

Note: The interface of a class is simply defined as the method signatures in the class (the method names and associated parameters)

 

Method Overriding

In Python, polymorphism is achieved through a technique called Method Overriding. Method overriding is where an inherited method in a child class is declared again with the same name and parameters, but operates in a different way than the same method in the parent class.

Consider a parent class called Animal, where its interface consists of the methods:

  • getName()
  • setName()
  • make_sound()
  • eat()

All animals can make a sound through the make_sound() method and can eat through the eat() method.

 

However, we would want child classes like Dog and Cat to make different sounds when using the method make_sound() (but the way they eat remains the same).

Consider the child classes Dog and Cat.

 

The Dog child class uses method overriding to change the output of the make_sound() method to "Woof! Woof!" to suit the context of the class.

Similarly, the Cat child class uses method overriding to change the output of the make_sound() method to "Meow! Meow!" to suit the context of the class.

 

In both the Dog and Cat child classes, the make_sound() method is defined in the same way as the Animal parent class using def make_sound(self):, but the code inside of the method behaves differently.

 

We now demonstrate the use of polymorphism when these classes are instantiated as interactable objects.

Output:

Alex says generic animal sound
Max says Woof! Woof!
Tom says Meow! Meow!
Alex is eating
Max is eating
Tom is eating

 

Notice how we can interact with the objects belonging to the Animal class (and its subclasses) by using the same make_sound() method, but the subclasses behave differently from the Animal parent class.

Additionally, notice how the behaviour in the eat() method remains the same since eat() was not overridden in the Dog or Cat child classes.
